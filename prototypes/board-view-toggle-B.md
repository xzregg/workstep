# 任务看板视图切换 · 原型 B

> 右上角图标切换器 + 按步骤分组表格
> 配套可交互 HTML: `prototypes/board-view-toggle-B.html`

## 方案概述

顶栏最右侧新增「列图标 / 行图标」双按钮切换器;表格模式按步骤分组——组头为彩色圆点 + 步骤名 + 数量 + 折叠按钮,组内为该步骤的任务行,完整延续泳道的颜色语言,视图间过渡自然。

## 布局示意

### 切换器(顶栏最右)

```
┌─────────────────────────────────────────────────────────────┐
│ 任务看板  电商后台重构     [🔍 搜索任务…]        ( ▥ | ☰ )   │
└─────────────────────────────────────────────────────────────┘
```

- 选中态:蓝色填充圆角块;按钮本体不带文字,悬停时在按钮下方弹出深色 tooltip 显示「泳道 / 表格」

### 泳道模式(现状,保留)

```
┌──────────────┐ ┌──────────────┐ ┌──────────────┐
│ ● 需求 (2) + │ │ ● UI设计 (2)+ │ │ ● 前端 (3) + │  ← 横向滚动
│ ┌──────────┐ │ │ ┌──────────┐ │ │ ┌──────────┐ │
│ │ 任务卡片  │ │ │ │ 任务卡片  │ │ │ │ 任务卡片  │ │
│ └──────────┘ │ │ └──────────┘ │ │ └──────────┘ │
└──────────────┘ └──────────────┘ └──────────────┘
```

### 表格模式(新增,按步骤分组)

```
┌─ ● 需求 ─────────────── 2 个任务   [折叠 ▴] ─┐
│ 任务                 状态     创建人  耗时    │
│ 退款流程状态机设计    已完成   王珊   2h 05m  │
│ 优惠券叠加规则文档    进行中   王珊   36m     │
└──────────────────────────────────────────────┘
┌─ ● 前端 ─────────────── 3 个任务   [折叠 ▴] ─┐
│ 订单列表筛选条件持久化  进行中  林一   1h 24m  │
│ 购物车响应式重构        失败    林一   2h 41m  │
│ 订单搜索联想            未开始  林一   —       │
└──────────────────────────────────────────────┘
（…每个步骤一个分组卡片,纵向滚动,与泳道顺序一致）
```

- 组头左侧色条与圆点沿用步骤颜色(`STAGE_COLORS`)
- 组内默认按更新时间倒序;组头可整组折叠,一屏纵览全流程
- **列对齐**:所有分组表格统一 `table-layout: fixed` + 同一套 `<colgroup>` 列宽(任务 38% / 状态 15% / 创建人 14% / 耗时 15% / 更新时间 18%),跨分组的列严格对齐,超长文本省略号截断

## 交互规则

1. 切换即时生效,分组顺序与泳道列顺序一致
2. 选择持久化到 `localStorage`;折叠状态仅当次会话保留
3. 移动端默认列表(现状),不展示切换器
4. 归档视图同样支持两种显示

## 实现要点

- 落点在 `apps/web/src/pages/TaskList.tsx`:
  - 顶栏追加快照式双按钮切换器(32×28 按钮,复用 `Icon`)
  - 新增 `<TaskGroupedTableView tasksByLane lanes ... />`,复用现有 `tasksByLane` 分组结果,零额外数据加工
  - 行复用 `STATUS_LABEL_KEYS` / `STATUS_COLORS` 元信息
- 预计改动量:中(约 300~400 行,主要是分组表格与折叠逻辑)

## 优缺点

- ✓ 视图间过渡自然:同一套步骤/颜色系统,从泳道到分组表「只是把列拍平」
- ✓ 组头可折叠,一屏纵览全流程进度与数量
- ✓ 直接复用 `tasksByLane`,数据加工最少
- ✗ 分组布局实现较重(组头/折叠/跨组排序需单独设计)
- ✗ 步骤多时纵向占用高,需要更多滚动
