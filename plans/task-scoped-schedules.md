# 任务级定时指令实施计划

## 目标与已确定方案

复用现有项目定时任务管理页面、调度器、API 和 CLI，增加绑定已有任务的定时指令。用户可在任务对话中要求协调助手通过 CLI 创建规则，也可在管理页面创建、修改、暂停和删除。

项目级固定模板创建、动态生成任务保持原行为。任务级规则到点执行自由文本指令，复用任务协调助手的上下文、提示词、引擎调用、结果解析和提案能力。每次执行使用全新的引擎 session，不读取或更新任务的主协调 session；用户对话继续沿用主 session。所有执行消息归入同一个任务的消息历史。

完成通知由规则统一配置并复用现有渠道发送服务，助手仍可按明确指令通过 WorkStep CLI 发送额外内容；不增加专用汇报生成器。自由文本不限制用途，实际操作仍受现有工具权限、提案确认和任务状态校验约束。

## 数据与公共接口

- 在现有 Schedule 增加 `target_type`（`project` / `task`，旧记录默认 `project`）、可空 `target_task_id`、任务指令 `instruction`、`stop_condition`（`manual` / `task_terminal`）。项目类型继续使用 workflow 和 task_template；任务类型不要求流程或创建模板。保留现有非空数据库列时使用兼容占位值，API 不将其暴露为任务类型必填项。
- ScheduleRun 增加可空 `coordinator_turn_id`。任务类型的 `task_id` 指向被处理任务，项目类型仍指向创建结果；执行记录返回关联的指令及回复消息 ID，支持跳转。
- CoordinatorTurn 增加执行作用域（`main` / `scheduled`）和可空调度来源标识；独立 session ID 使用现有回合字段保存。任务主 CoordinatorSession 的表结构和每任务唯一性保持不变。
- 扩展既有 schedule 创建、更新、列表、详情、执行记录接口及工具注册声明；列表支持 `target_type`、`task_id` 筛选。任务目标必须存在于指定项目且未归档。创建后目标类型和目标任务不可变，需要更换时新建规则。
- 默认省略 target_type 时为 project，旧 CLI/API 请求保持兼容。任务类型必填 target_task_id 和非空 instruction，禁止混用项目创建字段；任务类型 overlap 只接受 skip，避免同规则堆积或并行操作。
- CLI 复用 `schedule create/update/list/get/pause/resume/delete/runs`，新增 `--target project|task`、`--task`、`--stop-condition manual|task-terminal`；`--instruction` 同时用于项目动态生成和任务协调指令，由 target 区分。新增 `--every-minutes N`，与 at/cron 互斥。列表摘要增加目标类型和任务 ID。
- 分钟规则采用锚定间隔：创建或恢复后 N 分钟首次执行，后续按计划时刻推进；新增独立规则 kind，避免改变现有按每日小时对齐的 interval 语义。N 为正整数，前后端共享限制 1–10080 分钟，页面预览复用既有规则服务。10 分钟不转换为可能具有不同语义的 cron。
- 数据迁移提供旧记录兼容测试；所有数据库工作单元通过项目 run_db 执行。存储位置使用 Project.workstep_dir，兼容项目内和集中存储模式。

## 调度与协调执行

1. 现有轮询器领取到期规则，使用原有 `(schedule, scheduled_for)` 唯一约束创建执行记录，并推进下次时间。项目目标走原分支，任务目标交给专门的协调执行适配器。
2. 为协调助手增加内部定时提交入口。它只接受持久化且已校验的调度执行 ID，使用创建人的身份快照和 scheduler 来源落库，不依赖当前登录用户，也不能成为公开绕过用户身份门禁的入口。
3. 在一个项目数据库事务内创建 CoordinatorTurn、scheduler 指令消息和助手消息，并关联 ScheduleRun。使用 run ID 生成稳定幂等键，重复领取不得产生重复消息或回合；事务失败不残留半条关联。
4. 每次定时执行从空引擎 session 开始，不采用分叉、不调用主会话重置，也不写回主 session 的引擎状态、摘要或版本。引擎和模型使用该任务当前协调配置，按现有默认配置规则解析。
5. 复用协调助手公共执行管线，通过执行作用域区分会话读取、上下文、锁和完成持久化。主对话维持任务级串行锁，定时回合使用独立锁；不得复制完整协调助手实现。必要的执行作用域逻辑抽离组合模块，避免继续扩大 coordinator.py。
6. 定时上下文显式包含任务描述、当前步骤和运行状态、审核/待确认信息、近期已落库对话与结果，以及可查询历史和产物的 CLI 引导；复用现有上下文预算与裁剪。空 session 不能因引擎支持 resume 而省略任务背景。不读取另一运行中 session 的私有状态；上下文注明采集时间，执行操作时重新验证当前状态。
7. ScheduleRun 从 queued 转 running 后，等待关联协调回合终结再记成功、失败或中止，不能把消息已提交当作执行成功。生成待确认提案即完成本轮，记录“待用户确认”；确认后的动作结果沿用提案记录，不将规则长期挂起。成功表示助手回合完成，自动通知是否成功以每轮 notification_status 为准，自定义 CLI 发送以工具结果为准。
8. 同一规则上一轮 queued/running 时，本次触发记 skipped。不同规则和用户对话可并发生成回复；有副作用的操作复用现有提案确认、版本验证和操作互斥，补齐必要竞态测试，不用生成期间的全任务锁阻塞用户对话。
9. 定时执行不自动重试整个助手回合，避免重复发送或重复操作。失败保存原因，下个正常周期继续。服务重启跳过离线触发；未提交的排队执行恢复一次，已提交但未开始的回合按既有恢复机制执行；重启前已运行的定时回合标记中断，不自动重放指令。恢复逻辑必须按作用域区分，保留原主对话恢复行为。
10. 单次运行沿用协调助手现有超时和停止机制，执行资源在终结时释放。定时规则暂停不停止已开始回合；用户可单独停止该回合。删除规则保留已有执行历史，禁止级联破坏任务消息及提案。

## 生命周期、渠道与界面

- 默认 stop_condition=manual，任务暂停、等待审核、完成、失败、取消均不自动停用；用户明确要求任务结束后停止时设 task_terminal，检测任务现有终态后停止后续触发，不额外自动生成最终汇报。规则因终态停止后，重跑任务不自动恢复，需手动恢复且任务已不在终态。
- 任务归档/删除后规则失效，清除下次时间、取消尚未开始的回合并停止活动定时回合；恢复任务不自动恢复旧规则。按目标任务清理，不能误伤其他任务规则。规则编辑只影响未来执行，当前回合使用已保存指令快照。
- 指令消息显示“定时任务 · 规则名称”，作者类型 scheduler；助手消息显示定时来源、时间、运行状态，展开查看现有时间线、提示词和工具结果。跳过触发只在规则执行记录显示，不污染任务对话。
- 消息流、历史回放和停止按 turn/message ID 隔离。任务级主输入状态不能被定时回合改成全局忙碌；主停止按钮只停主回合，定时消息独立停止。提案、权限和选择题必须绑定原回合，不能误操作另一并发回复。
- 新增来源信息经统一 AG-UI 翻译层进入实时与历史接口，前端 store 不消费内部事件。任务详情与分享页都能查看定时消息和过程；新增读取能力通过 TaskDetailReadCapabilities 接入，分享页按现有授权限制操作。
- 复用 SchedulePage，提供“项目创建任务 / 任务协调指令”类型选择、任务搜索选择、自由文本指令、频率与停止条件。任务类型隐藏流程模板、创建执行模式和重叠策略。列表支持类型和任务筛选，显示关联任务与执行记录跳转。
- 新增独立的任务规则表单组合模块，拥有请求、校验、未保存关闭保护；公共规则编辑控件复用。暂不新增任务详情管理入口，以已有管理页及对话 CLI 覆盖首期。不得增加重复加载请求。
- 页面字段必填校验、ConfirmDialog、弹框缩放、移动布局、语义 CSS 和 i18n 遵循仓库约定；中文先行，其余词典键集合一致。
- 更新协调助手提示词与 CLI Skill：任务对话里默认绑定当前任务；保存明确频率、完整指令和停止条件；创建后反馈规则 ID 和下次执行时间。创建时说明通知默认值，支持 CLI 显式开关和指定目标；自动通知开启时避免重复调用 CLI 发送同一报告。
- 定时来源消息不进入现有渠道正文自动广播或来源回复链路，由规则通知或显式 CLI 发送，避免重复转发。普通用户协调对话及任务步骤、审核的既有转发保持原行为。排除依据为显式执行来源，不能依赖正文内容判断。

## 实施顺序与验证

遵循 TDD：各阶段先写失败行为测试，再实现，测试通过后进入下一阶段。

1. 数据迁移、目标校验及分钟规则：验证旧记录兼容、项目类型固定/动态创建、10 分钟锚定与预览、跨项目任务拒绝、编辑和恢复语义。
2. 独立协调执行：测试主回合与定时回合真实并发，不共享引擎 session、锁、摘要和流式消息；停止隔离、任务背景完整、错误与提案归属正确；主对话、权限及协调提案回归。
3. 调度集成与生命周期：真实后台 tick 测试幂等领取、同规则跳过、不同规则并发、完成关联、重启不重放已运行指令、离线不补发、归档/删除/恢复、规则暂停/删除与执行快照。覆盖并发副作用版本冲突。
4. API、CLI、工具声明和提示词：真实 API 与 CLI 请求映射测试，创建/更新/筛选一致，工具必填参数按目标类型校验；假渠道适配器验证 CLI 发送一次、自动转发排除、错误可见及普通转发无回归，不向真实群发测试消息。
5. Web 管理及任务历史：模块行为测试覆盖字段切换、任务选择、分钟预览、表单关闭保护、记录跳转、并发消息、停止和错误恢复；分享会话读取测试、词典一致性、Web 测试和构建，320/390/1023px 实际渲染核对。
6. 异步 canary：慢 SQL/锁竞争、慢上下文文件读取、慢引擎和慢渠道发送期间健康检查可及时响应；所有新增 Peewee 路径经项目执行器。覆盖两种项目数据存储模式。
7. 同步 docs/code-map.md、技术说明和 CLI 使用说明。日常开发不采集手册截图；本批 dev 合并本地 main 的交付节点，集中更新用户手册及固定 8777 模拟项目真实截图，执行官网测试、构建、manual:check，返回 dev；远端推送仅按用户指令。

验收示例：在已有任务对话中请求“每 10 分钟汇报整体进度并通过 CLI 发到指定绑定群”，助手创建可管理的任务规则；到点使用新 session 执行，消息在该任务历史可见，渠道只收到一次。执行期间用户仍可发消息并获得主会话回复；单独停止任一回合不会影响另一回合。

## 边界与默认值

- 本计划仅扩展现有能力，不另建定时管理页、汇报助手、渠道发送管线或引擎分叉适配。
- 每次定时执行都使用新 session，首期不提供复用定时会话或分叉主会话选项。
- 默认持续至手动关闭，同规则重叠跳过，离线触发不补发，失败不自动重放。
- 自由文本允许使用协调助手已有能力，不新增自动确认权限；现有确认步骤继续等待用户。
- 已于 2026-10-16 在 dev 工作区实施；本批尚未合并或发布，操作手册按仓库约定在批次合并交付时统一同步。

## 渠道完成通知补充（最终交互）

- 统一通知开关和机器人／会话选择。任务级有绑定群时创建默认开启并选中该群；无绑定群和项目级默认关闭，开启后必须选择有效目标。显式 UI／CLI 配置覆盖默认值，编辑既有规则不重新应用默认值；旧库规则迁移后保持通知关闭。
- 任务级在本轮协调回合结束后通知最终回复或失败原因；项目级成功创建任务后立即通知名称与任务入口，不等待流程完成。
- 规则与每轮目标快照分别保存；通知状态／错误与执行状态分开，失败可独立重试，不重跑任务、不改发其他会话。发送中断标记结果未知，核对渠道后手动重试。
- CLI 创建／修改支持 `--notify`、`--no-notify`、`--notify-session` 或 `--notify-bot`＋`--notify-group`；发现和重试使用 `schedule notification-options`／`schedule retry-notification`。
