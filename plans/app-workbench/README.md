# 应用工作台设计草案

日期：2026-10-31。状态：需求与交互原型，尚未实现产品能力。

- [产品需求 PRD](prd.md)
- [交互原型](index.html) — 用浏览器直接打开，默认从客户管理应用的开发态开始。
- [架构图](architecture.html) — 系统、部署与身份、版本与数据库三个视图。
- [流程图](flows.html) — 接入、开发、数据准备、发布、回退五条流程。

原型无网络依赖，不访问真实数据、不执行脚本、不调用模型、不启动 Docker。状态只存在当前页面内存中，刷新或“重置演示”恢复初始状态。进度、容量、测试结果和耗时均为演示值。

建议体验顺序：

1. 默认“常规更新”：发送修改 → 启动预览 → 运行测试 → 创建版本 → 发布检查 → 开始发布。
2. 切换“大表结构变更”：在环境与数据中选择隔离库、准备数据，查看版本发布中的高风险检查。
3. 切换“数据量过大”：比较全量复制与仅结构／业务子集，观察数据准备状态。
4. 切换“发布失败”：完整走到健康检查失败，核对正式版本未切换，重试发布。
5. 切换“回退不兼容”：版本页回退 v1.1.0，查看禁止直接回退和独立数据恢复确认。
6. 切换“空项目”：查看工作台模板包，应用后一起生成 6 条流程、6 个项目按钮和 5 个对话按钮。重复应用不会重复生成；“查看流程与按钮配置”可修改项目流程名称。
7. 在开发页点击“梳理需求”，提示词只填入输入框，确认发送后才修改草稿；“创建版本”“发布上线”“切换版本”等项目按钮复用原有版本和风险检查入口。

本草案中的默认值和方案不是现有运行行为；真实实现前需补部署执行器、持久化任务和数据库适配验证。见 PRD 的待验证事项。
