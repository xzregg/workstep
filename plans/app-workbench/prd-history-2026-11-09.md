# WorkStep 应用工作台 PRD

版本：讨论稿 v0.1 · 2026-10-31 · 配套：[原型](index.html) / [架构图](architecture.html) / [流程图](flows.html)

## 1. 产品目标与边界

把 WorkStep 项目升级为可选的应用开发与交付工作台。用户从模板新建应用，或导入本地目录／Git 仓库，通过聊天修改代码、预览、测试、形成版本并发布到本机或远程 Docker 主机。

用户心智：**聊到满意 → 预览程序 → 测试 → 创建版本 → 发布 → 必要时回退。**

首期“低代码”指模板、配置表单和聊天生成代码；不做拖拽页面编辑器。导入程序保留原技术栈，不要求迁移到特定前端或 ORM。普通项目不自动开启应用能力，不自动创建流程。

本次交付仅为 PRD 和交互原型，不实现服务、不修改现有业务行为、不执行实际部署。

### 用户与身份

| 用户 | 使用范围 |
|---|---|
| 创建者／开发者 | 使用现有 WorkStep／Gateway 身份管理项目、聊天开发、预览和测试 |
| 发布操作者 | 具备应用目标环境的发布权限，可查看风险、发起发布和回退 |
| 应用使用者 | 使用部署后程序自己的账号系统，账号、角色和业务数据归应用管理 |

网关认证复用在工作台控制面。新建后台模板包含独立登录与 RBAC，可配置 IM 身份／组织同步；不能把网关用户自动视为应用用户。导入应用沿用原认证体系。已有“项目发布／分享”开放的是项目访问，必须与新增“部署应用版本”区分。

## 2. 现状与演进方式

当前项目已有目录注册、聊天／模型引擎、Git、任务与工作流，流程模板在创建流程时主动选择。项目入口核对自 `apps/daemon/api/project.py` 和 `apps/web/src/api/project.ts`；Gateway 身份与远程访问职责见 `docs/gateway-development.md`。现有文件预览不等同于完整应用运行环境；现有项目分享不等同于应用部署。

新增应用配置与环境、发布能力，复用原有项目标识、聊天、代码操作、任务事件和权限边界。界面提供“应用接入、开发与预览、环境与数据、版本与发布、应用设置”；普通项目可随时接入，不另建一套项目系统。

## 3. 用户旅程

### 3.1 创建与接入

- 空项目提供“使用工作台模板”或“保持空项目”。空项目指没有业务代码和已有流程，允许存在 Git 元数据、README 与 WorkStep 管理文件。
- 新建应用：主动选择工作台模板及支持的前端框架／组件库、后端架构、SQLite 或 PostgreSQL。确认后同时生成应用底座配置、默认流程、项目快捷按钮和消息对话快捷按钮，不再要求逐一创建流程模板和按钮。
- FastAPI + Peewee 模板基于 `fastapi-peewee-backend` 技能；现有技能默认 SQLite，PostgreSQL 需真实适配驱动、连接、迁移、备份和并发行为，不能只替换连接字符串。
- 导入应用：选择本地目录或 Git 地址／分支，分析仓库并生成接入配置草案，用户查看后保存。凭据通过凭据引用配置，不写进仓库。
- 配置准备／安装命令、启动／停止方式、端口、健康检查、测试命令、Dockerfile／Compose、部署脚本、工作目录和服务列表。支持单仓多服务与子目录。
- AI 识别只提供建议，不未经授权运行仓库脚本；配置不全时显示缺失项，允许先保存但不能标记可预览／可部署。
- 新建模板可包含业务聊天界面和受限模型调用；工作台的开发聊天用于修改程序，两种会话分开。导入程序按需接入模型接口，不强行注入聊天窗口。

### 3.1.1 工作台模板是一套交付方案

模板包包含代码底座、技能引用、运行／部署配置、默认流程集合、项目快捷按钮、对话快捷按钮及其关联关系。用户应用模板是主动初始化配置，不代表自动执行所有流程或发布上线。

| 默认流程 | 标准步骤 | 项目快捷按钮 |
|---|---|---|
| 初始化应用 | 生成底座 → 安装依赖 → 初始化测试库 → 启动预览 | 初始化应用 |
| 开发验证 | 需求分析 → 修改代码 → 预览测试 → 代码审核 | 开发验证 |
| 创建版本 | 固定代码 → Docker 构建 → 镜像验证 → 保存版本 | 创建版本 |
| 发布上线 | 选择版本／环境 → 风险评估 → 备份／迁移 → 部署／健康检查 → 确认切换入口 | 发布上线 |
| 切换／回退版本 | 选择版本 → 数据库兼容检查 → 启动验证 → 确认切换入口 | 切换版本 |
| 准备测试数据 | 选择来源 → 容量评估 → 复制恢复 → 脱敏／迁移校验 | 准备测试数据 |

两类快捷按钮均随模板生成，并允许用户后续编辑、排序、启停及增删：

- **项目快捷按钮**：放在项目操作区域，关联对应流程或平台标准动作。点击后收集版本、目标环境等参数，展示进度与执行结果。初始化、构建、发布等可以独立触发，不要求每次从头跑完整开发链。
- **消息对话快捷按钮**：放在项目开发对话输入区域，包含“梳理需求、继续实现、检查本次修改”等提示词按钮，以及“启动预览、运行测试”等动作按钮。提示词默认填入输入框，由用户确认后发送；动作必须明确展示执行性质。
- 发布或切换入口可从对话发起，但只能进入相同的版本选择、授权、风险及确认流程，不能通过立即发送提示词或执行任意脚本绕过。没有可发布版本时按钮给出缺失条件。
- 模板包保存稳定的模板标识／版本及内部流程、按钮引用。应用时把这些引用映射到新项目的实例标识；不能带入来源项目的流程 ID、主机凭据、密钥、会话和业务数据。
- 重复应用同一模板按引用补齐缺失项，不重复创建流程／按钮，不覆盖用户改动。模板升级先显示差异，用户选择接收更新；不能自动覆盖已定制流程。
- 已有仓库可仅应用运行配置、流程和按钮。代码与已有流程保持不变，重名项先显示冲突处理；同一按钮被绑定到不存在的流程时禁用并提示修复。
- 模板描述编排，平台提供构建、备份、迁移、健康检查、版本切换等受控执行能力。复用现有快捷按钮的提示词／动作／确认配置；生命周期流程是拟议的新增平台能力，不能假定现有任意脚本已具备可靠发布和恢复能力。

原型演示完整模板包的 6 条流程、6 个项目按钮及 5 个对话按钮，支持应用、重复检查、修改流程名称和按钮触发；步骤编辑、排序、启停、升级差异及冲突处理仅在本 PRD 中定义，尚未在原型完整实现。

### 3.1.2 智能初始化：嵌入现有界面

配套原型：[按现有布局体验智能接入](onboarding.html)。现有界面依据 `ProjectConnectionDialog.tsx` 的本地／远程项目入口、`Layout.tsx` 的项目—流程—对话侧栏，以及聊天页的“打开目录／Git／配置”和输入区快捷操作。使用模拟客户项目，未复制真实聊天或凭据。

| 阶段 | 所在界面 | 操作与结果 |
|---|---|---|
| 入口 | 侧栏“项目 ＋” | 打开现有添加项目弹框；本地目录选择和数据存储选项保留，增加可跳过的智能配置选项 |
| 选择项目 | 添加项目弹框第 1 步 | 选本地目录，或从 Git 获取后选择检出目录；“远程项目”仍指 WorkStep 分享，不等同 Docker 主机 |
| 分析 | 同一弹框第 2 步 | 读取结构、启动、数据库、Docker、CI/CD，展示进度与证据。只读分析，不执行代码 |
| 确认 | 同一弹框第 3 步 | 展示识别结果、推测和缺失项；选择启动方案，确认测试库及 CI/CD 衔接方式，预览将创建的流程与按钮 |
| 验证 | 同一弹框第 4 步 | 用户查看执行计划后，启动独立测试环境并检查健康与测试结果；失败可调整重试，也可存为未验证草稿 |
| 应用 | 同一弹框第 5 步 | 确认新增项和保留项，生成当前项目的配置与流程／按钮，然后返回原聊天页面 |
| 使用 | 现有项目与聊天页 | 流程在左侧项目下面，项目按钮在操作区，对话按钮在输入框上方，预览在聊天右侧。后续创建版本进入既定版本发布流程 |

已有项目从“项目更多操作／聊天头部配置 → 工作台 → 分析当前项目”进入同一套流程，不必重新注册项目。关闭未应用的方案时保留草稿或继续编辑；再次打开从原步骤恢复。普通项目添加不受工作台配置阻塞。

**智能分析范围与证据：**

- 读取依赖清单、锁文件、脚本、README、Dockerfile、Compose、迁移配置和已有流水线；识别多服务、工作目录、端口、测试命令、环境变量及健康检查。
- 每项建议记录文件位置和来源，区分“已识别”“推测”“缺少配置”。发现多种启动方式让用户确认；脚本来自仓库不代表已安全或已验证。
- 读取 CI/CD 的触发条件、测试、镜像构建、制品和部署步骤。分析阶段不修改流水线或触发发布。
- 默认沿用已有 CI/CD。也可选择由工作台触发原流水线，或由工作台负责交付；前者需要受限凭据及状态回传，后者需要确认原部署触发已处理，避免重复部署。
- 识别完成但未接通 CI/CD 的项目，仍可生成发布流程草稿；正式发布和切换按钮保持禁用，显示待配置原因。不能仅靠“我已了解”勾选即开放生产操作。
- 未绑定测试库、未确认执行计划或目标为正式环境时不能启动接入验证。验证通过只代表测试运行可用，不代表部署脚本／DNS／生产迁移已验收。
- 导入应用保留代码与原流水线；已有同名流程采用明确的新名称，不覆盖已有实例。重复分析先产生建议差异，不自动替换已应用配置。

本轮原型演示：已有代码、空目录、现有项目补配置、验证失败四种路径；分析均读取固定模拟清单，CI/CD 凭据配置和实际执行尚未实现。

### 3.2 聊天、预览与测试

- 复用现有聊天和任务／流程体系；独立预览运行环境使用开发代码，不改正式服务。
- 修改后展示变更摘要、代码快照标识及是否涉及结构迁移；无确定证据时标记“需检查”，不以 AI 判断替代迁移工具。
- 启动预览后显示准备、启动、就绪／失败和日志；展示预览实际对应的代码标识，旧预览明确标为过期。
- 热更新由项目能力决定；不支持热更新的项目显示重启／重建。原型用“启动预览”模拟验证当前代码。
- 可运行项目测试，也能在预览界面人工验收。测试结果绑定代码、迁移集、测试库结构和数据快照；任一改变使旧结果过期。
- 没有自动测试的仓库显示“未配置”，由显式人工验证策略处理，不伪造通过。
- 用户满意后点击创建版本；测试未完成、预览非当前代码或数据未就绪时显示原因，不能静默使用旧结果。

### 3.3 创建版本

版本号默认建议递增，可填写说明；项目内唯一。版本固定源代码快照／提交、接入配置快照、迁移清单及校验和、镜像摘要和架构、测试证据。不能仅保存一个可变 Git 分支名或 `latest` 标签。

创建时固定源代码，再用该快照构建 Docker 镜像并进行隔离启动验证。构建中／失败都可查看记录；只有构建和版本验证通过才成为“可发布”。继续聊天产生新草稿，不修改已有版本。后续配置变更不得悄悄改变已验证的版本内容。

多服务版本记录各服务镜像摘要及 Compose 配置快照。构建架构需匹配目标主机；不匹配则重新形成对应构建记录并验证，不在正式部署时临时从源码构建。

### 3.4 发布

选择版本及环境 → 比较版本／数据库差异 → 生成发布预检 → 确认方案 → 备份 → 迁移 → 启动 → 健康检查 → 切换流量 → 验证正式入口 → 成功。

- 正式发布复用已验证镜像；环境密钥独立注入，不打包进镜像。发布记录固定配置修订引用，密钥值不明文展示。
- 数据库卷和上传文件卷位于容器生命周期之外，更新镜像不替换业务数据。
- 每应用每环境只允许一个变更任务执行；发布、恢复和测试库替换需要互斥。请求重试复用操作标识，防止重复迁移。
- 任务持久化步骤、日志索引、当前部署与上一部署；页面关闭后任务继续，重新打开恢复状态。
- 网络断连标记“状态待确认”，重连查询执行结果，不能直接当失败再次部署。
- 未进入有副作用阶段可取消；迁移／流量切换等阶段禁止假取消，显示当前可执行的恢复动作。
- 蓝绿启动及入口切换仅在资源和数据库兼容时使用。高风险不兼容迁移要求维护窗口／暂停写入及明确恢复方案，不承诺所有应用零停机。
- 自定义脚本有日志、退出码、超时及步骤边界；无结构化能力的脚本不虚构细粒度百分比。

### 3.5 回退

回退是新部署记录，引用历史镜像与配置，保留原发布历史。默认只回退程序，不倒退业务数据。

- 先校验旧版本支持的结构、迁移声明与演练证据；兼容则启动旧镜像、健康检查并切换入口。
- 不兼容或兼容性未知时禁止一键回退。给出修复前进、经验证的逆向迁移或备份恢复方案。
- 数据恢复单独列出备份时点及之后可能丢失的数据，要求有权限的操作者再次确认，并按维护恢复流程执行。
- 迁移失败不能简单切回旧镜像后宣称恢复；先判断数据库是否已部分变化，必要时保持维护状态。
- 旧镜像保留策略可配置；删除前列出受影响版本。缺失镜像／配置／备份时明确显示无法执行，不显示无条件回退按钮。

## 4. 数据库与测试数据

### 4.1 四个独立概念

| 对象 | 生命周期与关系 |
|---|---|
| 代码版本 | 固定构建产物，声明要求／支持的结构范围 |
| 结构版本 | 迁移集标识及校验和，记录已应用迁移；兼容性来自约定与验证，不只比较编号 |
| 数据库实例 | 绑定环境、引擎、存储及当前结构；可被多个兼容代码版本先后使用 |
| 数据快照 | 记录来源、时点、体积、结构及抽取规则，不随每次聊天重新生成 |

WorkStep 自己的 per-project SQLite 继续用于项目编排，不能等同于应用业务数据库。新建应用可选 SQLite／PostgreSQL；导入应用尊重现有数据引擎。首期平台数据复制适配 SQLite 和 PostgreSQL，不默认支持跨引擎转换。

### 4.2 调试库选择

- 无表结构变化：默认复用当前测试库，节省准备时间。
- 有变化：选择迁移当前测试库或基于快照创建隔离测试库；需要旧版同时运行时必须隔离有副作用的结构与写入。
- 空库初始化用于首次安装验证；复制旧库后迁移用于升级验证，两种测试不能互相代替。
- 共享测试库显示当前使用者和占用状态；只允许顺序使用或明确兼容的访问，禁止多个迁移任务竞争同一个实例。
- 平台 UI 显示数据库“复用、准备中、迁移中、就绪、失败、状态待确认”，失败的半成品不作为可用数据源。

### 4.3 测试数据准备与时效

可选内置种子、已有快照、正式库复制或仅结构。开始前显示源／目标、源结构、采集时点、数据规模、目标空间和预计耗时；未知项明确标记。正式库仅作为源，目标必须是非正式实例，执行端再次核验。

- 大数据量提供全量、仅结构、按表／业务范围抽取。抽取要保持关联完整性，不独立截断每张表。
- 推荐交互默认：预计超过 1 GiB 或 5 分钟提示“大规模准备”；值为可配置初始阈值，容量无法估计时也提示不确定性。
- SQLite 使用一致性备份，不能只复制正在写入的主文件而忽略 WAL；PostgreSQL 使用一致性导出／恢复，记录源负载和所需权限。
- 优先复用兼容快照，显示“采集于何时、是否适用当前结构”；演示默认超过 24 小时提示陈旧，不自动销毁或强制重新复制。
- 准备任务分评估、导出／复制、恢复、脱敏与环境处理、迁移、校验；显示实际可获得的计量与估时依据。源变化或吞吐变化可修正估计。
- 大文件／远程传输可按适配能力重试；不支持断点续传时明确重新开始的范围，不能承诺任意步骤续跑。
- 默认使用种子或脱敏快照；复制真实业务数据前显式告知。应用账号、凭据、通知、定时任务及外部写操作按模板／适配器清理或关闭，无法可靠处理时阻止标记安全就绪，交由操作者配置验证。
- 平台阻断正式配置和凭据自动复制；正式数据不会被测试结果反向覆盖。

### 4.4 迁移风险评估

评估是工具事实、迁移规则和操作者判断的组合，AI 只解释证据。记录评估时点、目标实例、目标结构及源代码／迁移摘要；目标变化后重新评估。

| 检查 | 需要呈现的信息 |
|---|---|
| 大表字段／类型修改 | 行数／字节数、是否重写整表、锁类型、影响读写及额外空间 |
| 索引／唯一性／非空约束 | 构建方式、脏数据预检查、锁等待、失败条件 |
| 删除／重命名／数据回填 | 数据损失风险、旧代码兼容、批处理与中断恢复方式 |
| SQLite 特性 | 单写入竞争、表重建与一致性备份要求 |
| PostgreSQL 特性 | 版本相关 DDL 行为、事务限制、长事务与锁等待 |
| 演练与恢复 | 同规模证据、实际耗时、维护窗口、备份可恢复性 |

输出低／中／高／未知风险、证据、阻塞项和建议。高风险需要维护方案与明确确认；空间不足、迁移不一致、无必要备份／恢复方案等硬阻塞不能通过勾选强行忽略。未知风险不显示为低风险。

## 5. 配置与系统边界

### 应用接入契约

接入配置包含项目／仓库子目录、服务定义、准备／启动／测试／构建命令、端口、健康检查、Dockerfile／Compose、部署步骤、数据库与迁移／种子适配声明、环境变量定义及凭据引用。代码侧配置可版本化，主机凭据、环境密钥和运行状态留在受保护的控制面。

推荐第一版远程主机经 SSH 接入并验证主机指纹，执行 Docker／Compose；本机使用同一执行协议。不引入 Kubernetes 作为前置要求。具体执行适配方案需实现前验证。

域名映射包含预览／正式环境入口、DNS 检查、反向代理路由、证书状态。绑定成功不等于 DNS 生效；目标不可达或证书异常分别显示。开发预览沿用工作台授权，业务正式域名使用应用自身认证，不能把应用凭据与网关 Cookie 混用。

模型调用由受限服务凭据和应用级能力授权接入 WorkStep 统一引擎，限制可用模型、额度／并发与工具范围。业务请求不能通过开发聊天入口获得任意宿主操作权限。

### 推荐模块

- 控制面：应用配置／模板、环境与凭据、版本与构建、发布任务、数据库计划／快照及审计。
- 执行面：本机／远程适配器，受控任务、Docker、多服务编排、备份／迁移工具、健康检查与日志。
- 运行面：应用前后端、独立用户／RBAC、业务库、文件卷、域名路由。

关键接口能力：应用接入配置读写；预览启停；测试任务；版本构建及查询；环境预检；发布／回退任务；数据评估／准备任务；日志／状态订阅。任务返回可恢复查询的操作标识，事件沿用项目对外统一事件边界，不另造引擎协议。此 PRD 不锁定具体 REST 路径与表结构。

## 6. 验收与分期

### 产品验收场景

1. 普通项目行为不变；开启应用能力后，模板新建和任意栈仓库接入进入同一开发流程。
2. 无结构变更可复用测试库，测试通过后创建不可变版本，部署同一镜像，正式数据保留。
3. 大表变更显示证据、空间／锁风险及维护方案；硬阻塞时不可发布。
4. 大数据准备可选择兼容快照或子集，陈旧／不兼容有提示，未就绪不能运行依赖测试。
5. 聊天继续修改不改变旧版本；旧测试证据过期，旧预览不能冒充新代码。
6. 健康检查失败不切换流量；迁移失败按数据库实际状态恢复，不能无条件报告旧版仍可用。
7. 回退兼容版本保留数据；不兼容、未知或镜像缺失阻止直接回退；数据恢复独立确认。
8. 页面关闭／远程断连后，操作可查询恢复，不重复执行迁移；日志与密钥隔离。
9. 网关开发者身份、应用用户身份、应用模型服务身份互不隐式提权。
10. 空项目不选择模板时不生成流程；主动应用模板后，流程与两类快捷按钮一并创建，彼此引用正确且不自动执行。
11. 提示词按钮只填入草稿，动作按钮遵守运行条件；项目按钮与对话动作不绕过版本、环境和数据库门禁。重复应用不增加重复项、不覆盖已修改流程。

### 交付顺序

先验证本交互原型；实现阶段按：接入与隔离预览 → 不可变版本与本机／远程 Docker 发布回退 → 数据库风险与快照准备 → 后台模板 RBAC／IM 完善。数据库高风险能力完成前，应阻止不支持的迁移发布，不能先开放无保护入口。

### 待工程验证事项

- 首批可支持的前后端模板组合及 PostgreSQL 适配矩阵；导入项目的迁移工具能力检测。
- 不同数据库版本的 DDL 风险规则及测量方式，演练规模与估时误差。
- SSH 断连恢复、镜像分发／存储、目标架构以及远程执行的可靠性。
- 域名反向代理／TLS 具体实现与共享主机资源限制。

## 7. 原型说明

所有容量、日期、日志、测试结果、镜像摘要和进度均为模拟，状态只在页面内存。原型中的“创建版本”模拟构建验证，“发布”模拟环境变更，数据库恢复确认不执行真实恢复。原型用于确定用户流程，不代表上述能力已支持。


## 2026-11-07：简化工作台入口与版本定义（优先于早期向导方案）

工作台是项目的一项能力。沿用项目侧栏、既有会话、聊天输入与执行基础设施。项目名称右侧提供工作台入口，打开程序预览；项目内多个对话共同修改同一份开发工作区。并发写入必须串行或使用明确的隔离分支并合并，不能静默覆盖其他对话的修改。

交互比较：A 对话为主＋右侧预览；B 程序为主＋右侧对话；C 对话／工作台页签切换。三个 HTML 原型仅比较布局，业务语义相同，尚未确定最终布局。日常路径为“聊天修改 → 预览与测试 → 创建版本 → 部署”。历史版本从预览选择器或版本记录进入。

用户主动启用模板时一并生成预览与测试、创建版本、部署上线、回滚版本流程及快捷按钮。普通项目仍保持无默认流程；已有项目自动分析配置，缺失项按需补齐，不强制经过完整向导。原五步向导降为高级接入参考。快捷按钮调用项目流程，结果回到当前对话，并可展开执行详情。

每个正式创建的应用版本对应唯一、不可移动的 Git Tag。草稿不创建 Tag。创建版本前展示拟纳入的代码变更，完成测试并固定提交，然后创建注释 Tag，构建镜像并记录不可变 digest、schema 版本、迁移清单和验证结果。构建失败显示版本构建失败，可对同一提交重试，不移动或复用 Tag。发布就绪要求镜像和验证完整；Tag 本身不代表已上线。推送远程仓库沿用项目配置与权限，不隐含在创建本地 Tag 中。

部署记录独立于应用版本：同一版本可多次部署至不同环境，复用相同镜像。环境绑定实际数据库实例，不为每个 Tag 默认新建数据库。历史版本预览运行固定版本代码，使用兼容的测试库；不兼容时再准备隔离库和测试数据，并展示成本及进度。不能通过切换版本预览器改动当前开发工作区或正式流量。

回滚选择已有版本镜像，先检查当前 schema 是否兼容；兼容则切换代码并保留正式数据，不兼容则阻止直接回滚并提供独立修复／恢复方案。部署时执行的迁移仍须进行大表、锁、耗时、备份和空间评估。页面只在需要用户决策时展开这些信息。


## 2026-11-07：确认交互与工作台目录模型（覆盖此前布局比较）

项目新增可选工作台属性，不引入另一套项目或会话。现有左侧项目／对话列表、聊天组件、输入框及功能保持，新增右侧工作台侧栏。桌面展开态工作台占页面总宽度至少 70%；原型取列表 12%、聊天 18%、工作台 70%。收起后恢复聊天宽度。窄屏使用单区域切换，避免强制三栏挤压。最终产品复用现有聊天组件，只扩展工作台入口、侧栏和快捷按钮。

A/B/C 是同一项目的功能对话，不是三种布局或三个版本。切换对话保留各自消息、输入草稿及执行状态，不切换工作台或预览版本。任何对话均可触发创建版本／打 Tag、发布、回滚流程。创建的版本是工作台仓库完整快照，包含各对话已合入的改动；创建前显示变更清单与测试结果，不能默认为仅包含当前对话。

工作台配置至少包括：enabled、root_directory、startup_command、healthcheck_url、deployment_workflow、gateway_share_policy。目录保存为项目相对路径，`.` 为项目根目录，也可为 `apps/customer` 等子目录；规范化解析后须验证位于项目允许范围并正确处理符号链接。用户指定的目录必须是实际 Git 仓库根目录，不可把父仓库误识别为子目录的独立版本历史。若目录不是独立仓库，提示选择实际仓库或明确初始化；不可静默新建嵌套仓库。

Tag 查询、提交、版本创建、构建和启动均以工作台仓库为范围。项目编排数据与工作台业务数据分离。已有项目先分析该目录的启动方式、部署与 CI/CD；补齐配置后可用，不强制替换原技术栈。

版本选择与启动分开：选择草稿或 Tag → 准备运行目录和兼容测试数据库 → 启动 → 健康检查 → 返回可访问地址。历史 Tag 使用独立检出目录／工作树或对应不可变镜像，不能在正在聊天编辑的目录直接切换 Tag。原型在切换版本后显示“尚未启动”，点击启动模拟可用页面。

启动完成后可通过网关分享当前运行实例。分享绑定实例 ID、版本／草稿标识及访问授权，沿用网关认证，不直接把本机 localhost 当共享链接。明确开发草稿会随修改变化，固定版本可稳定复现代码；数据仍属于运行环境。停止实例后链接不可用，重新启动后由实例／路由策略明确恢复，不能暗中指向其他版本。分享运行实例与部署正式环境是独立动作，启动成功不等于已上线。

网关负责访问工作台的外层身份与权限；应用内部原有业务账号和 RBAC 仍由应用管理，必要时单独配置身份映射。历史版本复用兼容测试库，迁移不兼容时独立准备库；不默认每个 Tag 新建库，更不让预览自动连接正式库。


### 工作台侧栏结构补充

右侧仅由顶部工具栏和填满剩余空间的 iframe 组成。顶部放预览版本、正式版本、运行状态、启动、刷新、分享、版本记录和收起入口。底部不放说明、状态条、按钮或额外留白；操作结果回到现有对话区域。未启动时 iframe 留空，状态和启动入口留在顶部。

真实实现中 iframe 加载工作台运行实例地址；当前静态原型使用 sandbox iframe 与 srcdoc 演示，不启动服务。工作台网页与宿主聊天隔离，跨域通信只允许显式协议与已验证来源；网关代理、嵌入策略及登录态须在接入时验证。

工作台打开入口固定在左侧项目列表的项目项右侧，聊天顶部不提供重复入口。切换同项目对话时保持工作台打开及当前预览状态；收起入口保留在工作台顶部。


## 应用命名、初始化与运行时复用（最新确认）

产品统一称“应用”，项目项右侧入口为“打开应用”。“工作台”保留为历史草案术语。项目配置 → 常规 → 应用是初始化与配置入口。用户选择应用目录、应用模板、框架与数据库；已有项目走接入分析，保留原技术栈。普通项目仍不创建默认流程，只有用户选择应用模板并初始化时补齐对应流程和快捷按钮。

模板分业务骨架与框架底座。首批业务骨架为后台管理应用、空白应用和接入已有应用；默认框架为用户确认的 FastAPI + Peewee + SQLite，允许 PostgreSQL。原型同时提供 Node.js + Fastify 作为可讨论的 Node 模板方向，非已实现产品能力。Python 模板须带异步数据库执行隔离和迁移；PostgreSQL 必须真实适配与验证，不能只换连接字符串。前端可按模板选 React 或 Vue。

初始化过程：选择目录／模板 → 检查目录、Git、运行时与文件冲突 → 生成／接入应用 → 准备独立依赖与草稿配置 → 建立默认流程和快捷按钮 → 回到对话。首次启动和正式发布分别触发。非空目录不直接覆盖；已有 CI/CD 默认保留。当前原型仅演示选择、保存、初始化结果，不实际执行这些步骤。

草稿与正式环境具有独立代码位置、进程／容器、配置、端口和数据库连接。聊天与模板操作只触及草稿。面板顶部有草稿预览／正式应用切换；创建 Tag 不更新正式环境，只有明确发布后才切换正式版本。历史版本预览使用兼容测试库，不在编辑目录切换正式版本。正式分享与草稿分享绑定各自实例。

运行时复用：按模板声明的版本范围检测并复用受管理 Python / Node，不盲目复用任意版本；Python 应用独立 venv，Node 应用独立依赖目录及锁文件。不能往 daemon 自身环境安装业务依赖；升级 WorkStep 后运行实例仍须有明确的兼容或迁移策略，不能依赖临时安装包路径。版本记录包含运行时版本与依赖锁定信息。轻量本地预览可使用进程启动，正式 Docker 发布仍沿用固定镜像；不能把宿主机运行时当作远端容器依赖。

当前代码证据：apps/desktop/README.md 说明桌面独立 Python runtime 和受管理工具目录；apps/desktop/package.json 的 extraResources 包含 backend，Electron runAsNode 为 false。现有 Node/npm 可使用宿主机工具，尚不能宣称所有桌面包包含可供任意应用调用的独立 Node CLI。应用运行时探测、安装与依赖隔离属于本功能待实现能力。

手机：通过现有项目导航的抽屉打开应用，全屏展示顶部工具栏＋iframe；返回对话保留环境与版本。配置使用可滚动表单，修改未保存时提供继续编辑／放弃修改。mobile-preview.html 嵌入实际 390px／320px viewport，展示相同 integrated.html 响应式页面，不是手机截图。

## 最新收敛：应用窗口栏、完整流程与统一 Node 默认模板

第三栏正式名称为“应用窗口栏”。顶部主要操作收敛到草稿／正式切换、正式版本摘要、发布及更多；启动、刷新、分享、历史版本选择和设置放入更多菜单。底部只有 iframe。既有聊天和列表继续保留。完整流程见 application-flow.html。

入口有三种：添加项目时创建应用、导入已有项目并接入应用、已存在的普通项目在配置 → 常规 → 应用中启用。普通项目可暂不启用应用。创建模式选择目录／模板，接入模式分析目录中的 Git、启动方式、环境变量及 CI/CD，缺失项按需补充。两者最终生成统一应用配置、草稿环境与流程按钮。原型的添加项目只模拟来源选择，不执行真实 Git clone／目录浏览／分析执行。

按最新产品方向，新模板统一 Node.js + TypeScript：前端 React（可扩展 Vue），后端 Fastify，数据库 SQLite／PostgreSQL；此前 FastAPI + Peewee 默认方案改为历史讨论，不作为首批新模板默认项。已有 Python 或其它技术栈的项目继续接入，不要求重写。WorkStep daemon 保持自身现有 Python 架构；统一 Node 只约束新建应用模板。ORM／迁移工具另行评估，但必须提供双数据库适配与迁移验证。

基础组件按带版本的模块定义，包含前端界面、后端接口契约、配置、数据库迁移、验证和兼容范围。身份模块提供登录与会话接口；权限模块按之前需求为 RBAC，必须在后端强制鉴权，前端仅负责呈现；统计模块约定业务事件与指标接口。网关负责访问应用的外层身份，应用内部业务身份通过显式映射／交换接入，不共享宿主数据库或复制宿主页面源码。

新模板生成标准组件；已有应用生成适配提案，展示将修改的接口、表和配置，经应用并验证后才启用。组件接入／升级进入草稿、测试、Tag 和发布流程；不得点击勾选即修改正式系统。版本 manifest 记录组件版本。是否真正存在可复用的登录／RBAC／统计后端需实施前审计，原型勾选不代表当前已实现共享组件。


## 非技术用户与渐进展示（最新交互规则）

默认使用态：没有打开对话时，点项目项“打开应用”只显示应用窗口栏，加载已发布的正式应用，不自动打开对话，不显示草稿、Tag 或发布控件。顶部只保留应用名、刷新、分享和收起。

编辑态：用户打开某个对话后，项目列表、聊天、应用窗口栏三栏并存，再展示预览和发布能力。聊天修改仅写草稿；有未发布变更时，即使关闭对话，也保留变更与预览／发布入口，避免遗失状态。关闭对话不撤销代码、停止应用或自动发布。首次创建尚无正式版本的应用应显示“应用待完成”的使用态，不把草稿冒充正式应用。

非技术初始化只选择应用用途模板，目录、框架、数据库及组件使用默认值，置于高级设置。已有项目自动分析，可确认用途及缺失项。应用内部业务操作不必理解 Git、数据库或运行时。完整生命周期能力仍保留，但按任务时机展示。


## 初始化入口修订（覆盖此前常规设置方案）

应用用途模板不标“推荐”，平等展示。模板、框架、数据库、基础组件是添加项目／初始化项目时的可选扩展，不放在配置的常规设置中。普通项目可直接跳过，以后从项目操作 → 初始化应用进入同一套表单。已有应用的运行维护配置与创建模板选择分开，调整运行配置不触发重新生成应用。


## 添加项目与应用初始化串联（当前主流程）

添加项目保持既有项目初始化流程，表单新增可选“将这个项目作为应用”。勾选后，先完成项目注册／初始化，再自动打开该项目设置中的应用初始化面板；不在添加表单内一次塞入框架、数据库与组件。未勾选时成为普通项目，可稍后从项目设置启用应用，复用同一初始化面板。此前“项目设置不提供任何初始化入口”的表述由此修订：常规设置不平铺创建字段，但项目设置可以承接独立应用初始化面板。

面板先自动只读分析，再按结果引导：

- 空目录：选择项目根目录或子目录作为应用目录，选择框架与基础组件；数据库等可折叠。检查目录与仓库边界、文件冲突，再生成最小可运行应用。
- 已有 Git／代码：Git 不等于应用。结合应用配置、依赖清单、启动脚本、CI/CD、数据库配置给出识别证据与不确定项。可识别的应用沿用已有技术栈；不能识别的项目要求补充目录／启动方式，不假装自动接通。
- 已有应用配置：恢复目录、脚本、组件、版本与环境记录，检查当前运行状态；不重新套模板，不覆盖文件或重复生成默认流程。

空目录完成后生成基本欢迎页，准备草稿环境、默认流程和快捷按钮，同时打开应用窗口栏与一段新项目对话。对话首条引导“你想用它解决什么问题？”，用户从这里开始描述业务功能。已有应用接入后显示原页面，不替换为新欢迎页，并可开启新对话改进功能。已有对话保留，新建接入对话不修改历史会话。

自动初始化执行阶段应报告分析、环境准备、生成／接入、启动验证和失败重试；配置可稍后继续。数据库隔离未确认前不得执行启动，项目初始化完成不等于应用已经运行。生成的新应用没有正式版本，明确处于草稿状态。project-journey.html 是当前连续交互原型，包含三组路径和欢迎页；其中分析证据、生成、运行均为模拟，发送消息只演示需求提交。
