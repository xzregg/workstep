# 手机端适配与验收记录

> 状态：已实现，仍待 Safari / Chrome 真机验收。文中的测试数量是 2026-09-08 历史基线，不代表当前测试总数。

2026-09-08。采用 Codex 式抽屉导航与全屏对话，保留 WorkStep 视觉系统。

## 实现

- 小于 1024px 使用抽屉导航、单列任务和全屏详情；手机与平板共享紧凑布局，桌面保留侧栏和看板。导航只有一个实例，切换断点不重建会话或订阅。
- 任务使用现有 `project`、`workflow`、`task` 查询参数；列表进入详情可返回原列表，直接链接关闭后保留项目与流程上下文。
- 详情默认显示对话，阶段和产物通过页签访问；待审核任务有固定入口，继续复用现有审核接口。
- 创建表单的内容、审核配置和 AI 助手分区显示，保留草稿；离开有改动的表单需确认。手机始终使用单列列表，不改写桌面看板偏好。
- 附件、引擎配置及模型选择复用底部面板；面板统一处理返回键、焦点循环、遮罩和滚动锁定。工具过程在手机默认折叠，可手动展开。
- 紧凑布局下画布只读，可缩放、平移和查看节点；禁止连线、拖动、删除快捷键、导入与保存。桌面节点编辑草稿在切换断点时保留。
- 动态视口高度跟随浏览器可视区域，保留安全区；触屏按钮至少 44px，输入字体至少 16px，代码与表格局部滚动。设置、项目配置、文件预览做防溢出适配。
- 无后台接口、数据库或实时事件协议变更。不包含原生应用、离线能力或新的远程连接方案。

## 验证

- 新增 DOM 交互测试覆盖抽屉、单实例导航、任务直达与返回、叠加面板、未保存草稿、过程折叠及模型选择。
- 移动专项、国际化、字号和公共弹窗检查：19 项通过；新增公共组件与 hooks 的 lint 通过；前端生产构建通过。
- 最近一次全量前端测试：408 项，407 通过。`chatInputLayout.test.mjs` 中旧的上下文提示断言仍要求 `contextWindowTitle/contextPercentDetail`，工作区已有实现已改成 `contextCompact` 与用量细分；本次未改写该既有功能或其测试。
- Chromium 浏览器检查覆盖 360、390、430、768、1280px：页面无横向溢出，导航保持单实例，断点切换未增加 WebSocket 连接；手机详情为完整 390×844 视口。
- 已用拦截请求的测试数据验证：菜单返回关闭、模型底部面板、表单切换保留草稿、返回触发放弃确认、审批只提交一次原有接口请求、只读画布无保存按钮且可打开节点信息。
- 可复现浏览器检查位于 `apps/web/scripts/check-mobile.cjs`，要求已有运行中的 Vite 服务及 Playwright。设置 `WORKSTEP_WEB_URL` 可覆盖地址，`PLAYWRIGHT_MODULE` 可指定既有模块路径，`MOBILE_QA_DIR` 可指定截图目录。测试不启动项目服务，拦截所有 API 请求与 WebSocket，不会修改真实任务。
- 设计检测仅报告原有桌面看板和创建表单的两处彩色侧边线，未引入新的该类样式。
