# WorkStep 平台模式实施计划

> 状态：提案，尚未实现。本文描述未来的平台登录、用户、权限、平台数据库和审计方案，不代表当前产品能力。

## 1. 目标

在保留现有本地优先工作方式的基础上，增加可动态开启、无需重启的“平台模式”。平台模式提供用户注册登录、用户管理、项目可见性管理和操作审计，同时继续使用每项目独立 SQLite 数据库。

本计划的核心目标：

- 平台模式可以在系统设置中即时开启或关闭，不重启 daemon。
- 平台模式开启后，用户必须注册并登录才能进入平台。
- 平台主数据库固定为 `<平台根目录>/workstep_platform.db`。
- 普通用户创建的项目只能位于 `<平台根目录>/projects/{username}/{项目目录}`。
- 管理员创建的共享项目可以指定任意本机绝对目录。
- 项目以“是否对当前用户可见”作为统一访问边界，不为每个业务接口设计独立角色权限。
- 普通用户创建的项目默认仅自己可见，可分享给其他平台注册用户。
- 管理员可以创建共享项目并分配可见用户。
- 本地模式和平台模式下，每一条新消息都必须记录用户名或明确的系统身份。
- 任务启动、排队、暂停、恢复、停止、取消、审核等关键动作必须持久化记录操作者。
- 现有项目级数据库继续位于 `<项目目录>/.workstep/workstep.db`。

## 2. 已确认的产品规则

### 2.1 运行模式

系统存在两种模式：

- `local`：现有本地模式，不要求登录，使用系统设置中的本地用户名和设备身份。
- `platform`：平台模式，必须登录，项目列表和项目访问按当前用户的可见项目过滤。

模式切换规则：

- 切换不重启 daemon。
- 模式配置更新后立即作用于新请求。
- 正在执行的任务不被中断，继续使用启动时持久化的发起人身份。
- 模式变化通过全局事件通知前端；前端更新路由状态并重新建立 WebSocket 身份。
- 关闭平台模式不删除平台数据库、用户、项目登记或审计记录。
- 再次开启同一平台根目录时恢复原平台数据。
- 更换平台根目录不自动迁移原平台数据库或项目文件。

### 2.2 平台目录

平台目录结构：

```text
<平台根目录>/
├── workstep_platform.db
└── projects/
    ├── zhangsan/
    │   ├── project-a/
    │   └── project-b/
    └── lisi/
        └── project-c/
```

普通用户创建项目：

- 前端只提交项目名称，不提交物理路径。
- 后端根据当前登录用户生成项目路径。
- 路径固定在 `<平台根目录>/projects/{username}/` 下。
- 普通用户不能注册平台目录外的已有项目。
- `username` 是稳定目录标识，创建后不可修改。
- 展示名称 `display_name` 可以修改，不影响目录。

管理员创建共享项目：

- 可以指定任意本机绝对目录并初始化新项目。
- 可以注册任意已有 WorkStep 项目。
- 平台只登记规范化后的真实路径，不自动移动项目文件。
- 取消平台注册默认只删除登记和可见关系，绝不删除本机目录。

管理员外部路径仍需通过基础安全校验：

- 必须是绝对路径。
- 使用 `resolve()` 得到规范路径。
- 禁止直接把 `/`、用户主目录或平台根目录本身注册为项目。
- 不允许两个项目登记到同一个规范路径。
- 检查读写权限。
- 非空且不是有效 WorkStep 项目的目录不得直接初始化。
- 检测符号链接、重复路径及父子项目嵌套，并阻止高风险情况或要求明确确认。

### 2.3 项目可见性

项目只有两种可见性：

- `private`：仅项目所有者和管理员可见。
- `shared`：所有者、管理员以及被分配用户可见。

项目来源：

- `user_managed`：普通用户创建，路径受平台目录限制。
- `admin_external`：管理员指定任意本机目录创建或注册的共享项目。

管理规则：

- 普通用户创建项目后自动成为所有者，项目默认为 `private`。
- 项目所有者可以添加或移除自己项目的可见用户。
- 管理员可以管理全部项目的可见用户。
- 管理员共享项目可以不指定普通用户所有者，只由管理员维护共享名单。
- 被分享用户获得项目现有功能的使用能力；第一版不再细分只读、编辑者等角色。

“不需要每个接口都授权”的实现含义是：

- 不在每个业务接口重复实现角色和权限判断。
- 所有项目访问统一通过项目解析/数据库执行入口检查项目是否对当前用户可见。
- REST、WebSocket、文件、上传、搜索和统计均复用同一检查结果。
- 前端隐藏不是安全边界；后端必须阻止通过猜测 `project_id` 的越权访问。

### 2.4 身份与消息署名

无论本地模式还是平台模式，每条新消息都要保存不可为空的作者快照。

统一字段语义：

- `author_id`：作者稳定标识。
- `author_username`：消息创建时的用户名快照。
- `author_name`：消息创建时的显示名称快照。
- `author_type`：`user`、`assistant`、`system` 或 `scheduler`。
- `initiated_by_user_id`：触发系统、助手或定时行为的原始用户。
- `initiated_by_username`：原始发起用户名快照。
- `author_device_id`、`author_device_name`：设备快照，保留现有远程项目能力。

记录规则：

| 消息来源 | author | initiated_by |
|---|---|---|
| 本地用户发送 | 系统设置中的本地用户名 | 同一用户 |
| 平台用户发送 | 当前登录用户 | 同一用户 |
| 助手回复 | 助手或引擎身份 | 启动该轮的用户 |
| 系统可见消息 | `system` | 存在原发起人时记录 |
| 定时任务消息 | `scheduler` | 创建或最后启用计划的用户 |
| daemon 恢复执行 | `system` | 原任务运行的发起用户 |

本地模式要求：

- 首次使用仍要求设置本地用户名。
- 本地用户名为空时，不允许发送消息或启动任务。
- 本地用户稳定标识继续使用设备 ID。
- 历史缺失作者的消息显示“历史用户”，不得回填或伪造成当前用户。

覆盖的消息类型：

- 任务执行消息和阶段中途消息。
- 任务协调助手消息。
- AI 流程助手消息。
- 任务创建助手消息。
- 独立聊天会话消息。
- 人工审核消息。
- 系统生成且前端可见的消息。

## 3. 总体架构

### 3.1 数据库分层

平台主数据库：

```text
<平台根目录>/workstep_platform.db
```

负责：

- 平台配置。
- 用户与登录会话。
- 项目注册信息和真实路径。
- 项目所有权与可见用户关系。
- 全局操作审计。

项目数据库：

```text
<项目目录>/.workstep/workstep.db
```

继续负责：

- 任务、阶段、消息、助手会话。
- 工作流、审核、产物和项目设置。
- 项目运行时数据。

平台主数据库使用独立的 Peewee 模型与独立执行器，不复用项目数据库的 `db_proxy` 激活上下文。所有异步路由、WebSocket 和后台协程中的平台数据库操作也必须提交到专用数据库线程执行。

### 3.2 运行时服务

建议新增以下职责边界：

- `PlatformModeService`：读取、校验并原子切换本地/平台运行模式。
- `PlatformDatabaseManager`：按当前平台根目录打开、关闭和切换平台主数据库。
- `AuthenticationService`：注册、登录、注销、会话校验和密码重置。
- `CurrentActorService`：统一生成本地或平台操作者快照。
- `PlatformProjectRegistry`：维护平台项目路径、所有者和可见关系。
- `ProjectAccessResolver`：根据当前身份解析可访问项目，并作为统一访问门禁。
- `AuditService`：追加写入关键操作记录。
- `MessageIdentityService`：为所有消息生成完整作者和发起人字段。

不能让各助手、任务路由、文件路由分别拼装身份字段；必须统一从身份服务取得快照。

### 3.3 热切换状态

后端运行状态：

- `local`
- `platform_initializing`
- `platform_ready`
- `platform_unavailable`
- `switching`

切换过程：

1. 校验目标平台根目录。
2. 打开或创建 `workstep_platform.db` 并运行迁移。
3. 构建新的只读运行时配置快照。
4. 原子替换当前配置和数据库引用。
5. 发布模式变化事件。
6. 新请求使用新模式；旧请求和已运行任务使用开始时捕获的快照完成。

如果切换失败，保留原模式和原数据库引用，前端显示失败原因，不进入半开启状态。

## 4. 平台主数据库模型

### 4.1 `platform_settings`

- `key`，唯一。
- `value_json`。
- `updated_by_user_id`，可空。
- `updated_at`。

平台模式开关和平台根目录的最低引导配置仍需保存在现有全局配置中，使 daemon 能定位平台数据库；平台内部设置保存在主数据库。

### 4.2 `users`

- `id`。
- `username`，唯一、不可修改。
- `display_name`。
- `password_hash`。
- `role`：`admin`、`user`。
- `status`：`pending`、`active`、`disabled`。
- `created_at`、`updated_at`、`last_login_at`。
- `created_by_user_id`，首位管理员可空。

用户名建议仅允许 ASCII 字母、数字、下划线和短横线，统一小写或执行不区分大小写的唯一约束，避免跨平台路径冲突。

### 4.3 `auth_sessions`

- `id`。
- `user_id`。
- `token_hash`，不保存明文令牌。
- `created_at`、`expires_at`、`revoked_at`。
- `last_seen_at`。
- `device_id`、`device_name`。

### 4.4 `platform_projects`

- `id`，与项目自身稳定 ID 一致。
- `name`。
- `path`，规范化绝对路径，唯一。
- `source_type`：`user_managed`、`admin_external`。
- `visibility`：`private`、`shared`。
- `owner_user_id`，管理员共享项目可空。
- `created_by_user_id`。
- `created_at`、`updated_at`。
- `status`：`active`、`unavailable`、`unregistered`。

### 4.5 `project_users`

- `project_id`。
- `user_id`。
- `assigned_by_user_id`。
- `created_at`。
- `(project_id, user_id)` 唯一。

该表只表达“额外可见用户”，项目所有者和管理员不需要重复写入。

### 4.6 `audit_events`

- `id`，建议 UUIDv7。
- `mode`：`local`、`platform`。
- `actor_type`。
- `user_id`、`username`、`display_name`。
- `initiated_by_user_id`、`initiated_by_username`。
- `device_id`、`device_name`。
- `action`。
- `project_id`、`task_id`、`step_key`、`run_id`、`message_id`。
- `result`：`success`、`failure`、`denied`。
- `metadata_json`，只保存经过白名单过滤的精简元数据。
- `request_id`。
- `created_at`。

审计记录只追加，不提供普通编辑和删除接口。不得记录密码、会话令牌、模型密钥或完整敏感消息正文。

## 5. 登录与注册页面

### 5.1 首位管理员初始化 `/platform/setup`

只在平台主数据库没有管理员时开放。

字段：

- 用户名。
- 显示名称。
- 密码。
- 确认密码。
- 只读的平台根目录和主数据库路径。

行为：

- 用户名即时校验格式和唯一性。
- 明确提示用户名将用于项目目录且不可修改。
- 创建成功后自动登录并跳转 `/admin`。
- 初始化完成后，接口永久拒绝再次创建首位管理员。

### 5.2 注册 `/register`

字段：

- 用户名。
- 显示名称。
- 密码。
- 确认密码。

页面展示项目目录预览 `projects/{username}/`，普通用户不看到或编辑服务器完整绝对路径。

状态：

- 开放直接注册：成功后自动登录。
- 开放注册且需要审核：成功后展示等待审核页面。
- 关闭注册：显示“平台当前未开放注册”，隐藏表单。
- 用户名冲突、格式错误、密码不符合要求均在固定错误区域提示并聚焦对应字段。

### 5.3 登录 `/login`

字段：

- 用户名。
- 密码。
- 保持登录。

状态：

- 错误用户名或密码使用统一提示。
- 待审核账户明确提示等待审核。
- 禁用账户明确提示联系管理员。
- 登录失效时保存原目标路由，成功后返回。
- 平台模式关闭后自动进入本地工作台。

第一版不实现邮件找回密码，由管理员在用户管理页重置。

## 6. 管理页面

管理中心使用独立完整页面布局，不继续堆叠到现有 `Layout` 或系统设置弹框中。

### 6.1 路由

- `/admin`：管理概览。
- `/admin/users`：用户管理。
- `/admin/projects`：项目管理。
- `/admin/audit`：操作记录。
- `/admin/settings`：平台设置。

仅管理员显示管理入口。普通用户直接访问管理路由时跳转工作台并提示无权访问。

### 6.2 管理概览

展示：

- 用户数、项目数、共享项目数、运行中任务数。
- 待审核用户数量。
- 不可访问的管理员外部项目。
- 最近关键操作。

概览只提供导航和摘要，不承载复杂编辑。

### 6.3 用户管理

列表字段：

- 用户名、显示名称、角色、状态。
- 拥有项目数、可见项目数。
- 最近登录时间。

筛选：

- 用户名或显示名称。
- 状态。
- 角色。

操作：

- 创建用户。
- 通过注册审核。
- 启用或禁用。
- 重置密码。
- 设置或取消管理员。
- 查看拥有及可见项目。

用户名不可修改。已产生消息或审计记录的用户不物理删除，只允许禁用。

### 6.4 项目管理

列表字段：

- 项目名称。
- 项目来源类型。
- 所有者。
- 可见用户数量。
- 路径状态。
- 当前运行状态摘要。

操作：

- 创建管理员共享项目。
- 注册已有 WorkStep 项目。
- 代普通用户创建受管项目。
- 分配或移除可见用户。
- 打开项目。
- 取消平台注册。

管理员创建共享项目表单：

- 项目名称。
- 本机绝对目录及目录选择器。
- “初始化新项目”或“注册已有项目”。
- 可见用户多选。
- 目录预检结果。

取消注册必须提示“不会删除本机目录或项目文件”。

### 6.5 操作记录

筛选：

- 时间范围。
- 用户。
- 项目。
- 操作类型。
- 结果。
- 关键字。

列表展示：

- 时间、用户名、动作、项目、目标、结果。

详情展示：

- 操作者、设备、运行模式。
- 原始发起人。
- 项目、任务、阶段和运行标识。
- 精简元数据。

### 6.6 平台设置

分区：

- 平台基本信息。
- 注册开关。
- 新用户是否需要管理员审核。
- 会话有效期。
- 平台根目录和 `workstep_platform.db` 路径。
- 普通用户项目路径模板，只读展示。
- 更换平台根目录。
- 关闭平台模式。

更换根目录与关闭模式使用 `ConfirmDialog`，执行期间持续展示旋转状态。

## 7. 用户侧项目页面

### 7.1 我的项目

项目列表分组：

- 我创建的。
- 分享给我的。
- 管理员共享的。

每个项目展示所有者或“平台共享”标识，不展示用户无权知道的完整本机路径。

### 7.2 普通用户创建项目

平台模式下创建弹框只包含项目名称，目录以只读预览显示：

```text
projects/{username}/{项目目录}
```

不显示任意目录选择器和注册已有目录入口。

### 7.3 项目成员设置

在现有项目设置中新增“成员”页签，与现有“公开分享”和“远程访问”分开。

所有者可执行：

- 切换私有或共享。
- 搜索平台注册用户。
- 添加、移除可见用户。

管理员共享项目的普通成员只能查看成员列表，不能修改。

## 8. 统一项目访问流程

平台模式下：

```text
请求或 WebSocket 订阅
  → 解析登录会话
  → 得到当前用户
  → 根据 project_id 查询平台项目登记
  → 判断项目是否对用户可见
  → 取得受信任的项目真实路径
  → 提交到该项目数据库执行器
```

客户端不得通过提交本机路径选择项目。项目路径只能来自平台主数据库中的项目登记。

需要接入统一可见性解析的入口：

- 项目列表和项目详情。
- 任务、工作流、助手、计划任务、频道。
- 历史消息、事件日志、统计和搜索。
- 文件浏览、上传、产物和 Markdown 图片。
- WebSocket 任务、会话和频道订阅。
- 项目导出或公开分享创建。

远程项目和公开任务分享保留现有独立凭据模型，不自动转化为平台注册用户权限。

## 9. 消息和审计改造

### 9.1 消息入口收拢

当前任务消息和聊天消息已经有部分作者字段，但覆盖不完整。实施时建立统一消息身份填充函数，并使所有持久化入口调用它。

要求：

- 用户消息缺少有效用户身份时拒绝创建。
- 助手、系统和定时器消息也必须写入明确 `author_type` 和作者名。
- 助手回复持久化本轮 `initiated_by`，不依赖读取当前请求上下文。
- API 历史响应和 AG-UI 自定义字段统一返回作者快照。
- 前端 `MessageMetaBar` 统一渲染本地或平台作者。

### 9.2 后台身份传播

不能只依赖 `ContextVar` 传播身份。任务启动时把身份快照写入运行记录；队列等待、daemon 恢复、定时器触发和子任务接力都从持久化快照恢复。

需要覆盖：

- `WorkflowRun`。
- 助手会话轮次。
- 定时计划。
- 人工审核和交互响应。
- 跨阶段任务分发。

### 9.3 审计动作

第一版至少记录：

- 平台开启、关闭、根目录切换。
- 注册、登录成功、登录失败、退出、用户审核、禁用和密码重置。
- 创建、注册、取消注册项目。
- 项目可见性和成员变化。
- 创建、修改、归档、删除任务。
- 启动、排队、暂停、恢复、停止和取消任务或阶段。
- 人工审核、审批和交互答复。
- 定时计划创建、启用、暂停及触发。
- 消息创建失败等需要追责的异常。

普通消息正文仍以项目数据库为权威；审计表只保存消息标识和动作，不重复保存正文。

## 10. 前端全局状态

前端平台状态：

- `local`
- `platform_initializing`
- `platform_unauthenticated`
- `platform_authenticated`
- `platform_unavailable`

状态变化：

- 本地切换到新平台：进入 `/platform/setup`。
- 本地切换到已有平台：进入 `/login`。
- 平台关闭：退出管理路由并回到本地工作台。
- 用户被禁用：撤销会话并进入登录页。
- 当前项目可见性被撤销：关闭项目内容并跳转“我的项目”。
- 平台数据库暂不可用：展示明确故障页，不自动退回本地模式。

登录、用户管理、项目管理、审计和平台设置分别建立自管理组合模块；页面层只负责编排和路由，遵循现有前端拆分规范。

## 11. 实施阶段与验证

全程采用测试先行方式。每一阶段先增加失败测试，再实现最小功能使测试通过。

### 阶段 1：平台数据库与运行模式

工作：

- 建立平台数据库模型、迁移和专用执行器。
- 增加本地/平台配置快照及动态切换服务。
- 固定数据库文件名 `workstep_platform.db`。

验证：

- 开启、关闭无需重启。
- 失败切换能原子回滚。
- 切换过程中健康检查保持响应。
- 平台数据库慢 SQL 或 SQLite 锁竞争不阻塞事件循环。

### 阶段 2：注册、登录和身份

工作：

- 首位管理员初始化。
- 注册、审核、登录、注销、禁用和会话恢复。
- 统一本地及平台操作者快照。

验证：

- 未登录无法进入平台业务页面。
- 禁用、过期和撤销会话立即失效。
- 用户名大小写、重复和路径字符校验正确。
- 本地模式继续使用本地用户名和设备 ID。

### 阶段 3：平台项目登记与目录策略

工作：

- 建立项目登记、所有者和可见用户关系。
- 普通用户受管项目创建。
- 管理员任意目录共享项目创建与注册。

验证：

- 普通用户无法控制物理路径。
- 项目只能落在自己的 `projects/{username}` 下。
- 管理员可以使用合法的任意本机目录。
- 目录穿越、符号链接逃逸、重复路径和危险根目录被拒绝。
- 取消注册不删除文件。

### 阶段 4：统一项目可见性

工作：

- 在项目解析和数据库执行入口接入可见性检查。
- 项目列表、REST、WebSocket、文件和搜索复用检查。

验证：

- 无权用户无法通过直接 `project_id`、WebSocket 订阅或文件地址访问项目。
- 用户只看见自己拥有或获分享的项目。
- 管理员可查看全部平台注册项目。
- 移除可见关系后，已有订阅立即停止接收项目事件。

### 阶段 5：消息作者完整性

工作：

- 扩充消息字段和迁移。
- 收拢任务消息与助手聊天消息持久化入口。
- 前端统一展示作者。

验证：

- 所有用户、助手、系统和定时消息的作者字段均非空。
- 平台消息记录登录用户名快照。
- 本地消息记录本地用户名快照。
- 后台回复能追溯原始发起人。
- 历史缺失作者显示“历史用户”，不被错误回填。

### 阶段 6：任务动作审计

工作：

- 建立统一审计服务。
- 接入任务生命周期、审核、定时器和项目成员变化。

验证：

- 启动、暂停、恢复、停止和取消均能查到操作者。
- 后台恢复和定时任务包含 `actor_type` 与原始发起人。
- 失败和拒绝操作也有结果记录。
- 审计元数据不包含敏感值。

### 阶段 7：认证和注册页面

工作：

- 实现初始化、注册、登录和等待审核页面。
- 增加路由守卫与登录后返回。

验证：

- 各平台状态跳转准确。
- 表单校验、焦点和加载状态符合规范。
- 注册关闭、待审核、禁用和数据库故障均有清晰页面。

### 阶段 8：管理中心

工作：

- 管理概览。
- 用户管理。
- 项目管理和管理员外部目录选择。
- 操作记录。
- 平台设置。

验证：

- 普通用户看不到且无法打开管理功能。
- 管理操作有确认、错误恢复和审计。
- 页面模块测试覆盖自己的状态、请求和校验。
- 大列表具备分页或服务端筛选，避免一次加载全部记录。

### 阶段 9：项目成员与现有功能回归

工作：

- 项目设置增加“成员”页签。
- 明确区分平台成员、公开任务分享和远程设备访问。
- 完成模式切换和权限变化的实时处理。

验证：

- 项目所有者能分享自己的项目。
- 管理员共享项目仅管理员能修改成员。
- 现有任务、画布、聊天、助手、计划任务、远程项目和公开分享无回归。
- i18n 所有词典键一致且非空。

## 12. 完成标准

- 平台模式可即时启停，无需重启。
- 平台主数据库始终为 `<平台根目录>/workstep_platform.db`。
- 普通用户项目只能创建在 `<平台根目录>/projects/{username}/`。
- 管理员共享项目可以使用任意通过安全校验的本机绝对目录。
- 项目默认私有，所有者可以分享，管理员可以管理全部项目可见用户。
- 用户不能通过项目 ID、WebSocket、搜索或文件接口看到无权项目。
- 本地模式和平台模式下，每条新消息都有明确作者用户名或系统身份。
- 所有助手和后台消息都能追溯原始发起人。
- 任务启动、暂停、恢复、停止和取消均有持久化操作者记录。
- 关闭平台模式不会删除平台数据或项目文件。
- 全部新增 Peewee 异步路径通过专用数据库执行器运行，并有事件循环非阻塞回归测试。
- 前端管理页面符合现有组件复用、弹框关闭保护、加载旋转和 i18n 规范。

## 13. 第一版暂不包含

- 组织、部门和用户组。
- `viewer/editor` 等项目细粒度角色。
- 单独的接口权限编排系统。
- 邮件注册验证和邮件找回密码。
- OAuth、LDAP、OIDC 等外部身份源。
- 用户磁盘或任务配额。
- 自动迁移不同平台根目录之间的数据。
- 自动移动管理员注册的外部项目目录。
