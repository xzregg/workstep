01 · Business boundary

先定边界，再谈增长

WorkStep 的优势是“本地、多引擎、可编排、可审核”。商业化不能破坏这些承诺，也不能引入需要 7×24 小时维护的云端执行系统。

必须坚持的产品边界

  • ✓模型由用户购买。
    BYOK 或复用 Claude Code、Codex 等现有订阅，WorkStep 不赚 Token 差价。
  • ✓执行发生在用户设备。
    平台只分发软件和工作流包，不接触代码、凭据和项目正文。
  • ✓源码继续免费。
    付费购买官方发行、更新权益、精品内容与分发便利，不人为阉割现有能力。
  • ✓支持异步化。
    公开文档、FAQ 和 GitHub Issue，不承诺一对一即时响应。
真正要优化的指标不是 ARR，而是：
净收入 ÷ 维护小时 拒绝企业定制、模型托管、强制联网和实时客服。

02 · Payment

具体怎么收钱

第一阶段不要自建收银台。使用 Merchant of Record（登记商户）托管结账，让服务商处理全球支付、销售税、VAT、欺诈和账单问题，你只接收付款成功事件并交付许可证。

首选 · MVP

Lemon Squeezy

适合个人软件与数字下载。公开标准费率为每笔 5% + $0.50，并提供许可证密钥、数字下载、一次性付款和订阅。

  • 售卖 WorkStep Personal / Supporter
  • 售卖你自己的工作流包
  • Hosted Checkout，无需保存银行卡数据
  • Webhook 驱动许可证发放
注册资格、提现方式和实际附加费用应在开户时重新核实。先申请通过，再开发支付集成。
备选 · 软件销售

Paddle

同样作为 Merchant of Record，官方说明会处理数字产品的 VAT、GST 和销售税；公开标准 Checkout 费率也是 5% + $0.50。

  • 适合一次性软件和订阅
  • 提供 API、Webhook 与托管结账
  • 全球税务和发票由平台承担
  • 许可证能力需由 WorkStep 自己实现
如果 Lemon Squeezy 审核、提现或地区支持不合适，再选择 Paddle，不要同时维护两套。
后期 · 自动分账

Stripe Connect

适合真正的多卖家市场，可把一笔付款拆分给平台和作者，并对卖家进行身份验证。但合规、退款和负余额责任显著提高。

  • 作者开户与 KYC
  • 平台抽成和自动转账
  • 退款、拒付和余额管理
  • 仅在主体与地区满足条件时采用
Stripe 官方列出的 Connect 分账支持地区不包含中国大陆。主体所在地与跨境付款方案必须先确认，不能把它作为 MVP 前提。

订单与许可证的最小数据

平台本地只需要保存：order_id、支付服务商、产品 ID、买家邮箱哈希、许可证状态、购买时间、更新截止时间和退款状态。不保存银行卡信息，也不把许可证设计成持续在线 DRM。退款后停止未来下载与更新；已经下载到本地的版本继续可用，这是低维护和本地优先之间的合理取舍。

04 · Workflow marketplace

市场卖的不是一份 JSON

本地执行意味着明文无法彻底隐藏。正确策略是让“正版包”持续更方便、更可信：完整资产、作者签名、兼容性测试、一键安装和版本更新共同构成价值。

code-review-pro.workstep-pack●●●
package/
├── manifest.json      # 作者、版本、权限
├── workflow.json      # DAG 定义
├── prompts/          # 分阶段 Prompt
├── skills/           # 配套 Skill
├── examples/         # 输入输出示例
├── docs/             # 使用说明
├── tests/            # 兼容性检查
└── signature.json     # 哈希与平台签名
平台数字签名确认作者和内容未被篡改，解决可信来源问题，不伪装成防复制。
购买与更新权益许可证控制下载和升级；本地包无需持续联网，也不绑定单台设备。
每单弱水印在包元数据中写入不可见购买编号，用于追查公开传播，不能承诺绝对防泄露。
安全权限清单早期只允许声明式 JSON、Prompt 和 Markdown；含代码的 Skill 后期单独审核。

邀请制市场的资金分配

为什么先人工结算

开放市场的自动分账需要卖家 KYC、税务资料、退款分摊、负余额和跨境付款。最初只有 5–10 位邀请作者时，每月生成一份销售报表并人工支付版税，成本远低于自建市场财务系统。交易额稳定后，再评估 Stripe Connect 或其他符合主体所在地的市场支付服务。

07 · Risk control

小团队最容易踩的坑

最危险的不是工作流被复制，而是市场还没有交易就提前承担支付、审核、客服和合规责任。

风险等级控制方式不做什么
工作流被复制传播中签名、购买权益、弱水印、更新服务与下架流程不承诺绝对 DRM，不绑定单设备
恶意 Skill 执行代码高早期只允许声明式包；权限清单、人工审核和沙箱验证不在免费目录直接执行任意脚本
税务、退款与拒付高官方商品使用 MoR；作者市场先邀请制与书面协议不自行保存卡数据，不私下混合收款
双边市场冷启动高先用官方工作流和免费目录形成买家，再邀请作者不先建设复杂卖家后台
客服吞噬开发时间中文档、FAQ、Issue 模板、兼容性测试、明确退款政策不承诺私聊和响应 SLA
支付平台或地区不可用中在编码前完成账户审核和小额真实收款/提现验证不把某个支付商写死进产品核心
