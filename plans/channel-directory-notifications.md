# 渠道通讯录与按姓名通知

状态：已实现本地代码与模拟协议测试；真实平台验收待完成。日期：2026-11-09。

## 目标与首版默认范围

用户可以说“用研发钉钉机器人提醒张三查看任务 A”，助手查询该机器人的可见联系人，解析发送身份，通过已有渠道发送服务发送。首版接入钉钉、企业微信和飞书，入口为助手工具与 CLI；设置页增加能力配置、目录状态与刷新操作。不新增任务页发送表单、定时提醒规则、任务事件订阅规则或全员广播。

默认采用本机独立目录，不依赖网关。以下是未收到选择回答后的推荐默认值，可在实施前调整：仅通讯录开关、企微独立通讯录凭证、助手/CLI 优先；通讯录仅在内存缓存，不持久化。

## 已核实的现状与平台边界

- `apps/daemon/services/channels/sender.py` 已支持 session_id 或 bot_id + user_id/group_id，复用项目范围、机器人启用与连接检查；原始通知不启动助手、不写聊天历史。
- `apps/daemon/api/channel_bots.py` 已有发送与机器人配置 API；tool_registry 与 CLI 已有渠道列表、会话列表和发送工具。
- `apps/web/src/components/BotSettingsEditor.tsx` 持有配置表单，目录配置应作为独立组合模块接入。
- gateway 的 identity_connectors 已有部门递归、成员读取与授权范围判断，可参考协议处理；其身份用于登录，尤其钉钉 unionid 不可直接当作机器人发送 userid，不让 daemon 导入 gateway 业务服务。
- 本机企微 SDK 的 send_message 明确说明单聊使用 userid；官方 SDK 说明主动发送无需回调帧：https://github.com/WecomTeam/aibot-node-sdk 。这不构成“任意目录成员必定可达”的保证。
- 企业微信官方通讯录页面本次无法读取。目录 ID 与机器人身份的适用范围、管理员创建方式及可能的加密 ID 转换仍需官方协议和真实测试验证；禁止从名字相同推导两种 ID 相同。

## 配置、目录与身份

支持通讯录能力的机器人仅增加 `directory_enabled`（读取通讯录），新旧机器人默认关闭；开启后才读取与查询企业目录。不新增主动发送开关，现有发送、回复和自动通知继续沿用已有接口与权限检查。目录关闭不阻止按已知 ID 发送，但禁止目录搜索和按姓名发送。

钉钉和飞书复用已有应用凭证，并在平台侧配置通讯录读取权限。企业微信增加独立的 corp_id、目录应用 secret 与用于权限范围检查的 agent_id；与 Bot ID/Secret 分开保存。设置页提示目录凭证和机器人必须属于同一企业，并记录管理员确认的关联；管理员确认不是自动验证成功。凭证仅通过现有配置存储保存，公开响应改用显式字段白名单，返回 has_directory_secret，禁止嵌套凭证泄漏。

新增独立 DirectoryService 和平台目录适配器，与消息长连接解耦。通讯录仅在内存缓存，按 bot_id + 企业/应用身份隔离，保存目录 ID、发送 ID（可空）、姓名、部门、有效状态、映射来源、同步时间；不写文件或数据库，不采集手机号、邮箱。机器人凭证与通讯录开关仍沿用现有配置存储。

机器人启用且通讯录开关开启、没有内存缓存时，异步获取一次；程序重启后重新获取。无 TTL，不定时刷新，不因搜索或发送请求外部通讯录。手动点击“更新通讯录”可重新获取，同一机器人合并并发请求。刷新覆盖授权范围及分页，按目录 ID 去重；完整成功后交换内存快照，同步期间继续使用旧快照，失败或部分结果不得覆盖它。明确撤权或更换企业/应用身份时禁用并清理旧映射，普通网络失败不视为撤权。查不到提示手动更新。关闭通讯录时取消同步并清理内存缓存；删除机器人同样清理。姓名与部门可变，ID 作为映射主键，不假定跨企业或应用通用。

目录身份与发送身份是不同字段。钉钉使用经过适配器确认的 userid，不使用 unionid。企微先验证同企业明文 userid 路径；有加密或不同身份域时，首版返回 identity_unverified，保留已有按已知 ID 发送路径，不自动切换成企业应用消息，也不按姓名拼接映射。企微完整按姓名通知只有真实平台身份与可达性验收通过后才声明支持。

## 统一通讯录能力与非阻塞边界

- 在渠道能力声明中增加 `directory`（默认不支持）；支持的渠道注册独立 `ChannelDirectoryProvider`。UI 和 API 读取能力声明，不用平台名称硬编码判断是否展示通讯录入口；能力存在不等于凭证和权限已就绪，运行状态单独返回。
- 最小协议为异步 `fetch_snapshot()`，返回联系人快照、授权范围标识、完整性和身份域。联系人统一包括 directory_id、display_name、departments、recipient_id、recipient_id_type、identity_status；平台只负责令牌、部门遍历、分页、协议错误及合法 ID 映射，不负责本地缓存或姓名选择。
- 统一 `ChannelDirectoryService` 持有内存快照、不可变内存索引、精确/模糊查询、重名候选、同步任务、并发去重及身份有效性；各提供者通过注册表发现，不让 BotManager 累积平台分支。发送仍使用 ChannelMessageSender，目录服务仅返回已解析的收件人，不另建发送体系。
- 刷新 API 立即返回任务状态（202），后台任务由服务统一持有并可取消；UI 只轮询本地状态，不因轮询重复请求厂商。退出时取消并回收任务、关闭 HTTP 连接；更改配置时使用代次标识丢弃旧任务结果，防止旧目录写回。
- 厂商 HTTP 使用复用的 httpx.AsyncClient/aiohttp，设置连接/读取/总任务超时、平台限流及有限重试。每机器人最多一个同步任务，全局最多两个同步；首版每个同步内顺序请求分页与部门，避免无界 gather。
- 网络响应 JSON 解码、索引构建和排序作为完整同步工作单元放入专用有界线程池（2 个工作线程）；搜索分页也在该执行器运行，事件循环仅接收有限结果和切换快照引用。不得把同步 SDK 包成 async 后直接调用。
- 不在等待网络时持有查询锁；更新只在完整快照构建成功后交换内存引用。项目数据库调用继续走 project_manager.run_db，不把 Peewee 对象或惰性查询带回事件循环。
- 验收增加慢网络、慢 JSON 处理、同时刷新多个机器人与高频搜索场景：同步进行时健康检查、WebSocket 心跳、已有聊天仍响应；搜索和发送连续调用不增加外部通讯录请求数；重启后每个启用目录重新拉取一次，目录数据无文件或数据库写入；旧代次同步不能覆盖新身份。

### 平台接口落点

| 渠道 | 通讯录读取 | 发送身份与接口 |
| --- | --- | --- |
| 钉钉 | `/topapi/v2/department/listsub` + `/topapi/v2/user/list`，按部门分页 | userid；复用现有 `/v1.0/robot/oToMessages/batchSend` |
| 企业微信 | `/cgi-bin/department/list` + `/cgi-bin/user/list`，需要企业应用通讯录凭证；仓库 gateway 已有调用 | 经验证可用的机器人 userid；复用 SDK send_message，不擅自转用应用消息 |
| 飞书 | `/open-apis/contact/v3/departments/:department_id/children` + `/open-apis/contact/v3/users/find_by_department`，遍历授权部门及分页 | 同一应用的 open_id；复用 `/open-apis/im/v1/messages?receive_id_type=open_id` |

接口可读取的目录受应用授权范围约束，目录可见不保证消息可达。飞书目录请求显式指定 user_id_type=open_id，与现有适配器保持一致；不得混用 user_id、union_id。Lark 可复用协议实现但域名与身份隔离，未完成独立验收不宣称已支持。

## 查询、发送接口与交互

- 增加 `GET /api/channel-bots/{bot_id}/contacts?project_id=...&query=...&cursor=...`，返回匹配联系人、目录状态及分页信息。每项包括稳定 contact_id、姓名、部门、可发送状态；仅返回与请求有关的联系人，不把整份目录塞进助手上下文。
- 增加 `POST /api/channel-bots/{bot_id}/directory/refresh` 和目录状态查询，属于设备设置权限；普通项目工具仅允许查询该机器人默认项目内联系人。复用发送服务的项目归属规则，群绑定不额外赋予该项目整个企业目录访问权。
- 扩展既有发送 API，支持 bot_id + contact_id 或 bot_id + user_name，和原 session_id/user_id/group_id 互斥。按名字发送只接受完整、有效目录中的唯一精确姓名匹配；模糊结果仅供候选选择。使用 contact_id 时重新检查归属、状态、开关及映射，不信任客户端提交的姓名或发送 ID。
- 注册 workstep_search_channel_contacts；扩展 workstep_send_channel_message。CLI 增加 channel contacts --project ... --bot ... --query ...，send 增加 --user-name 和 --contact，复用同一工具注册与后端服务。
- 重名返回 ambiguous_recipient 及姓名/部门候选，由助手使用现有选择交互让用户决定；未找到返回 recipient_not_found；缺权限、目录未完成和身份未验证分别返回可操作错误。机器人名称也必须唯一解析，不能任选一个。
- 用户明确要求发送且目标唯一时直接执行，不重复要求确认。只要求“查找联系人”时不发送。提醒正文仅包含用户要求的任务信息；不能自动创建公开分享链接或把 localhost 地址当作收件人可访问链接。
- 发送前解析为平台收件人，然后调用现有 ChannelMessageSender，不复制媒体处理和平台发送实现。返回平台接受、失败或结果未知；平台接受不表述为已读/必达。发送请求超时不自动重试，避免重复通知；目录读取可有有限退避重试。

设置模块展示开关、凭证、最后成功同步时间、人数、权限错误与手动刷新。刷新时持续旋转图标，离开有改动时复用 ConfirmDialog，新增文案与全部语言键保持一致；不在现有页面层堆积独立状态。

## 实施顺序与验收

1. 先补失败测试：目录唯一/重名/空结果、分页与子部门、部分授权、同步失败、身份域不匹配、跨机器人/跨项目隔离、关闭能力及旧配置兼容。
2. 实现目录服务、平台适配器、缓存和配置字段；随后接 API、工具、CLI 与既有发送服务集成，再接设置 UI。
3. 覆盖真实 API 与助手工具调用：唯一姓名成功；重名零发送并可选候选后发送；目录关闭后姓名查询不可用，按 ID 发送仍按既有权限工作；凭证不出现在公开响应或日志中，通讯录只经受控查询接口返回且不落盘。
4. 使用慢 HTTP、慢 JSON/索引处理、慢 SQL/锁竞争与健康检查 canary 验证事件循环响应；查询并发不重复全量拉取。回归既有渠道回复、卡片、任务广播、完成转发、计划通知和附件发送。
5. 前端测试配置保存、密钥留空保留、状态/错误/刷新、关闭保护和 i18n；运行相关 daemon 测试、Web 测试与构建。仅修改计划阶段不运行实现测试、不启动应用。
6. 真实平台验收使用明确授权的测试账号：钉钉、企微和飞书分别验证有/无历史对话的收件人、同名成员、权限不足、不可达成员与 ID 类型。没有测试凭证时记录缺口，企微未验证身份路径保持不可发送，不能用模拟测试宣称全部打通。
7. 实施时同步 docs/code-map.md、渠道协议及技术配置文档；操作手册、翻译、演示截图和 manual:check 留到本批合并交付节点按 AGENTS.md 执行。


## 本批实现结果

- 已接入统一 provider、内存目录服务、生命周期、API、工具、CLI 与机器人编辑页独立目录模块。
- 新机器人先保存再编辑通讯录；配置与基本机器人表单分别保存，未保存状态参与页面关闭保护。
- 企微目录读取已实现；已观察到的同机器人 sender_id 与目录 ID 完全一致时允许发送，其余身份拒绝目录目标发送。真实平台身份转换不作猜测，继续保留已知 ID/会话发送。
- 目录密钥明确排除在公开机器人响应之外；未改造整个历史机器人配置的公开字段机制。
- 本批只实现目录关联的发送解析，不改动既有通知发送策略。Lark 未启用目录能力。


企微身份补充：仅在同一机器人实际收到成员消息、且其 sender_id 与目录 contact_id 完全一致时，内存服务将该联系人标记为可发送。相同姓名不作为映射依据；加密 ID/不同 ID 不自动转换。观察到的身份仅保留内存，重启或身份变更后需重新验证。


本地验证：目录服务/API/身份验证、平台 MockTransport、CLI、已有渠道发送/协议/机器人/飞书及任务与会话通知回归已通过；包含慢网络与慢索引处理健康检查。Web 目录模块、机器人设置、语言键测试通过，TypeScript 与生产构建通过。未启动用户应用、未发送真实平台消息；企业权限配置、企微加密身份转换和平台可达性仍需授权测试账号验收。
