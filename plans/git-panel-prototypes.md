# Git 管理面板交互原型

日期：2026-09-21。状态：A/B 已制作；根据反馈增加 C 融合方案并设为默认入口。

## 打开

在 `apps/web` 执行 `yarn dev` 后，打开开发服务的以下路径；本次复用了已有的 5173 服务，未另起进程。

- C（当前推荐）：<http://localhost:5173/prototype/git?variant=C>
- A：<http://localhost:5173/prototype/git?variant=A>
- B：<http://localhost:5173/prototype/git?variant=B>

开发环境左侧「统计」下方增加「Git 原型」入口。底部切换条可随时切换 A/B/C；输入框及弹窗外可用左右方向键切换。正式构建不会包含原型入口或页面。

## 当前融合方案 C

- 仓库树和提交区域常驻，提交说明直接显示在页面右侧；只有点文件时打开代码对比弹窗。
- 顶部「切换分支」在页面内展开分支列表。点击树里的分支只是浏览；点击「切换到此分支」才模拟检出。
- 当前分支显示标记；已被其他 Worktree 占用的分支显示「定位工作目录」，不对该分支重复检出。
- 原型采用保守切换规则：有修改时先提交，不提供丢弃或自动 stash。可选择干净的 `fix/chat-scroll` 工作目录，切换到 `develop` 或 `release/0.9` 体验成功路径。
- 成功后更新当前分支、仓库树与未检出分支列表，工作目录路径不变；仍为纯模拟，不执行 Git。

## 对比方向

- A：常驻仓库树、文件列表和代码差异，适合连续审阅。仓库列和文件列右下角可拖动宽度。
- B：侧栏仓库树保留工作区上下文；点击工作目录打开提交弹窗，再点击文件进入更大的差异窗口；返回后保留草稿与暂存状态。弹窗右下角可调整大小。
- 两套沿用 WorkStep 的视觉变量及图标，复用相同文件面板、差异面板和模拟工作目录状态。

## 体验流程

1. 选择 `workstep / feat/git-panel`，查看项目目录外的 Worktree 路径。
2. 点击 `task_runner.py`，查看两处函数修改；用函数下拉框或上下按钮跳转。
3. 点击代码旁的「陈予 · 09/18」，查看上次修改人的提交摘要。未提交行没有历史作者。
4. 点击文件旁的 `+` 暂存，填写提交说明，执行模拟提交。
5. 查看提交历史中的新记录，切换到 `main` 验证其文件状态独立。
6. 选择 `fix/chat-scroll` 查看干净工作目录；选择 `develop` 查看未检出分支的历史与差异。
7. 切换 A/B 比较常驻审阅与弹窗审阅；搜索支持仓库、分支和路径。

## 范围

数据、代码片段、作者和历史全部为演示内容。不会读取或写入实际 Git 仓库。刷新页面恢复初始数据；切换方案保留当前内存状态。代码在 `apps/web/src/pages/prototype/`，尚未选定正式方案，不合并为生产实现。
