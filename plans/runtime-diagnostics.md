# WorkStep 运行诊断

状态：三端已接入，保留安卓真机与 USB 调试验收。

## 入口

| 平台 | 入口 | 日志来源 |
| --- | --- | --- |
| 浏览器 | 设置 → 反馈问题 → 运行诊断 | 页面异常、失败和慢请求 |
| 桌面包 | 帮助菜单、托盘、后台启动失败页 → 运行诊断 | 页面、Electron、内置后台及沙箱 |
| 安卓包 | 悬浮球长按菜单、连接失败页 → 运行诊断 | WebView、安卓主进程、通知进程及崩溃记录 |

浏览器在现有 `ProblemFeedbackSettings` 中增加「运行诊断」按钮，放在一键反馈下方。点击打开自管理的诊断面板，无需开启调试模式。三个平台共用「日志」「性能」两个页签的交互规则。桌面和安卓的本地入口在后台或网页不可用时仍可查看已有日志。

## 日志与录制

- 复用 `browserDiagnostics`、桌面 `diagnostics.cjs` 和安卓 `CrashReports`。日志按时间、来源、级别和关键词筛选，支持展开详情和复制附近记录。本地文件异步、有界读取。安卓显示远端后台日志不可用，首版无需新增服务端日志接口。
- 复用安卓现有采样逻辑，提取三端共用的页面采集器。默认录制 15 秒，支持提前停止。开始录制后回到原页面复现；设置页卸载不结束录制，离开当前文档或转入后台则结束并释放监听。记录帧间隔、输入延迟、长任务、慢请求及可用的星图绘制指标。运行环境缺少的指标显示为不可用。
- 为消息链路增加仅在录制期间生效的测量点。从发送到首个流式片段、首个片段到页面首段提交分别计时。Markdown Worker 分开记录排队和解析耗时，同时记录流式提交频率、历史消息首屏提交和自动跟随滚动。使用相对录制起点的时间戳；点选性能事件可跳到对应时段的日志。
- 三端提供摘要复制和带版本的 JSON 导出，包含构建版本、环境信息、录制结果及附近日志，上限 2 MiB，标记截断。按白名单采集，报告排除消息正文、凭据、请求头、请求体及完整 URL。导出和分享由用户主动触发。

## 深入调试

- 桌面通过本地帮助菜单为受信工作台窗口打开开发者工具。安卓调试包可通过 USB 使用 Chrome DevTools，正式 APK 关闭 WebView 调试。原生线程调度用 Android Studio 或 Perfetto 分析。
- 在支持性能分析的调试构建中，用 React Profiler 检查消息列表、流式消息和富文本的更新次数与渲染耗时。

## 验收

- 先写定向回归，覆盖长任务和慢请求区分、Markdown 排队和解析区分、录制中断、日志轮转、慢盘、导出截断、敏感字段过滤和桥接来源校验。
- 在真实聊天页面复现长回复期间的输入卡顿，验证能从卡顿时刻找到相应的消息阶段和附近日志。复用现有流式响应脚本，并在安卓真机上复测。
- 更新 Code Map 和使用说明，编译 Web、桌面包和安卓包。检查浏览器「反馈问题」入口及 320、390、1023、1024、1440px 布局，验证桌面安装包离线日志、安卓真机录制和调试包 USB 检查。
