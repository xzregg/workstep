# 动态语言包方案（待实现）

> 最新入口调整：取消独立语言中心。语言作为外观的分区，并在皮肤中心同一个普通对话中制作；右侧用“样式 / 字体 / 语言”切换。皮肤包与语言包独立保存，应用时分别选择。交互参考 `prototypes/skin-center-v2.html`。校验与动态加载方案保持独立，界面复用皮肤中心。

本方案基于当前 feature/custom-skins：语言位于系统设置，外观一级页持有字体与皮肤。最新交互原型 `prototypes/skin-center-v2.html` 使用示例数据，没有连接 AI、安装文件或修改真实偏好。已有应用仍只有 zh-CN、zh-TW、en-US、ja-JP 四种编译内置语言。

## 产品与入口

设置的「外观」集中呈现皮肤、字体与语言。字体类型、文字大小与语言选择集中放在皮肤卡片上方；字号沿用既有“小／标准／大／特大”分段 Tab，聊天编辑栏的字体分区使用同样控件。语言选择器列出四种内置语言与已安装语言包；不增加独立语言中心。皮肤中心保留全部皮肤／我的皮肤卡片，导入 ZIP 与 Tab 同行，使用中由卡片标识。点「聊聊怎么改」打开普通对话与右侧编辑栏，右侧分为样式／字体／语言；手机用聊天／编辑与预览 Tab，保存放顶部。语言分区提供草稿、覆盖率、缺失项、翻译校验和预览。保存后选择要应用的皮肤与字体、语言包，安装不自动应用。

皮肤与语言独立保存、独立安装。同一皮肤可搭配任意语言；不翻译历史消息、用户文件、工具输出、模型消息，也不设置模型回复语言。界面翻译只使用应用注册的文案键。

内置语言不可被覆盖、删除；自定义语言包可更新、卸载。卸载当前语言前明确提示回到其内置回退语言。同一语言可有多个包版本，但设备选择的是稳定包 ID 与不可变版本快照。一个语言标识只有一个默认候选；同语言的多套术语通过不同 package ID 区分，不静默替换别人的包。

## Runtime 与对话

继续使用既有固定「默认工作区」项目 `$WORKSTEP_CONFIG_DIR/runtime/workspace`，不为语言制作创建新项目或自动生成类型目录。用户明确制作后可在根目录创建 `es-ES/` 等任意包目录；已安装技能库与 SDK 安装目录不改变。

复用普通 ChatPage、ChatInput、流式消息、停止、引擎选择、附件与工具审批，不注册新助手。安装 CLI 扩展命令和语言规范作为工作区上下文。在皮肤制作对话中添加语言时，直接沿用当前普通会话，不创建新的助手或会话；技能和引擎制作仍保留各自已有会话。登记稳定制作会话 ID 与皮肤、语言草稿路径，重复打开复用，支持历史选择，不覆盖未发送草稿。一个会话可关联多个包草稿，调整目标须明确，避免调整西班牙语时读到法语草稿。

对话完成一轮后后台校验并读取草稿快照，刷新右侧覆盖率与预览；手动修改名称、回退语言、术语等须持久化后再发送下一轮。运行时禁用冲突编辑，关闭有修改时复用 ConfirmDialog。会话历史正常落在项目 chat_sessions / chat_messages；预览和未确认方案不能写成已安装语言。

## 包规范 v1

包为目录或 ZIP：`manifest.json`、`messages.json`，可选 `glossary.json`。禁止 JavaScript、HTML、CSS、可执行文件或远程资源。安装只读取声明式字符串，不执行包内容。

```json
{
  "schema_version": 1,
  "id": "community-es-es",
  "locale": "es-ES",
  "name": "西班牙语",
  "native_name": "Español",
  "version": "1.0.0",
  "fallback_locale": "en-US",
  "direction": "ltr",
  "catalog_revision": "<文案目录哈希>",
  "description": "简洁自然的西班牙语界面"
}
```

`messages.json` 使用拍平点分键，如 `nav.settings`；value 只允许非空文本。`glossary.json` 描述译词约定，供模型参考，不直接参与渲染。规范自动从 zh-CN 词典提取键、原文、占位符、模块、关键提示标识，不能人工维护第二份键清单。覆盖统计以实际原文目录为准，原型数字仅为示例。

第一版只支持从左到右的语言。包必须如实声明 ltr；rtl 先明确拒绝并提示不支持，不能只给页面设置 dir 就宣称阿拉伯语等完整适配。完整 RTL 是后续独立任务，需要导航、画布、拖动、图标方向与输入区实测。

## 校验与发布边界

安装阻断项：非法标识或包 ID、内置 ID 碰撞、JSON 结构错误、原型污染键、非字符串、未登记键、占位符缺失／新增／不匹配、任意代码资源、路径越界、ZIP 路径穿越／链接、超量文件／解压量、审批与权限等核心安全提示缺失。核心提示集由应用明确维护，新增提示按职责标记，不靠猜测 key 名。

允许缺失普通文案；以覆盖率与完整缺失清单告知用户，缺失时回退。文案过长、看起来仍是原文、术语不一致仅告警，不伪装成翻译质量认证。审批用词不能改动作或权限值，授权行为继续由业务模块负责。重复同一占位符的次数也须一致；Markdown 文案保留必要结构，但不能注入 HTML 或链接到未经允许的动态资源。

安装必须生成不可变快照并原子更新索引。草稿更改、安装和卸载执行已有宿主包管理权限；项目绑定分享会话只可读取允许的已安装语言并选用，不能读取 Runtime 草稿、上传或发布宿主包。沿用 existing require_catalog_project 与具体 managed capability，新增能力须明确登记，不能复用纯外观读取授权放行写操作。

所有文件 I/O 在线程执行，Peewee 会话映射通过 project_manager.run_db。更新使用 expected_revision；冲突 409，保留用户草稿并提供重新读取／比较，不最后写入者覆盖。

## 动态加载与兼容

保留四种内置词典作为无需后台的兜底。Locale 从固定四值联合类型改为经过校验的运行时语言标识；TKey 仍由 zh-CN 推导，以保持编译期键检查。createT 支持拍平运行时词典，查找顺序是所选包 → 指定内置回退词典 → zh-CN → key。fallback 只允许内置语言，禁止循环依赖。

切换前下载目标不可变快照、校验内容和资源边界，加载成功后一次性切换 store；失败保留原语言并允许重试，不能显示“已切换”却仍用旧词典。缓存至少保留当前包与四内置词典；缓存损坏直接回退，离线启动可用已缓存版本。偏好使用与皮肤类似的 origin＋网关设备路径作用域；迁移旧 workstep.locale 保留用户已有选择，不同步到所有设备。

React 组件与非 React 工具层必须审计：部分工具现在固定使用 zhCNT，动态 UI 不能仅修改 Provider 就声称全量翻译。日期格式要映射到包 locale，未知 Intl 支持时安全回退。第三方控件语言资源必须明确支持范围，不支持的保留内置文本并纳入覆盖说明。跨版本新增键会自然回退，安装界面提示目录版本差异；应用版本元数据不被包伪造。

安全恢复入口：URL `?language=default` 回到内置默认；固定预览确认／取消控件使用内置可信文案，防止坏翻译让用户无法恢复。皮肤中心的语言分区在安装成功后只打开隔离预览，不直接改变真实应用语言。

## API 与 CLI 草案

- GET /api/language-packs：列出已安装包与内置候选（项目范围读取）。
- GET /api/language-packs/{id}：manifest、不可变 revision、覆盖摘要。
- GET /api/language-packs/{id}/revisions/{revision}：受限已安装词典。
- GET /api/language-packs/contract：规范与当前文案目录。
- POST /api/language-packs/onboarding：绑定当前皮肤制作会话与语言草稿；没有现有会话时才获得／恢复默认工作区普通制作会话。
- POST /api/language-packs/validate、/draft、/register、/import：宿主校验／保存／原子安装／导入。
- GET /api/language-packs/{id}/export 与 DELETE /api/language-packs/{id}：宿主管理，内置语言拒绝。
- `workstep language contract|validate|register|list|export|import|remove`；CLI、工具和 UI 调用同一服务，register 默认不覆盖，更新须 --replace。

第一版可以复用皮肤不可变快照／ZIP 防护的共性辅助方法，保留语言自己的校验与索引；不复制整套会话运行时，也不为了此任务重写所有包管理。

## 涉及改动与实施顺序

1. 规范／服务：自动生成文案目录、包校验、索引与不可变快照、API 和宿主权限边界。
2. 前端加载：i18n registry／Provider、运行时 locale store、旧偏好迁移、缓存和失败恢复；审计日期与固定 zhCNT 调用。
3. 皮肤中心扩展：外观内语言选择、制作编辑栏语言分区、当前会话绑定、缺失项报告、术语与隔离预览、移动端 Tab；不增加独立中心。
4. Runtime／CLI：会话映射、草稿路径上下文、语言 CLI 与 workstep-cli 参考文档。
5. 行为验收：真实模型在 Runtime 生成一个第五语言包，校验、导入、安装、预览、应用、重启恢复与卸载回退；无真实生成验收前不能宣称聊天制作已完成。

预计涉及约 20–30 个新增或修改文件（含测试和文档），具体规模取决于固定 zhCNT 与第三方控件审计结果；这是初步范围估计，不是已完成清单。先做 ltr、自定义文案、不自动联网翻译；术语编辑可先通过普通对话实现。后续再考虑完整 RTL、多版本差异翻译、共享语言包目录。

## 必须覆盖的测试

真实 API 权限隔离、遍历 ZIP、恶意字典、占位符计数、内置不可覆盖、损坏缓存、加载失败保留旧语言、普通缺失回退、关键提示缺失阻断、旧偏好迁移、重复点击不建新会话、草稿冲突、会话隔离、停止和错误恢复。慢盘与慢 SQL 配合 health canary，证明事件循环可响应。
