# WorkStep 可选快速决策增强：Jev / Laya 场景规划

状态：场景规划，尚未接入。本文扩大此前仅面向协调助手资料推荐的方案范围。

## 定位

建立由 WorkStep 各模块共用的快速决策服务，用于有限候选选择、相关性排序、简单条件判断及按量表评分。支持 WorkStep 托管本地 Laya、用户配置的本地 Jev 兼容服务，以及远程 Jev 兼容服务；分别验证实际支持的协议能力和效果，不能将兼容接口等同于相同判断质量。本地 Laya 不等同于官方 Jev 模型。

沿用现有生成模型及 fast_model 配置。文本生成、摘要、需求编写、代码编写及 JSON 修复继续交给生成模型。确定性条件先用代码处理，模型只补充语义判断。

## 候选场景与优先级

| 阶段 | 场景 | 输入与决策 | 接入效果 | 不可用时 |
| --- | --- | --- | --- | --- |
| 优先验证 | 技能推荐 | 用户问题与已启用技能简介；选择、排序 | 普通聊天、任务和助手得到建议优先使用的技能 | 原有技能列表及引擎自主选择照常工作 |
| 优先验证 | 流程推荐 | 需求与当前可用流程简介；候选选择 | 新建任务、定时任务草稿得到推荐流程 | 原有人工选择或主模型选流程 |
| 优先验证 | 搜索结果重排 | 查询与已召回的任务标题、描述；相关性评分 | 增加相关结果视图，帮助查找历史任务和类似问题 | 原搜索及原排序 |
| 后续验证 | 上下文推荐 | 用户问题与允许访问的产物、历史经验摘要；相关性排序 | 对话和任务获得优先查看建议 | 原完整索引与现有上下文策略 |
| 后续验证 | 输入类型与缺项提示 | 当前输入；分类为咨询、需求、故障、补充等，判断是否缺目标或验收条件 | 推荐下一步入口或提示主模型重点补问 | 按现有对话处理 |
| 后续验证 | 重复任务提示 | 新需求与召回的历史任务；是否可能重复 | 创建前展示相似任务，不自动拒绝创建 | 正常创建流程 |
| 后续验证 | 经验候选整理 | 已抽取的经验候选与已有经验摘要；相关性、相似性及可复用性 | 为归档提供分类、重复和保留建议 | 原归档助手流程 |
| 实验 | 角色与专家团推荐 | 需求与用户可用的角色、专家团目录；候选选择 | 在已有选择入口推荐合适角色，由用户采用 | 保持原角色绑定和选择方式 |
| 实验 | 失败类型归类 | 有界错误片段；网络、认证、依赖、测试、资源等固定分类 | 在诊断入口提供分类标签和对应帮助入口 | 保留原错误信息及原处理 |
| 实验 | 通知重要程度标签 | 已生成通知及事件信息；重要程度评分 | 增加标签或在可选摘要中排序，不丢弃通知 | 原通知发送及顺序 |

技能推荐先提示优先使用的技能，不修改用户启用名单、权限及完整技能可见性。流程推荐不覆盖用户已经明确选择的流程，不改变自动启动与审核设置。搜索重排只在原权限范围内进行，不额外扩大跨项目读取范围。

## 首批建议

先接统一服务与离线评估，再按“技能推荐 → 流程推荐 → 搜索重排”逐项交付；这是验证顺序，不是同时上线全部功能。

- 技能推荐：现有技能中心与运行时投影提供候选来源。推荐在 WorkStep 发往引擎的提示中附加简短建议，不能假设能够控制外部 CLI 引擎内部每轮工具选择。
- 流程推荐：复用任务草稿现有 candidate_workflows 和允许流程校验；只增加建议，不跳过原结构化结果校验。
- 搜索重排：现有 task_search 主要按标题、描述包含匹配召回，再按更新时间排序。先在有界候选上验证重排；它不能独立解决关键词未命中的语义召回。完整语义搜索另行规划召回索引。相关性模式按有界候选集合排序后分页，不能只重排当前页并声称全局相关性排序；默认更新时间视图保持原行为，相关性视图说明候选范围。

相关入口：services/skill_runtime.py、agent_assistants/task_draft.py、services/task_search.py。

## 配置与公共服务

供应商中心新增 TypeSafe Jev、自定义 Jev 兼容服务及独立 systemone 协议；决策供应商不混入生成模型选择列表。外部服务可配置本地或远程地址、模型名称及可选认证信息，连接测试使用最小真实决策请求，不依赖生成模型的 /models 路径。

设置增加全局“快速决策增强”：总开关、运行方式、供应商或本地模型，以及每个已交付场景的独立开关。全部默认关闭；未交付场景不展示可用开关。用户只配置一次，各业务模块复用同一决策接口与故障隔离逻辑；本地托管走进程管道，外部服务走异步 HTTP，不为每个助手各造一套。

服务接收已授权的有限候选和有界文本，返回候选 ID、排序或分类以及应用/跳过原因。验证候选归属、响应结构、分数范围；不允许模型增加候选 ID、权限或操作。不同后端分别评估，置信分数不能直接作为统一正确率阈值。

### 本地托管与用户主动下载（2026-11-10 确认）

- 桌面包不携带模型权重、分词器以及本功能专用推理运行库；只分发必要的管理与通信代码。不得因新增此功能删除其他功能必需的运行依赖。
- 设置提供“下载运行组件”和“下载模型”两个明确入口，展示平台、版本、下载大小及进度，支持取消、失败重试和删除。推理依赖安装到 WorkStep 专用隔离目录，不修改系统 Python 或 daemon 的运行环境。
- 所有下载、安装和资源更新都必须由用户点击对应操作触发。应用启动、打开设置、开启增强、测试或首次推理都不隐式下载依赖或模型；缺失时展示待下载项目，原功能继续工作。
- 下载完成校验版本与摘要后才标记可用；失败或取消留下的未完成资源不得进入推理。模型与推理运行组件保存在 WorkStep 用户数据目录，应用升级保留。
- WorkStep 管理内部推理子进程，通过标准输入输出管道通信，不监听 HTTP 端口。组件和模型齐备且功能开启后按需加载、预热，就绪后参与增强；支持关闭、空闲回收、异常退出隔离及受控恢复。
- 模型和依赖分别显示安装状态；运行状态显示未就绪、加载中、就绪及异常。下载、加载与预热不占用用户前台请求的 300 ms 预算，未就绪期间直接跳过增强。

### 用户配置的本地或远程服务

- 本地 HTTP 服务可填写如 http://127.0.0.1:6000，模型可填写 multilingual；这些是外部服务配置示例，不是 WorkStep 托管进程的地址。
- 所有 HTTP 地址由 daemon 所在机器访问，界面说明 localhost 指向 daemon 所在机器。外部服务方式不要求下载本地模型或推理组件，WorkStep 不负责启动或停止该服务。
- 远程供应商只在用户明确选择后接收场景所需数据；本地托管、本地 HTTP 和远程服务之间均不自动切换。更改运行方式不自动删除已有下载资源。

## 故障回退与验证

- 未启用或无有效配置时不发请求；已启用的前台增强总预算 300 ms，包含等待与请求。没有候选时直接跳过。
- 每供应商最多两个并发，没有空位立即跳过；本轮不重试。连续失败三次暂停 60 秒，到期单次探测。用户取消必须传播，不得吞掉取消后继续主流程。
- 超时、断网、鉴权失败或无效响应时走原行为。只处理当前回合的决策结果，不让迟到结果覆盖已采用配置或其他会话。
- 后台经验整理和通知分类若未来启用，单独设定有界预算，不直接套用前台 300 ms，也不阻塞原通知交付。
- 开启与关闭做对照：技能/流程的前几项命中率、搜索相关性、误推荐率、主模型调用及 token 变化、端到端耗时、300 ms 内成功率、回退率。单次短请求压测不能证明大候选或长上下文仍符合预算。
- 覆盖权限与会话隔离、原始候选仍可访问、显式选择不被覆盖、慢网络健康检查、熔断恢复和停止取消。效果不足的场景继续关闭，不宣称已节省 token 或提高正确率。
- 验证首次启动、打开设置、开启增强、测试及首次请求均不会隐式下载；只有用户点击下载才获取相应资源。覆盖下载取消、校验失败、依赖缺失、加载失败及子进程退出时原功能正常。
- 验证三种运行方式独立可用：本地托管不监听端口，外部 HTTP 不安装本地资源，切换方式不删除资源或自动回退到另一后端。桌面打包检查模型及推理组件未混入发布包。

## 不建议交由快速决策直接控制

代码或方案的最终正确性、人工审核通过/拒绝、权限与工具授权、自动执行或重试、工作流跳步，以及重写/删除记忆。这些能力可以参考语义标签，但最终动作沿用已有验证与授权链路。引擎和主模型自动切换暂不接入，避免成本、能力与会话恢复语义发生隐式变化。
