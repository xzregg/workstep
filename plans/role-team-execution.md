# 角色与专家团执行方案

日期：2026-10-15。状态：原始研究方案，已被后续简化需求取代。

2026-10-17 更新：本次仅实现普通本机对话的「＋ → 面具／角色与专家团」选择、会话引用保存和按引擎会话／提示词摘要增量注入。专家团将多个角色与分工展开为当前模型的提示词，不建立独立专家会话，不实现调度；任务步骤不在本批范围。已实现行为及代码入口以 `docs/role-center.md` 和 `docs/code-map.md` 为准。下文保留为历史研究，不作为本次实现规范。

## 1. 产品结论

采用「角色定义专业身份，专家团定义协作，工作流定义业务步骤」的分层方式。

- 角色是可复用的提示词资产，不绑定引擎、账号或模型。
- 单角色用于当前执行者的专业身份。
- 专家团的成员分别拥有独立执行会话，由 daemon 调度和交接，最后统一汇总。
- 工作流可以把一个专家团作为某个步骤的执行方式；复杂分支继续在画布中表达。
- 选择与使用由用户明确触发。第一版不根据聊天正文自动召唤、增加成员或扩大任务。

本方案取代先前「把所有专家提示词拼到同一个模型请求」的专家团执行建议。单模型加载专业提示词适合单角色；专家团需要独立成员结果、执行状态和失败恢复。

## 3. 入口与触发

### 聊天

- 输入框增加面具按钮，打开角色／专家团共用选择器。
- 现有 `/` 菜单增加「角色」「专家团」两项，选中后打开同一选择器；命令由前端消费，不传给引擎。不要求用户记住资产名称或 ID。
- 选择器提供分类、搜索、最近使用、角色简介及提示词预览；团队预览包含成员、顺序、分工和团级约定。
- 每个会话同时选择一个角色或一个专家团，也可以选择「普通执行」。不允许在输入框叠加多个团队；多人组合在角色中心保存为专家团。
- 选中身份持续显示为输入框标签，后续消息沿用，直到主动切换或移除。选择本身不启动执行，发送消息才启动。
- 普通文字 `it` 不作为触发词；`@` 保持现有步骤寻址语义。
- 身份选择随会话持久化；最近使用只保存资产引用，不复制提示词。

### 角色中心

- 卡片保留点击编辑，增加明确的「用于对话」操作。
- 点击后选择有聊天写权限的本机项目，默认当前项目；新建带该身份的普通会话，不自动发送消息，也不覆盖正在编辑的对话。

### 工作流与任务步骤

- LLM 步骤配置增加「执行身份」：普通执行／角色／专家团。任务派发等非 LLM 节点不显示。
- 流程保存默认引用；单个任务步骤可继承、覆盖，或明确清除为普通执行。
- 运行中的步骤禁止修改身份。角色只作用于当前执行步骤，不自动应用到协调助手或独立审核节点。
- 模板保留引用。导入到缺少对应资产的设备时显示失效引用并阻止启动，不自动联网安装。

## 4. 执行语义

### 单角色

角色提示词作为专业身份指令接入现有提示词通道，保留项目规则、引擎权限、步骤输入输出契约和本轮目标。角色文本不构成额外权限授权。

身份切换、移除，以及同一角色内容版本更新，都在下一次发送前通过现有上下文交接机制建立新的引擎会话，携带任务事实、成果与待办，清除旧身份配置。UI 保留连续聊天及身份切换记录；不承诺消除历史内容对模型的全部影响。无历史时直接创建会话。

### 专家团：第一版为顺序协作

执行链：用户任务 → 按配置顺序执行每位专家 → 主会话统一汇总。

- 成员顺序是实际调度顺序，团级提示词补充目标、交接和汇总方法。提示词写了不同顺序时不改变调度；编辑器提示「执行顺序以成员排序为准」。
- 成员提示词由项目约束、团级约定、自己的角色提示词、自己的分工、本轮目标和前序成果组成。不把其他成员的完整角色提示词交给该成员。
- 分工为空时，默认按该角色专长完成本轮任务中相关的部分，并明确产出结论、依据和后续建议。
- 每位专家分别调用当前选定引擎，拥有独立引擎会话；成员与汇总默认继承本轮引擎、模型及权限配置。第一版不提供成员级模型覆盖。
- 前序成果通过项目数据目录中的运行成果文件交接，正文包含有界摘要及引用；原文超限不静默截断。引擎不能读取成果引用时使用有界正文，仍超限则停止并明确提示。
- 汇总由父会话执行，使用原始任务、团级约定和全部成员成果，不加载全部角色正文；保留分歧、失败和未验证事项，不把成员意见全部表述成共识。
- 第一版不额外配置主持人角色：父会话承担汇总，daemon 承担确定性调度。
- 追问启动新一轮执行，携带上一轮最终汇总和本轮要求；成员每轮新建会话，避免不断累积交叉身份。历史成员输出仍可查看。
- 第一版不开放团队间递归、成员自由通信和自由辩论。专家执行适配层不得提供 WorkStep 递归召唤入口；引擎内部原生子代理不计作可展示的专家团成员。

### 与现有工作流的关系

专家团在外层表现为一个步骤，成员输出属于步骤过程，最终汇总作为步骤输出接受原有端口及审核校验。全部成员和汇总成功后，该步骤才成功。

需要条件、循环、明确依赖边、多个独立审核或复杂输入输出时，使用现有画布，不在专家团编辑器再实现一套工作流。

## 5. 运行体验与失败处理

- 每轮团队显示一张运行卡片：团队名称、成员顺序、当前执行者、状态、耗时。展开可查看成员输出、工具过程和实际输入；最终汇总使用现有聊天消息组件。
- 状态为等待、运行中、等待交互、成功、失败、已取消、已中断；只在实际运行时转圈。
- 工具审批沿用既有权限机制，注明当前专家名称；角色不能替用户批准操作。
- 停止时取消当前执行并禁止启动后续成员和汇总。完成回调与停止操作由同一运行锁串行处理，避免停止后继续调度。
- 成员失败时团队停止，不输出成功汇总；保留已完成成果，提供「从失败处继续」和「重新执行整轮」。不自动重试可能产生副作用的成员任务。
- 从失败处继续只重新执行失败成员及其后续环节，使用同一轮冻结快照。汇总失败则只重试汇总。重试产生新的尝试记录，不覆盖历史。
- daemon 重启后将未完成运行标为已中断；用户明确继续后，从首个未完成成员开始。提示未完成成员可能已经产生文件或工具副作用，执行结果不会自动回滚。
- 身份切换在运行中禁用。第一版团队运行期间，用户补充进入现有待插入队列，由下一个尚未启动的成员消费并传递给后续环节；汇总前补充由汇总消费。汇总已启动后新增补充留给下一轮，界面明确显示生效位置。

## 6. 数据、接口与代码职责

- 全局资产沿用 `~/.workstep/data/role-center/`，定义不混入引擎会话状态。团队增加 `execution_mode: sequential`，缺失时按此值兼容；保留现有名称、成员、分工、排序和团级提示词。
- 会话和 LLM 步骤新增 `execution_identity`：普通执行用 null，其他为 `{kind: role | team, id}`。任务步骤覆盖另以「未配置」与显式 null 区分继承和清除。
- 聊天发送请求可提交本轮所选身份，服务端在同一启动操作内校验并持久化；已有客户端不提交时沿用会话身份。流程及任务配置读写接口返回最终身份和来源。
- 每轮启动在线程内解析完整资产，冻结资产 ID、revision、成员顺序、分工、提示词及引擎配置。角色中心改动只影响下一轮；恢复、失败继续和查看实际输入均使用快照。
- 在项目数据库增加团队运行、成员执行／尝试记录，记录所属聊天或任务步骤、父消息、本轮目标、快照、状态、成果引用与引擎会话标识。运行产物通过项目存储解析器定位，禁止写死项目根 `.workstep`。
- 专家执行使用 `AssistantConfig` 注册，复用 `AssistantRuntime` 的会话、引擎、流式事件、停止和审批；新增团队调度服务仅负责顺序、交接、快照及状态，不复制引擎循环。
- 使用独立 `expert_team` 通道与运行／成员标识，沿用 ACP 到 AG-UI 的统一转换；父聊天和成员事件按订阅隔离，既有聊天 store 不接收其他成员正文。
- 增加项目范围的运行详情读取、继续和取消接口；校验运行属于当前授权项目及父聊天／任务。重复启动及重复继续通过请求标识与运行锁去重。
- 身份选择器与运行卡片为独立组合模块，复用现有输入、消息、Markdown、确认及可缩放弹框组件。页面只装配，不向超大页面新增独立业务流程。
- 角色引用失效或文件损坏时阻止发送／启动，保留用户草稿；已冻结快照的运行不受资产删除或损坏影响。
- 首期仅支持本机普通聊天及任务步骤，不开放远程项目、分享、渠道聊天和内置助手入口。使用与管理权限后续分开设计，不直接放宽现有宿主资产管理门禁。

## 7. 分期与验收

### 第一期：角色可用

实现共用选择器、面具和斜杠菜单、会话身份持久化、切换交接、步骤继承与覆盖、实际输入快照。角色中心增加用于对话入口。

验收：两种选择入口一致；刷新及重启保留身份；新旧身份不共用引擎会话；失败保留草稿；旧会话及旧流程保持原行为；步骤普通启动、追问、审核返工均使用正确身份。

### 第二期：顺序专家团可用

实现独立专家执行、顺序交接、父会话汇总、运行卡片、工具交互、停止、失败继续和重启恢复；接入聊天与步骤相同运行服务。

验收：用可控假引擎证明成员拥有不同会话且按序启动；成员只能接收自身角色正文；前序成果真实传递；汇总包含全部成果；失败及取消不启动下游；重复继续不重复执行；重启不自动重放；修改全局资产不改变已冻结运行。

所有新增文件 I/O 及 Peewee 路径覆盖真实 API 与慢盘／慢 SQL 健康 canary。检查桌面及 320px、390px、1023px 布局、既有技能及步骤菜单、聊天停止、权限审批与历史查看回归；更新 Code Map、角色中心说明及语言词典。

### 后续扩展

第二期验收后再设计并行会审、成员级模型选择、指定主持人和远程使用授权。并行开发还需工作区隔离与冲突策略，不以多人同时写同一目录作为默认实现。
