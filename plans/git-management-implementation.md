# Git 管理功能实施方案

## 目标与当前状态

采用 C 融合方案：全局仓库树、文件列表、提交说明常驻；只有文件对比打开大弹窗。点击分支是浏览，显式「切换分支」才改变工作目录。

已实现：三套交互原型；真实全局 `git_scan_depth` 配置、读取/保存接口及设置页，默认 5。
待实现：真实仓库扫描、Git 状态/历史/差异/归属、真实提交与分支切换。当前原型的数据及 Git 操作仍为模拟。

提交默认值待用户进一步选择；在没有补充前采用：默认选中已跟踪文件修改及已有暂存内容，未跟踪新文件手动勾选。暂存不再是提交前必须手动执行的步骤。

## 1. 入口与信息结构

- 生产入口为全局侧栏「Git」，主路由 `/git`；项目菜单「查看 Git」携带项目标识进入并定位。全局页面不切换会话/任务的 activeProject。
- 树按「WorkStep 项目目录 → 发现的 Git 仓库 → 主工作目录 / Worktrees / 其他分支」组织。项目根目录不是仓库也保留这一层；仓库显示相对项目路径。
- 同一仓库通过规范化的 Git common directory 去重；多个项目发现同一仓库时保留各项目入口，复用同一份仓库状态。
- 工作目录行显示路径、当前分支或 detached HEAD、修改数及上游领先/落后数；没有 upstream 明示，不发起隐式 fetch。
- 主区明确当前仓库、目录、分支。文件按目录树排列并有状态标记，使用「纳入提交」复选框；点击文件名打开对比，点复选框只改变提交范围。

## 2. 全局扫描设置与仓库发现

- 全局「设置 → Git 设置 → Git 扫描目录层级」，键 `git_scan_depth`，保存至现有 `~/.workstep/config.json`。根目录是 0 层，直接子目录是 1 层；深度 5 包含第 5 层，不包括第 6 层。0 只检查根目录。
- 扫描根是已注册的本地项目目录；暂不扫描远程项目，也不遍历整块磁盘。项目路径重叠时复用目录访问结果。
- 在层级内查找 `.git` 目录或文件，并用 Git 验证候选路径；支持嵌套独立仓库与以 `.git` 文件关联的仓库。发现仓库后仍按深度继续查找子目录中的独立仓库。
- 不进入 `.git` 元数据、`.workstep`、`node_modules`、`.venv`；不跟随目录符号链接。显式注册为项目根的符号链接先规范化根路径。目录权限错误只影响对应目录，不中断其他项目。
- 对每个已发现仓库调用 Worktree 列表接口，纳入 Git 登记的外置 Worktree；这些路径不受递归发现层级限制。已删除/不可访问 Worktree 标记不可用，不自动 prune。
- 进入 Git 页面读取缓存并发起过期扫描；手动刷新、项目列表变更和层级保存后触发重新扫描。扫描按最新配置代次发布结果，过时扫描不得覆盖新结果。
- 扫描在后台有界执行，最多同时检查 4 个目录/仓库；逐项目显示进度、错误和上次扫描时间。结果驻内存，不新增 Peewee 表。

## 3. 文件审阅与提交

- 默认交互是「勾选文件 → 填写说明 → 提交 N 个文件」。不要求先点击暂存；保留暂存状态作为辅助信息，不把它作为能否提交的唯一条件。
- 提交范围是所选文件的完整当前内容，包括修改、删除及被选中的新增文件。重命名将旧路径与新路径视为同一项。新出现的文件不在用户已选范围中静默加入。
- 默认对比 HEAD 与当前文件，能看到尚未暂存的修改；同一文件存在部分暂存时明确标记「将提交完整文件，包含未暂存修改」。V1 不提供按代码块提交。
- 已勾选文件在审阅后再次变化时使提交快照失效，刷新差异并要求重新审阅后提交。说明为空、无有效选择、存在合并冲突或提交执行中时禁用提交。
- 后端接收工作目录标识、所选相对路径、提交说明和审阅快照标识；验证所有路径和 HEAD/状态快照，不接收任意 cwd 或任意 Git 参数。
- 文件级提交采用限定路径的 Git add 与 commit --only：仅处理选中路径，未选文件及其既有暂存保持不变。参数使用 argv 和字面路径模式，重命名包含新旧两条路径；大量文件使用 NUL 分隔 pathspec 文件，提交说明通过 UTF-8 临时文件传递。
- 保留 Git 的 hooks、签名与身份检查，不自动跳过或修改用户配置。失败时保留提交说明与选择，刷新并显示实际暂存状态，不执行隐式 reset/checkout 回滚；若已有提交生成，先核实 HEAD 后报告结果，不盲目重试。
- 成功后移除本次已提交的修改项、清空本次说明、刷新提交历史及分支状态；其他工作目录的选择和草稿保持独立。

## 4. 对比、归属与分支操作

- 文件对比弹窗支持左右/统一视图、行号、增删高亮、修改段导航及函数上下文。函数名使用 Git diff 提供的 hunk context，缺失时显示行号范围，不伪造解析结果。
- 逐行归属读取比较基准版本的 blame 数据；未提交新行标记「未提交」。展示作者、日期、提交摘要及哈希；首次提交、未跟踪文件、已删除文件分别展示空基准或单侧内容。
- 单个文件超过 2 MiB 或差异超过 20,000 行时返回带原因的限量预览；二进制仅展示状态和大小。子模块显示引用变化，V1 不在面板里执行子模块更新。
- 历史分页每页 50 条，选择提交显示该提交相对第一父提交的文件变化；根提交与空树比较。历史内容只读，不能混入待提交列表。
- 点击「其他分支」只浏览该分支与当前 HEAD 的差异；「切换分支」在页内展开搜索列表。只支持现有本地分支切换；已被其他 Worktree 检出的分支提供「定位工作目录」。
- V1 对存在未提交修改、未跟踪文件、冲突、正在进行 merge/rebase 或有 WorkStep 执行任务的工作目录禁用分支切换，并展示具体原因。不自动 stash，不强制 checkout，不丢弃修改。
- 切换成功后目录路径不变，重新读取实际分支、状态和历史；跨进程竞态导致失败时显示 Git 原因并刷新。分支创建/删除、Worktree 创建/删除、push/pull、stash 和图形化冲突解决不纳入 V1。

## 5. 代码边界与接口

- 后端新增 Git 服务，分为仓库发现、受控 Git 子进程执行、查询与写操作；API 只负责校验/调用。文件枚举等同步 I/O 放执行器；Git 使用 asyncio 子进程，沿用项目分块流读取约束。
- 仓库和工作目录使用服务端分配的稳定标识；按 common directory 串行化提交/分支写操作。读取可并行，命令超时与输出上限集中管理；不自动清理 index.lock。
- 全局本地 API 使用既有鉴权，禁止将全局 Git 操作通过远程项目通道暴露。工作目录授权来自已发现项目与其登记 Worktree；路径规范化后校验，符号链接文件只操作链接本身。
- 设置沿用 `GET/PUT /api/system-settings` 的 `git_scan_depth`，不另造设置存储。
- 发现接口：`POST /api/git/scans` 返回扫描任务标识；`GET /api/git/scans/{id}` 查看进度；`GET /api/git/repositories` 读取缓存结果。
- 工作目录接口：`GET /api/git/worktrees/{id}/status|branches|history|diff|blame`；写接口 `POST /api/git/worktrees/{id}/commit|switch-branch`。历史 diff 与 blame 使用校验过的提交标识，所有查询返回实际比较基准。
- 前端独立 `GitWorkspace` 组合模块，分别拥有仓库树、提交编辑器、文件对比和分支选择状态；Layout 只挂入口。共用 Git store 对同一查询去重、按目录缓存。
- 页面可见时每 5 秒刷新当前目录状态；窗口恢复焦点、手动刷新、操作完成合并到同一刷新入口。后台页暂停轮询；扫描期间每秒读取进度，完成后停止。

## 6. 交付顺序与验收

1. 全局设置持久化：默认值、0 层、非法输入、失败重试、重启读回；已完成，含慢 I/O 事件循环 canary。
2. 仓库扫描与树：在临时目录构造非 Git 项目根、深度 0/1/5/6 仓库、嵌套仓库、外置 Worktree、符号链接循环、重复项目和不可访问目录；验证边界、去重、过时扫描及慢盘响应。
3. 只读审阅：真实 Git 临时仓库覆盖修改/新增/删除/重命名、中文空格与特殊字符路径、二进制、大文件、无 HEAD、历史与 blame；完成 UI 集成后再接写操作。
4. 文件勾选提交：验证未暂存可直接提交、未选文件和既有暂存不被带入、选中文件含部分暂存、新文件、删除/重命名、hook 拒绝、身份缺失及审阅后内容变化。不得触及用户当前仓库的数据。
5. 分支切换：干净成功、脏目录拒绝、Worktree 占用定位、后台任务保护及外部 Git 并发错误恢复。
6. 桌面/窄屏验收：只有文件对比弹窗；目录切换不串草稿；设置保存只发一次请求；读写命令慢时健康检查仍响应；确认生产入口使用真实 Git，原型入口仍限定开发环境。
