# 项目聊天中的流程模式技能

## 已确定的交互

- 本机项目普通聊天输入框「＋ → 流程模式」查询当前引擎的已启用技能，插入引擎提供的技能引用（Codex：`$workstep-exec `；Claude：`/workstep:workstep-exec `；其他适配器默认 `/workstep-exec `），保留用户原有想法，不自动发送。
- 技能源为 `apps/daemon/data/skills/workstep-exec/SKILL.md`，与内置 CLI 技能同层，随应用打包。调用引用作为真实用户消息发送，正文由现有技能中心和引擎按白名单加载，不占用输入框。
- AI 先理解想法、按需求动态设计步骤，在消息中输出基础 Mermaid 流程图、步骤说明和任务内容。通过继续对话调整，不新增编辑画布。
- 用户通过 A2UI「创建并启动」按钮或明确回复确认后，技能通过公开 CLI／原生工具新建一个可复用项目流程和一个任务，随后单独启动任务。
- 最终回复包含工具返回的真实任务详情链接，应用将其显示为「打开任务详情」按钮；任务创建成功但启动失败也保留入口。结果不确定时先查询，不盲目重复创建。

## 实现边界

输入框加载及会话隔离归独立 hook；现有页面与聊天组件只装配入口。没有新增 `workflow_mode` 请求字段、专用助手、事件通道或后台流程设计服务。复用引擎 inspect 接口，增加公开流程创建与任务启动工具、成功任务结果链接，以及应用内按钮导航。

流程和任务继续使用现有 REST API 的定义校验、项目数据库执行器、任务创建与运行逻辑。规划及创建顺序由内置技能指令驱动；不将提示词遵循声称为服务端事务或强幂等保证。
