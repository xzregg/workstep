# 引擎原生权限整改

## 目标与职责

权限选项和执行语义由具体引擎拥有。公共 Base/ACP 只提供配置描述、选择校验、设置与审批请求/响应接口；Web 按声明展示，不按引擎 ID 或固定五档推断权限。不实现宿主沙箱。

复用 EngineConfigField 表单声明，以 category=mode 标识原生权限字段，允许一个或多个选项组。发布给客户端时使用 ACP configOptions 的 id/name/description/type/currentValue/options 形状。自定义 worker 同样导出该声明；无声明不补造模式。

## 默认与历史兼容

- 跟随引擎设置不是原生 default 模式；前者无覆盖，后者可以是实际枚举。
- 明确选择覆盖引擎已保存设置，未设置才使用原生默认。只有权限字段可进入权限选择，禁止注入其他配置。
- 新选择绑定引擎并带版本，复用现有权限文本持久化位置，不以数据库结构变更阻断重启。旧五档按适配器原有映射继续读取，保留旧限制；新菜单不再生成旧值。
- 跨引擎切换/接力/分叉清除旧引擎的选择；同引擎可继承有效选择。不把旧 read-only 解释成 Pydantic 的可批准写入。
- 清除覆盖必须实际恢复引擎配置；不能只清空 UI，而让复用会话沿用旧模式。不支持热切换时明确下一轮生效。

## 实施步骤

1. 测试先行：原生多字段、默认继承、错误值/跨引擎拒绝、旧配置及新进程恢复。
2. 引擎声明：标注各适配器权限配置字段，输出安全的 ACP 形状配置描述。保留旧映射仅作兼容。
3. 执行与审批：取消新选择的全局名称推断；由适配器最终配置决定审批。Pydantic 接入官方 Permissions 和 deferred approval handler，旧选择保留既有约束。
4. 选择入口：共用动态权限菜单，设置/步骤复用现有 schema；默认值回显、清除、引擎切换、接力、分叉及辅助调用一起覆盖。
5. 自定义引擎：升级 describe/proxy/validate 契约，旧安装元数据继续可发现可执行，新增声明重新 inspect/validate/register。
6. 更新 Code Map、引擎指南、CLI 接入及测试规范；完成行为测试、类型检查和实际渲染。

## 必过验收

- 全新 Python 进程重新发现全部已安装引擎，读取保存配置；不能出现重启后不可选或无法执行。
- 自定义引擎 worker 退出后重新启动，原生选项、默认值、明确覆盖均正确恢复；旧包元数据可用。
- 空覆盖随引擎设置变化；显式原生 default 不等于空覆盖；恢复原生会话不遗留旧权限。
- 新模式不被 ACP 公共层按字符串自动批准；用户问题不被审批策略代答。
- Pydantic full/auto/read-only 使用官方含义，批准/拒绝在执行前生效；旧只读与计划限制不放宽。
- 聊天/渠道/任务/审核/助手默认/分叉/接力的配置不串引擎；不支持选项不能保存。
- 前端默认/明确选择/多配置字段、五种宽度渲染及 TypeScript 验证。
- 测试不并发全量套件，临时产物统一在 tmp/engine-native-permissions 下；不重启用户正在使用的应用。
