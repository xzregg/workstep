# 可视化连接器与多引擎适配评估

日期：2026-11-11

状态：评估方案，未实现；本次不修改应用代码、运行配置或安装环境。

## 结论

建议增加独立连接器模块：统一配置、凭据引用、安装与授权状态、项目使用范围，再通过各引擎适配器提供运行配置。不能只在现有设置页增加 JSON 文本框，也不能把所有连接器直接塞进引擎基类的每次启动。

采用增量接入：未选连接器时维持原启动行为；逐个引擎开启适配，不一次替换现有配置、Skills 和安装流程。零回归是验收要求，不能仅靠架构设计宣称已保证。

## 当前实现依据

- `apps/web/src/components/EngineSettingsPanel.tsx` 已负责引擎安装、配置、模型和检测，状态较多；连接器应独立为自管理模块，设置页面只装配入口。
- `apps/daemon/engines/core/acp_base.py` 接收 `config_overrides.mcp_servers`，检查 Agent 声明的传输能力，并传给新建/恢复会话；这是可复用的接缝，不是完整的连接器管理层。
- `apps/daemon/engines/claude_agent_sdk.py`、`qoder_sdk.py` 显式提供插件、Skills 和 settings sources，当前未统一接入上述 MCP 参数；不能假设会自动加载原生配置文件。
- Codex CLI/SDK 有原生配置覆盖机制，需评估 MCP 参数与自定义配置的合并、账号认证环境和会话恢复行为。
- Pydantic AI 已有 MCP 存储和能力展示，但当前 Agent 构建未见对应配置挂载；依赖存在不等于工具已加载。
- `services/engine_runtime.py` 和 `engines/core/packages.py` 是引擎包安装管理，包查找依赖引擎 registry，不能直接把连接器注册成引擎来复用。
- `services/skill_runtime.py` 已有按引擎输出项目 Skills 的实践，可借鉴配置转换方式，保持其现有白名单规则。
- 基类存在无工具协调调用路径；连接器注入必须明确执行用途，不能自动给只读协调、标题生成、模型检测等内部调用增加外部工具。

## 可视化交互

在设置中提供独立“连接器”栏目，沿用现有设计系统和控件。

### 添加与配置

1. 选择预置连接器，或“添加自定义连接器”。预置模板只表示已验证的接入，不默认依赖 Composio，不把尚未支持的平台写成已支持。
2. 按模板显示必要字段和主操作：网页登录授权、填写 Token、安装 CLI、本地 MCP 或远程 MCP。普通用户无需选择底层引擎参数。
3. 本地 MCP 使用命令、逐项参数、环境变量表单；远程 MCP 使用地址、认证方式和必要请求头表单。密钥使用密码控件，保存后不回填明文。
4. OAuth 页面显示实际申请权限与回调结果；取消、超时、失败可重试，不要求重填无关信息。
5. 测试连接后选择使用项目和适用引擎。默认不自动对所有项目、所有内部助手开放。
6. JSON 仅作高级导入/导出入口。导入先预览差异和冲突；默认导出脱敏，不包含凭据。未知字段不得静默丢弃。

### 列表与状态

每项显示名称、账号、使用范围，以及安装、授权、连接检测和引擎可用性。分别提供连接、重连、测试、编辑、停用、移除操作。

必须区分：未安装、待授权、授权有效、连接检测通过、选定引擎验证通过、授权失效和失败。一次检测结果带时间，不能把历史成功标成实时在线。未选验证引擎时只显示连接级结果。

停用、移除与撤销第三方授权分别处理；不能把删除本地记录表述为已经撤销平台授权。删除本地记录也不能擅自清理 CLI 管理的共享登录凭据。

配置编辑拥有独立草稿、校验、请求、错误恢复和关闭保护，避免向 SettingsPage 或 EngineSettingsPanel 继续堆业务。复用 ConfirmDialog、输入和选择控件；弹窗遵循项目缩放、移动端和 i18n 规范。

## 模块边界

建议新增以下职责，文件名在实施时按项目惯例确定：

| 模块 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 连接器定义与存储 | MCP/CLI 定义、配置版本、启用状态、项目绑定、凭据引用 | 不修改引擎的用户原生配置 |
| 认证与凭据 | 安全保存、OAuth 临时流程、撤销和过期状态 | 不向 UI、日志或提示词返回原始密钥 |
| 连接器运行管理 | 独立安装目录、版本、检测、进程与退出清理 | 不替换现有引擎安装器 |
| 会话解析 | 根据身份、项目、用途、引擎能力生成本次连接器快照 | 不自行扩大项目权限或开放全部工具 |
| 引擎适配 | 把统一描述转换为引擎原生 MCP/CLI/Skill 参数 | 不重写原有模型、审批、沙箱与 Skills 逻辑 |
| 前端组合模块 | 可视化配置、授权、检测、项目与引擎可用性 | 页面层仅装配 |

统一描述至少包含：稳定 ID、名称、类型、传输、命令/参数或地址、认证方式与 secret reference、CLI 登录/状态/退出定义、运行包版本、使用范围、配置 revision。安装、授权和验证结果独立记录，不以单个 connected 布尔值代替。

本地安全存储需单独验证桌面、独立 daemon、Docker、无图形会话和托管模式的可用性；当前不能直接承诺所有平台都使用系统钥匙串。CLI 自管登录时复用 CLI 的认证行为，不强制导出 Token。

## 各引擎适配评估

| 引擎路径 | 预期工作 | 风险/验收重点 |
| --- | --- | --- |
| ACP 原生及 OpenCode ACP 路径 | 复用会话 MCP 参数，统一描述转 ACP schema | stdio/HTTP/SSE 实际声明、恢复会话、取消与子进程清理 |
| Claude CLI/Agent SDK | 通过各自原生启动配置接入 | settings sources、已有 MCP、插件 Skills、审批及恢复不能被覆盖 |
| Codex CLI/SDK | 通过原生配置适配，保持命名空间隔离 | 自定义覆盖、用户已有服务器、原生 OAuth 状态、恢复和 fork |
| Qoder SDK | 核实所用版本的真实原生入口后适配 | 未有入口时明确不支持，不以接口签名冒充支持 |
| Pydantic AI | 实际创建 MCP toolset/能力并挂载 Agent | 异步生命周期、并发会话隔离、停止关闭、原 Coder/Skills 工具保留 |
| DeepSeek Harness、OpenClaw、自定义引擎 | 分别核对入口与策略后纳入 | 未验证不显示可用；不能仅凭所有引擎共享基类推断支持 |

CLI 接入只对确实具备命令执行能力、允许目标 CLI 且能访问对应凭据环境的引擎生效。Pydantic AI 的命令白名单和桌面沙箱均需验证，不得为了连接器放宽现有安全边界。

## 兼容性约束

- 未选择连接器时返回空运行补丁，原参数、环境、配置读写及启动路径保持原语义。
- 不写入或迁移用户的 Claude/Codex 原生配置文件；原生已有 MCP 保留。服务器重名时提示用户处理，不能静默覆盖、禁用或造成重复调用。
- 只覆盖连接器命名空间；模型、供应商、审批、沙箱、Skills、系统提示词和输出事件沿原实现。
- 配置 revision 固化为会话快照。一般编辑对下一次兼容启动生效，不热重启运行中任务；原生会话恢复不能更新工具集合时明确提示需要新会话。
- 停用后拒绝创建新的使用会话。运行中会话的停用/撤权语义单独实现并明示；密钥已交给原生引擎时，不能承诺本地开关立刻撤销已发出的调用。
- 连接器故障按所选会话报告，不影响未使用它的聊天、任务与设置操作；所需连接器不可用时不得静默继续并宣称可用。
- 新接口沿用宿主管理和项目授权边界，不复活 `engine.install`。宿主安装/认证与项目绑定分权；分享访问不能获得新增执行权限。
- 阻塞文件、系统钥匙串、安装和数据库访问均隔离事件循环；新增路径须有延迟或锁竞争 canary。
- 打包仅包含运行必需资源和定义模板；凭据、OAuth 临时数据、日志与连接器运行缓存不进入发布包。

## 分阶段交付

1. 先补兼容性基线测试与真实引擎能力核对，确定合并规则；独立增加定义、存储和可视化配置，尚不改变任务启动路径。
2. 接通一个已验证引擎和 MCP 传输，贯通添加、测试、启用、执行、停止、重启与移除。远程地址连接不应先安装无关依赖。
3. 各引擎逐个实现适配器，每个通过回归后再开放。保留模块停用开关；默认不自动迁移旧原生 MCP。
4. 扩展 OAuth、托管服务和 CLI 安装模板；每个平台独立验证认证、权限和退出行为，不一次性承诺所有平台通用。
5. 合并交付节点同步 Code Map、完整手册译文和真实演示截图，并运行项目要求的官网测试、构建和 manual:check。

建议首批限定为可视化 MCP 配置和已验证引擎；OAuth/CLI 与平台目录分批。若首批同时要求全引擎、跨平台安装、Composio、钉钉和企业微信，范围属于较大功能建设，不是一个表单改造。

## 必须通过的验收

- 默认空配置、全部停用：原引擎启动参数和行为与基线一致，普通会话、任务步骤、助手、只读协调、定时和恢复入口均覆盖。
- 同时存在原生 MCP 和托管连接器：原配置保留，重名可见且无静默覆盖。
- 每个宣称支持的引擎完成真实工具发现与最小调用；新建、恢复、重启、停止和 fork 按能力覆盖。仅 mock 不能作为全引擎可用证明。
- 工具流式事件、审批、错误、图片输出、Skills、附件、模型/供应商选择和沙箱行为回归通过。
- 用户、项目、多账号、并发会话隔离，禁用/撤权、过期刷新和失败重试通过；只读与分享场景不能越权。
- 密钥不出现在普通 API 响应、事件、导出、诊断日志和模型上下文；连接级/会话级认证仅在受信运行边界使用。
- 慢网络、慢钥匙串/磁盘、SQLite 锁及并发安装不阻塞健康检查，取消后无遗留进程。
- GUI 覆盖新增/编辑/导入、字段校验、关闭保护、授权取消/超时、错误后保留草稿、请求去重，以及真实桌面/移动端布局。
- 安装失败不破坏旧版本；不修改用户全局依赖；重启恢复状态真实；发布 payload 检查不包含凭据与运行缓存。

本次仅完成静态评估，未运行测试或启动项目，未验证外部 SDK 最新能力。实施前需核实依赖版本及各平台认证要求，并先编写上述关键行为测试。
