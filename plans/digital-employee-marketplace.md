# 数字员工订阅平台实施方案

创建日期：2026-10-20。更新日期：2026-10-26。状态：规划草案，尚未实现。

WorkStep 同时服务员工发布者与雇主。发布者把岗位职责、工作流、Skill 和主动工作规则打包为数字员工；雇主按月订阅，在自己的 WorkStep 中安装，也可后续申请远端运行实例。首个岗位为研发员工。

可信执行是开放第三方员工市场的前置条件。第三方岗位指令、工作流、Skill、测试和生成代码均按不可信内容处理；老板授权的数据与操作边界由其控制的运行环境执行。安全承诺须说明实际接收方、强制约束和验证范围，不能仅以本地部署、平台审核、版本签名或容器作为依据。

## 1 产品约定与首版默认值

已明确的产品方向：

- 用户能够制作并发布自己的员工，老板能够订阅并下载员工包。
- 一名员工可以由一个流程、多个流程组成，也可以通过默认工作区的主对话承担沟通、判断和调度职责。
- 员工具备主动性，能够检查工作情况、跟进待办并在授权范围内推进工作。
- 员工支持本地部署；模型可由老板选择本地、内网或云服务，模型费用另计。
- 月费购买员工使用授权与能力更新；员工的业务资料、记忆和工作记录属于老板。

以下为推进方案采用的默认值，尚非用户逐项确认的商业规则：

| 事项 | 首版默认值 |
| --- | --- |
| 发布供给 | 用户发布，平台审核每个版本后上架；先向受邀用户开放 |
| 交付顺序 | 先验证执行边界，再完成本地员工、市场订阅，最后提供远端托管 |
| 订阅单位 | 一份员工商品的一个活跃安装名额，可绑定该设备上多个获准项目 |
| 运行位置 | 首版本地；后续远端由平台提供服务器，算力与存储费单列 |
| 到期 | 停止员工的新工作，保留资料、历史、成果和导出能力 |
| 主动授权 | 默认检查与提议；具体流程可经老板授权自动启动，写入与外部操作须单独满足权限 |
| 更新 | 提醒后由老板应用，空闲时切换；新权限重新授权 |
| 角色中心融合 | 升级为数字员工中心，角色库保留为岗位模板；现有角色不自动变成在岗员工 |
| 专家团 | 首版保留当前单模型使用多角色的语义，独立员工团队另行建设 |
| 本地自建员工 | 老板可自行装配使用，无需市场订阅；项目授权与可信执行要求相同 |
| 数据接收方 | 优先支持本地或老板内网模型；云模型须单列其接收的资料范围，由老板选择 |
| 外部连接 | 员工执行环境默认不能直接外联；必要动作通过环境外的受控服务办理 |
| 试运营收款 | 管理员确认月度订单后生效，不宣称已支持在线支付、自动续费或自动分账 |

订阅能力与本地 WorkStep 的普通功能分开。未订阅、到期或平台不可用，不锁住普通聊天、自建流程、自有 Skill 与原有数据管理功能。

## 2 员工对象与使用体验

### 2.1 商品 订阅 安装与会话

| 对象 | 所有者与职责 |
| --- | --- |
| 角色与专家团模板 | 设备上的岗位方法资产，沿用现有角色中心格式及来源信息 |
| 员工定义 | 发布者或老板装配的岗位、流程能力、Skill 和主动职责，可保存草稿及不可变版本 |
| 员工商品 | 发布者维护岗位、介绍、价格和交付能力；平台持有上架与审核状态 |
| 员工版本 | 不可变的能力包及依赖摘要，保留来源与许可信息 |
| 订阅 | 记录雇主、商品、名额、付费周期和授权状态，不保存业务对话 |
| 员工实例 | 老板安装后的持续身份，绑定版本、工作范围、个人配置和订阅名额 |
| 交互会话 | 一次聊天上下文，可以显式绑定员工实例；会话不是员工身份 |
| 项目工作记录 | 员工在具体项目的发现、提案、任务关联、检查点与阻塞记录 |

工作流、项目、聊天及员工实例分别使用稳定 ID。删除或归档聊天不删除员工；重命名默认工作区不改变员工身份。默认工作区可以指定一名主员工，但其既有会话不会被批量绑定或更改。

多流程员工首先表示一组可调用能力。流程之间存在顺序、返回或依赖时，使用现有工作流编排与任务派发明确表达，不凭列表顺序合成另一套执行器。

### 2.2 发布者路径

1. 在 WorkStep 创建员工草稿，填写岗位、职责、交付要求与使用说明。
2. 选择一个或多个流程、所需 Skill、主对话配置及可选主动职责；查看依赖和导出文件清单。
3. 在独立演示项目验证安装与运行，提交版本、更新说明和月订阅价格。
4. 平台校验包完整性、依赖、许可与声明权限；审核通过后上架。
5. 后续更新生成新版本；驳回可重新提交新版本，已发布版本不能原地覆盖。

发布者可以看到商品、版本、订阅与订单归属，不因发布身份获得老板的仓库、凭据、聊天、记忆或任务日志访问权。第三方员工代码与工具仍可能尝试外传资料，因此还必须通过第 6 节的实际执行边界验收，不能把后台账号权限当成完整的数据保护。

### 2.3 老板路径

1. 在员工市场查看岗位、能力、模型与环境要求、权限、月费和真实示例，订阅一个安装名额。
2. 选择安装到当前 WorkStep，下载并验证固定版本的员工包。
3. 通过入职配置绑定项目、执行与审核模型、必要凭据、工作时间、通知位置和行动权限。
4. 查看实际提供的资料、模型接收方、外部动作及运行环境检测结果；先用模拟数据试工，确认后再授权真实资料。
5. 查看将创建的流程、Skill 与定时职责；配置完整且执行边界验证通过后明确启用。
6. 从员工对话或能力入口派活，查看当前工作、主动发现、待批准事项、阻塞与交付成果。
7. 随时暂停主动工作、停止当前执行、调整职责、更新版本、取消续订或卸任。

卸任停止该实例的定时职责并保留工作数据。移除受管理能力文件时展示清单；不删除老板仓库、自有 Skill、记忆和任务成果。

### 2.4 与角色中心结合

现有角色和专家团继续作为岗位模板，保留 ID、正文、分类、来源、修订和对话加载能力。从模板明确点击“创建员工”才生成独立员工草稿，不批量迁移既有模板、会话或引擎身份。

员工草稿选择角色或专家团的具体修订，再装配一个或多个流程、Skill、知识来源与主动职责。岗位模板定义工作方法，流程和 Skill 定义可执行能力，项目授权决定实际可接触的数据与动作。只配置主对话的员工可先承担咨询与提议，卡片如实显示尚未装配的执行能力。

草稿保存使用修订冲突检查；生成本地版本时冻结所选岗位正文与能力资源，记录来源 ID 和修订以便追溯。模板编辑后显示可采用的新修订，由老板决定是否生成员工新版本；不通过可变角色引用直接改变已安装实例。来源模板删除或不可访问时，已冻结版本仍可按原授权使用，仅影响来源查看与后续修订采用，不在每次执行时重新读取源模板。角色模板和专家团原有编辑接口保持原结构，不把员工运行配置写入角色 JSON。

自建、导入与市场订阅使用同一种员工实例及执行门禁。自建员工凭本地所有权使用；市场受管版本按订阅授权使用，导入包不能自动获得订阅名额。资料、凭据、模型绑定、权限和工作记录始终属于实例，不能随员工定义发布。

现有专家团继续由一个模型使用多位成员的岗位指令。专家团可以作为员工岗位模板，但不会因此产生独立成员会话或真实调度。首版独立研发员工分别拥有自己的实例状态；多员工团队的任务分配、交接和成员执行另行设计。

### 2.5 员工中心与专属对话

现有工具栏的角色入口升级为“数字员工”，进入独立 `/employees` 页面，默认显示“我的员工”。页面保留“岗位模板”分区，其中继续提供角色库与专家团；原设置中的角色入口复用同一岗位模板模块，避免两套编辑器和加载逻辑。市场与订阅服务完成后再增加“员工市场”，首版本地提供创建和导入入口。

“我的员工”卡片显示岗位、当前版本、来源、自建或订阅状态，以及待配置、待验证、在岗、暂停等真实状态。员工详情集中呈现能力、当前工作、主动发现、待批准事项、交付记录和实际资料与接收方范围。尚无执行任务时不伪造忙碌状态；环境验证未通过时可以编辑草稿，不能启用执行或定时职责。

从岗位模板创建员工的装配模块依次持有岗位、能力、主动职责和版本预览；实例入职模块再持有工作项目、模型、凭据引用、权限和运行验证。两个模块自行处理状态、请求、校验、保存及关闭保护，页面和 Layout 仅做区域编排。

从员工卡片创建专属会话，沿用普通会话的页面、消息、流式事件与停止能力。新会话显式绑定员工实例，不把历史普通对话自动转成员工会话；会话归档、删除或重启不删除员工身份和待办。员工专属对话使用其固定岗位，不叠加普通角色选择；后端也拒绝普通角色绑定接口对员工会话的角色或专家团变更，不能只隐藏选择器。普通对话仍可按现有方式加载角色或专家团。

默认工作区可以指定一名主员工，使用绑定它的专属会话作为入口。主员工只对获准项目取数和调度，不能因会话属于默认工作区获得全局项目权限。每轮执行锁定员工版本及能力快照；升级只影响后续轮次，并刷新岗位注入检查点和能力上下文，未执行提案须重新核对版本与授权。

### 2.6 StaffDeck 参考边界

参考 [StaffDeck 官方工作流说明](https://github.com/OpenBMB/StaffDeck#core-workflows)中的员工档案、能力装配、运行观察和人工介入体验，映射到现有 WorkStep 能力：

| 参考概念 | WorkStep 落点 |
| --- | --- |
| 员工档案与岗位边界 | 角色模板加员工定义、实例配置与实际授权 |
| 员工能力与 SOP | 已有流程画布、任务派发、项目 Skill 和工具连接 |
| 执行记录与人工介入 | 现有任务消息、事件日志、审核、协调提案与停止能力 |
| 持续运营 | 员工级主动发现、项目记忆、工作记录和定时职责 |
| 员工与资源展示入口 | 员工中心及后续 Gateway 员工市场 |

以上是 WorkStep 的产品映射。员工月订阅、老板本地授权和第三方包可信执行沿用本方案，不据此认定 StaffDeck 已解决这些边界。首版知识来源复用获准项目文档、Skill 参考资料与项目记忆，不增加独立的知识索引或另一套 SOP 执行内核。

## 3 员工包 安装与版本

### 3.1 可移植的包

采用带清单的 ZIP，包含包 ID、不可变版本、岗位、职责、入口、最低兼容版本、文件摘要、来源许可、依赖和所需权限，以及显式选择的资源：

- 工作流定义；资源间使用包内稳定键引用，不携带作者设备上的数据库 ID。
- Skill 正文与声明文件，包含需要的 scripts、references、assets，并固定版本和摘要。
- 岗位模板的正文与来源修订快照、可选主对话配置、能力选择说明及不含私人信息的初始知识。
- 主动职责与定时模板：检查目标、规则、工作时间默认值、重叠策略和允许调用的能力。
- 执行环境要求与公共资源文件；安装说明列明需要老板配置的连接。

导出采用资源选择与文件白名单。排除数据库、聊天与任务历史、引擎会话、日志、记忆、上传资料、产物、缓存、真实仓库、密钥、登录态、私有地址和作者的本机路径。定时模板不含既有任务目标、执行记录、作者身份或下一次触发时间。

首版接受平台支持的运行环境与依赖声明，不接收发布者自带的任意镜像或安装后自动执行的安装脚本。未能移植的绝对路径、快捷动作、跨项目派发或外部文件依赖阻止发布，并说明需要补充的资源或安装映射。

### 3.2 安装事务

安装先验证签名、摘要、文件边界、兼容性与全部依赖，再暂存资源。老板完成项目、模型、工具连接、时区和权限映射后统一激活。下载、解包和失败重试均不能启动流程或定时职责。

包内流程键映射到本地独立流程行；Skill 绑定明确版本，不能静默覆盖同名自有技能。项目文件与运行数据通过现有项目存储解析器定位，不重新写死项目根目录的 `.workstep`。凭据由老板在本地受信控制程序中配置，员工仅引用被授权的动作，不获取原始密钥，不回填发布包。

员工包、安装配置、运行记录分别保存：包存于配置目录的受管理版本库；安装登记与授权缓存原子落盘；项目内的绑定、检查点、发现和任务关联进入各项目数据库。跨项目读取分别经各自数据库执行器返回纯数据。

### 3.3 更新与本地定制

- 发布基线、本地配置覆盖、业务数据分离；升级保留老板的路径、模型、凭据、权限、记忆和历史。
- 资源修改采用本地覆盖，升级时展示差异与冲突；不自动用新版覆盖老板修改。受订阅管理的副本仍遵循该员工授权，不把另存副本描述为脱离授权的功能。
- 当前任务绑定启动时的包版本、独立流程定义及依赖；更新不改变其恢复、返工与人工审核语义。新版本使用新流程行，旧任务继续引用旧行。
- 空闲时整包切换，失败恢复旧版。回退只切换能力定义，不逆向删除新任务、回滚代码或清除数据。
- 新增目录、工具、外部发送或写入权限必须重新确认；老板未批准时继续使用旧的已授权版本。

当前任务流程读取“主流程加任务覆盖”，尚不具备发布版本冻结语义。因此不能直接绑定并持续修改发布源流程。

## 4 研发员工与主动工作

### 4.1 首个岗位

研发员工提供四类能力：需求分析与计划、功能开发、缺陷修复、代码与测试检查。每项能力调用现有流程，具体步骤与审核仍由现有执行系统持有。

主员工在默认工作区与老板沟通，按授权选择目标项目和能力，并汇总进展。它不能因为属于默认工作区而获得全部项目访问权，也不自动替换任务协调助手或现有创作对话。

首版观察来源为获准项目内的 WorkStep 待办、任务与测试结果，以及周期性读取的 Git 状态。外部 Issue 平台同步、文件系统常驻监听和自动生产发布不在首批范围。

### 4.2 主动循环

1. 本地调度器在工作时间内检查来源变化，读取员工职责、项目检查点与尚未解决的事项。
2. 观察助手返回结构化判断：无需行动、待批准提案、可执行的已授权能力，或需要老板补充的信息。
3. 后端重新核对项目范围、订阅、能力版本、权限、当前任务状态和去重键，再持久化提案或启动现有流程。
4. 运行完成后更新对应事项；失败保留阻塞原因。条件未变化时不重复创建任务或反复通知。
5. 主对话呈现工作记录，集中显示需要老板决定的事项；无变化只更新检查点。

员工级发现与去重状态不依赖聊天历史。使用员工实例、项目、职责和来源变化标识形成稳定工作键；并发巡检、重连与重启复查均不得重复派发。各项目独立观察，主员工只接收被授权汇总的结果摘要；跨项目转移正文、产物或派发任务须另行校验。

研发写入先在该项目的授权工作副本中进行，向正式目录交付改动时使用项目级串行队列。工作副本不共享宿主 `.git`、原目录可写挂载或真实凭据。受信控制程序核对批准的具体差异、目标路径、符号链接和源版本后应用改动；内容变化、目录逃逸或与老板未提交修改冲突时暂停，不自动还原、清理、执行 Git 钩子或覆盖修改。

首版每条职责默认工作日按安装时区每 30 分钟检查，老板可修改并单独停用。轮询先判断来源变化或到期条件，再调用模型。初始预算为每个员工实例按安装时区自然日最多 24 轮模型巡检，跨项目和职责共享，失败轮次也计入；未调用模型的轻量检查不计入。该预算只约束主动判断，实际工作流另按老板的执行配置运行并记录消耗。界面展示预算与执行上限；重叠检查跳过，单次执行沿用已有引擎限额。

首次检查建立基线，不把全部历史问题自动变成工作。休眠期间不工作；恢复后补一次当前状态检查，不逐次补跑错过的时刻。暂停主动工作后取消待启动巡检；正在运行的流程可由独立停止操作终止。

### 4.3 行动授权

主动性与行动权限分开。默认只检查并生成提案；老板可为指定项目和流程开启自动执行。方案批准或职责授权均落为明确记录，模型不能自行扩大授权。

代码修改、提交、推送、合并、发布与外部消息不能仅靠岗位提示词授权。应用操作经过统一服务门禁；引擎自身的文件、命令和网络边界还须由可验证的权限或隔离能力承担。无法满足所需边界的引擎不开放对应自动能力，界面说明需要人工操作或更换执行配置。

外部文本、仓库文件与检查结果属于待处理资料，不构成新的老板授权。执行前校验实际目标与允许能力，不让观察助手直接执行任意命令。

示例验收：员工发现已授权任务的测试失败，形成关联事项；未获写入授权时给老板修复提案；批准后执行修复流程，运行测试并提交改动与证据；同一失败不重复派发，失败超过流程既有重试上限后报告阻塞。

## 5 月订阅 离线授权与商业边界

### 5.1 试运营订阅

每个商品由发布者设置月价。订单固定保存成交价格、币种、授权起止与安装名额；同一确认请求只生效一次。试运营由管理员确认收款并登记订单，平台记录作者应计收益，不自动打款；自动支付、续费、退款与分账接入作为正式商业化的独立交付项。

取消续订保留已付费周期内的使用权。涨价只影响后续新订单，不能改写既有订单。到期后禁止新的员工对话执行、任务启动与巡检。到期前已经启动的 WorkflowRun 可继续执行原定步骤至完成，不因到期强杀正在执行的引擎调用；若发生错误需要新的重试或返工，或进入人工等待，则保存为暂停状态，续订后才能恢复。不启动新的流程运行。查看、导出、停止和卸任始终可用。

普通下架停止新订阅，已付费用户在周期内保留获准版本。安全撤销走单独状态与签名通知；本地收到并验证后按第 6.3 节终止受影响执行，不适用普通到期收尾。删除商品不级联删除雇主业务资料。

### 5.2 授权租约

为员工订阅新增独立的签名授权租约，绑定平台、账号、商品、安装实例、设备、付费截止时间与授权修订。租约落盘，启动时可验签；与当前短期受管策略、设备重连凭据分开，不能直接把远程访问票据延长为月度授权。

默认每日联网刷新，允许最近一次成功验证后离线 72 小时，且不超过已付费截止时间。断线但租约仍有效时继续使用；超过宽限提示需要联网复核，真正到期显示需要续订。检测到明显时钟回退时要求联网验证。平台撤权通知尚未送达离线实例时，不能承诺已经停工；租约失效后禁止新工作，既有运行按第 5.1 节收尾，收到有效安全撤销通知后则立即执行第 6.3 节。本地老板撤权不依赖平台联网。

首版一份名额只有一个有效安装登记。换机先由原设备确认停用，再签新设备授权；原设备离线且无法确认时，等待其租约失效后转移名额。备份可以保留，但不作为并发运行许可。本地和远端不默认同时运行同一名额，也不自动同步业务状态。

本地交付的流程与 Skill 可以被设备所有者读取。订阅限制约束官方客户端管理的员工能力，不能承诺内容绝对保密、不可复制或无法绕过；平台价值包含审核、分发、更新和持续服务。

### 5.3 数据与模型

平台保存账号、商品版本、订阅订单、审核和安装授权登记，以及发布者在员工包中公开交付的岗位指令和流程模板。直接本地使用且未开启平台代理、分享或日志提交时，老板的业务文件、运行时输入的业务提示词、记忆、聊天与任务日志不作为订阅上传内容。模型和代码仓库凭据由运行环境外的受信控制程序持有，不交给第三方员工执行进程。

老板选择云模型时，执行所需输入会发送给对应供应商；入职配置显示实际模型来源。选择本地或内网模型时，依赖预检须验证员工所需能力，不把“可选择本地模型”描述为所有包都能在任意模型上等效运行。

## 6 老板可验证的信任边界

### 6.1 保护对象与接收方

首版防范员工包中的恶意指令、脚本、测试与生成代码读取未授权资料、调用未授权服务或破坏原始数据。老板仍须信任自己的设备、操作系统、运行时与受信控制程序；所用模型及其管理者也属于对应资料的接收方。该边界不承诺抵御已被控制的宿主或消除未知隔离漏洞。

| 使用方式 | 明确的数据边界 |
| --- | --- |
| 本地或老板自有内网 | 选定资料进入老板控制的执行环境与本地或内网模型；员工无直接外联权限 |
| 本地配指定云模型 | 老板明确授权云模型接收指定范围的资料；不适用数据不离开老板环境的承诺 |
| 平台远程中继 | 平台参与处理工作台请求与响应；当前 Gateway 不是端到端加密中继，不能承诺平台技术上不可见 |
| 平台托管容器 | 还须信任宿主平台及运维；普通容器和磁盘加密不能保证宿主管理员无法接触运行中的明文 |

云模型的接收方由老板在包外配置。允许某模型端点，意味着该接收方可能获得员工已被授权读取的资料，不能依靠域名白名单或自动脱敏保证秘密不会进入提示词。要求资料不出老板环境时，仅启用已验证的本地或内网模型与相应网络策略。

普通平台订阅控制面与业务远程中继分别启用。仅订阅不等于打开远程项目、任务分享或运维访问；启用这些通道时重新显示接收方和资料范围。老板不信任平台接触业务数据时使用自己的运行环境与直连入口。

### 6.2 受信控制程序与员工执行环境

受信控制程序负责安装、租约、授权、项目取数、模型与外部动作代理、交付物回写及本地记录。员工执行环境只获得当前项目获准的资料副本、临时工作空间和限定能力，不拥有宿主桌面令牌、完整 daemon 接口、模型或 Git 原始密钥。

运行环境必须强制执行以下约束，并覆盖引擎及其所有子进程、脚本、测试、MCP 和浏览器：

- 每次项目执行使用独立 Home 与工作空间；不挂载老板 Home、其他项目、生产库、宿主控制套接字或已有登录态。资料按显式选择范围提供；敏感文件扫描辅助检查，不能保证自动发现全部业务秘密。
- 默认拒绝直接公网、局域网、DNS、宿主回环和元数据服务访问；只提供专用的受控能力通道。不得通过兼容模式、工具失败重试或切换引擎临时解除边界。
- 模型调用、Git、消息等动作由环境外代理执行。代理校验具体服务、账号、仓库、操作、资料范围及授权版本，不提供任意 URL 请求或宿主命令执行入口。推送等批准绑定具体内容，不能只绑定一个域名。
- 联网准备工具链与依赖时不携带老板资料、真实凭据和员工运行状态。资料进入执行环境后不能切回无限制联网；动态依赖、子模块与安装脚本也须遵守相同边界。
- 任务结束后只提取声明的改动与交付物，按不可信文件检查。回写不执行生成脚本、Git 钩子或未经批准的额外动作，正式环境修改遵循第 4 节的差异校验。

主员工的模型判断和工具调用也必须经过这些边界，不能让普通聊天的宿主权限成为绕过入口。首批仅开放验证通过的操作系统、引擎与运行配置；不支持时保留草稿并显示具体原因，不自动回退到宿主全权限运行。

租约刷新、版本下载与诊断均由受信控制程序独立办理。授权请求只携带固定的账号、商品、安装及版本等字段，禁止携带任务名、项目正文、摘要或日志；员工不能控制目标、附加字段或错误上报内容。诊断和业务日志默认保留在老板环境，外发须由老板另行选择内容。

### 6.3 老板能检查的证据

上岗页区分发布者声明、老板授权与运行环境实际生效的权限，展示实际提供的资料、可写位置、模型接收方、代理动作、包版本、镜像摘要及边界检测结果。实际范围超出授权或检测失败时不能启用该配置。

提供可重复执行的模拟试工与恶意演示包，使用无真实秘密的测试资料，验证越界读文件、读取凭据、直接外联、调用宿主接口、向错误仓库推送及未经批准回写确实被拒绝。报告绑定运行平台、引擎、配置和版本，允许企业在自己的网络环境中复测。

运行时显示受控动作、拦截事件和模型接收方；企业可结合自己的网络策略核对。记录由员工环境外生成，明确其覆盖范围，不能用没有日志证明没有访问或泄露。安全机制、验证方法与独立审阅结果应可供检查；市场中的审核与来源标识不表示安全认证。

老板在本地撤销资料或行动权限时，立即阻止新取数与代理动作，停止受影响执行环境并关闭其通道，优先于第 5.1 节的普通到期收尾。平台安全撤销在本地收到并验证通知时执行同样停止；离线未送达时存在第 5.2 节所述延迟。已经被进程读取或已送给获准接收方的内容无法远程收回；不能仅停止调度器却继续保留活动进程、令牌或连接。

### 6.4 输出与当前实现边界

员工输出、Markdown、HTML、产物预览和异常信息均按不可信内容处理。默认禁止自动加载远程图片、字体、链接预览和嵌入资源；打开外部地址或发送交付物属于单独授权的动作。查看报告不能替员工绕过出网限制，日志脱敏也不能证明已去掉所有业务机密。

当前桌面沙箱主要隔离整个 WorkStep 的 Home 和挂载项目，尚未实现这里要求的逐员工执行隔离和出站策略；部分引擎的统一权限没有等价实现。现有 Gateway 会处理代理正文，Base64 编码不提供对平台的保密性。因此这些能力属于实施前置项，不能作为现有产品承诺。

设计原则参考 [NIST 零信任架构](https://www.nist.gov/publications/zero-trust-architecture)，不因部署位置自动授予信任。关于宿主和容器的边界，参考 [Docker Engine 安全文档](https://docs.docker.com/engine/security/)对 daemon 权限、挂载与隔离配置的说明；本方案不把普通容器作为对宿主控制者的保密边界。

## 7 现有系统接入与接口边界

| 子系统 | 新增职责与复用边界 |
| --- | --- |
| Gateway | 员工目录、作者版本提交、审核、订单、订阅、安装名额与签名租约；复用身份、审计、签名和已有 Skill 分发校验 |
| 本地 daemon | 员工包校验安装、配置与版本管理、项目绑定、主动工作状态、权限和租约校验；复用统一任务创建、工作流和项目数据库执行器 |
| 岗位与员工装配 | 复用角色中心目录和编辑服务，新增独立员工定义及不可变版本，不改变原角色与专家团数据格式 |
| 受信执行控制 | 在第三方员工环境外持有授权、凭据与宿主能力；代理取数、模型、外部动作、工作副本和结果回写 |
| 员工执行环境 | 仅运行获准版本与资料，实施文件、进程与网络约束；缺少约束能力时拒绝启动对应配置 |
| 主对话 | 显式绑定员工身份，复用普通会话与 AssistantRuntime；保留会话与引擎的现有恢复、停止和事件语义 |
| 主动观察 | 通过 AssistantConfig 注册独立结构化模块和 channel；复用运行基础设施，增加无需行动结果，不强制每次巡检都创建任务 |
| Web | 数字员工中心、共享岗位模板模块、装配与入职模块、我的员工及后续市场；复用聊天、提案卡片、确认与可缩放弹框 |
| 后续远端运行 | 根据安装名额创建运行环境，登记为独立 Gateway 设备，复用远程工作台 |

新增接口按归属分开：Gateway 的 `/api/employee-catalog`、`/api/employee-subscriptions`、`/api/employee-installations` 分别管理目录版本、订阅和安装授权；本地 `/api/employee-definitions` 管理岗位装配草稿、修订与不可变版本，`/api/employees` 管理实例的安装、配置、状态、更新、暂停、卸任和导入导出。原 `/api/role-center` 及普通对话的角色绑定接口保持兼容。浏览器不能传入作者本机路径、任意宿主目录或替代真实订阅身份。

新增 `EmployeeDefinition` 保存岗位来源修订、正文快照、入口、能力和主动职责，`EmployeeInstance` 保存来源版本、真实所有者、设备、项目绑定、模型与权限引用、在职状态。所有者由认证上下文解析，凭据不直接存入这两个公共类型。定义与实例登记位于设备配置目录；项目内的会话、发现、提案与任务关联继续通过项目数据库执行器处理。

项目 `MEMORY.md` 继续作为获准员工可共享的项目背景，沿用现有引擎的项目记忆入口。员工私有经验、主动检查状态和工作笔记在对应项目数据库中按实例隔离，不新增另一份 Harness 记忆路径；读取共享项目背景仍须满足该实例的资料授权。

通过 `POST /api/employees/{employee_id}/sessions` 显式创建员工会话并返回现有会话结构。会话持久化新增可空的员工实例引用，已有记录保持为空；实例引用只在创建时确定，不能通过普通角色绑定接口改写。创建和每轮执行均校验所属实例及目标项目授权，项目范围票据不能借此创建或管理宿主员工。

共享类型至少包含员工包清单、版本依赖、安装状态、项目授权、主动判断和授权租约，以及执行授权快照、实际生效权限与验证报告。本地接口支持读取实际资料范围、接收方、受控动作和验证状态，不能只返回员工包自报权限。安装状态区分待下载、待配置、在岗、已暂停、待联网、已到期与错误；执行中的任务仍使用现有任务与运行状态，避免从员工在线状态推断工作已完成。

新增 API、CLI 和后台路径共享服务校验。所有文件与同步 SDK 工作隔离到线程，Peewee 工作单元走对应项目执行器；事务内物化查询与序列化，返回纯数据后再发布事件和创建后台任务。前端按员工实例、项目、会话和 channel 订阅与分流，不新增一套聊天或引擎循环。

主要现有依据：

- [默认工作区](../docs/customization-workspace.md)：固定普通项目及多会话，员工身份需要另行持久化。
- [项目技能中心](../docs/skill-center.md)：项目 Skill 白名单、镜像与各引擎加载边界。
- [执行语义](../docs/workflow-engine-execution.md)：任务创建、版本读取、审核、重跑与恢复。
- [Gateway 开发](../docs/gateway-development.md)：平台账号、设备、分发与远端入口。
- [容器运行时](../docs/container-runtime.md)：共享镜像、Home 与项目持久化。

这些基础不等同于员工市场、支付系统或远端容器供给已经完成。

## 8 分阶段交付与验收

### 第零阶段 可验证的执行边界

先完成受信控制程序与员工环境的分离、授权资料副本、独立 Home、默认禁外联、受控模型与动作代理、输出预览约束和可检查的实际权限。以本机或老板自有内网及一个明确支持的引擎配置验证，不为尚未验证的平台提供安全承诺。

验收：使用恶意演示包，证明文件越界、符号链接逃逸、跨项目读取、浏览器与子进程外联、DNS 和宿主接口访问、凭据读取、错误仓库推送及未经批准回写被实际阻止；生成含远程资源的报告也不能自动外传测试标记。证明撤权能阻止后续取数与代理动作并停止环境，故障不降级为全权限。报告写明测试版本及覆盖范围，允许老板复测；这些测试不等于证明绝无未知漏洞。

### 第一阶段 本地研发员工

在第零阶段通过的环境中完成员工身份、三种组成方式、包导出与安装、项目绑定、入职授权、版本冻结、主对话入口，以及带无需行动结果的主动检查。先使用本地员工包验证，不依赖在线支付。

本阶段按以下批次推进；定义编辑和待配置页面可先验证，实际执行始终要求第零阶段的对应运行配置通过：

| 批次 | 交付与验收 |
| --- | --- |
| 岗位与员工定义 | 角色中心复用为岗位模板；从现有角色创建员工草稿、装配能力、保存不可变版本；不改动原模板或启动任务 |
| 我的员工与入职 | 创建自建实例、绑定项目和模型、展示实际权限与验证结果；未完成配置或验证时保持不可执行 |
| 专属对话与能力调用 | 新建绑定员工的普通会话，按版本选择真实可用能力并进入现有流程；不复制助手运行时，不影响普通角色对话 |
| 主动职责与包迁移 | 验证无需行动、提案、已授权派发及去重；导出到干净配置后重新入职，保留来源并排除老板数据 |

验收：一个研发员工包可安装到另一份干净配置；完成一个获批需求的编码、测试与审核交付；主动发现不重复派发；会话切换和重启保留岗位与待办；配置不完整、权限不足或无事可做时不会意外启动任务。既有角色、专家团和对话绑定保持原行为，修改或删除来源模板不改变已冻结版本；两个员工实例不串用配置、私有经验、检查状态、授权或事件，共享项目背景按各自授权读取。

### 第二阶段 市场与月订阅

完成作者上传与审核、员工目录、不可变版本下载、管理员确认订单、名额、离线租约、更新和到期处理。使用受邀发布者与雇主走完真实试运营流程。正式线上收款与自动作者结算须单独完成支付渠道的接入与验收，不以订单登记替代支付成功。

验收：非订阅者不能领取授权包；重复订单确认不重复发放；修改其他人的商品、订阅或安装被拒绝；到期、离线宽限和平台故障可区分；升级保留老板定制与数据；分别验证普通到期收尾、本地撤权停止、平台安全撤销送达后的停止及离线通知延迟；未订阅用户仍能正常使用本地普通功能。

### 第三阶段 远端托管员工

使用平台支持的固定摘要镜像安装同一员工包，为每个雇主的一名员工建立独立运行实例、设备身份、Home 与项目卷。新增短期单次无头入网凭证、幂等创建、资源限制、健康检查及暂停、恢复、重建、升级与销毁。远端资源费单列，创建前明确运行位置、计费和停机后的数据保留规则。

远端使用专用运行配置。当前 Compose 的 `SYS_ADMIN` 与 `seccomp:unconfined` 不可直接复制为平台多租户配置；第三方技能和代码执行需要验证对应的运行隔离。无法满足所需引擎与命令边界时不开放该运行档位。托管版明确要求老板信任宿主平台与运维，不能沿用本地或自有内网的数据边界宣传；平台代理也须列明数据可见性。

本地与远端首版不做无缝接力；切换须停止原实例、导出明确数据、激活目标并建立新的检查基线，防止同一职责在两端重复执行。远端撤销访问不等于停止计算，控制面必须实际停止对应运行环境。容器重建复用自己的持久卷，不复用其他老板的 Home 或设备身份。

### 通用验证与交付

- 按 TDD 先覆盖包迁移、依赖映射、幂等安装、版本冻结、订阅与巡检的关键行为，再实现功能。
- 真实 API、WebSocket 与调度测试覆盖跨账号、项目、实例和 channel 隔离；慢盘与慢 SQL 配合健康检查 canary。
- 覆盖恶意路径、符号链接、超大包、摘要不匹配、安装中断、更新回退和权限变化。
- 安全测试覆盖所有受支持引擎的子进程、脚本、测试、MCP、浏览器与输出预览，验证版本更新不扩权、租约与诊断不上传业务内容，不能仅断言接口返回拒绝而忽略底层访问结果。
- 覆盖无事可做、同事件重放、并发巡检、休眠恢复、暂停、运行停止与失败上限。
- 验证岗位模板兼容、角色到员工草稿的显式创建、专属会话与普通角色对话隔离、版本注入检查点、多流程选择、默认工作区员工绑定、配置草稿、错误恢复，以及 320px、390px 和 1023px 下的真实布局。
- 实现时更新 Code Map 与对应技术文档；手册及真实截图在项目规定的合并交付节点集中同步，规划阶段不把草案写成已支持能力。

首个可交付目标是：老板能在自己的环境中复测员工访问边界，确认实际资料范围与接收方后，订阅并启用一个可迁移的研发员工；员工在批准范围内主动跟进一个真实研发事项，交付可核对的代码改动与测试证据，并保留清楚的权限、版本和订阅状态。
