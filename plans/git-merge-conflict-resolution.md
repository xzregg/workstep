# Git 合并预览与三栏冲突解决

## 目标与现状

在现有“合并到当前”和“合并去”入口增加合并预览。若产生文本冲突，打开类似 IDEA 的三栏窗口：左侧为目标分支原文，中间为可编辑的最终结果，右侧为来源分支内容。用户确认前，不修改目标分支或其工作目录。

当前 `GitWrites.merge_commit` 在冲突时执行 `merge --abort`；`merge_into` 在目标分支被检出时直接合并，在未检出时使用临时 Worktree。现有 `GitDiffDialog` 是双栏查看及普通文件编辑器，不能直接承担三方合并状态。保留原有自动中止行为，新增独立的预演与解决流程。

## 交互

1. 用户从顶部合并菜单或分支行选择方向和分支，点击“预览合并”。显示目标、来源、双方提交哈希、目标上游更新情况、自动合并文件、冲突文件。预览阶段只读取仓库并在临时 Worktree 执行 Git 合并。
2. 无冲突时展示文件清单和差异，点击“确认合并”执行现有合并语义；合并完成后沿用目标分支的手动推送入口。
3. 有冲突时打开大窗口：左栏“目标分支”，中栏“合并结果”，右栏“来源分支”。文件列表显示未解决数量。每个冲突块提供“采用左侧”“采用右侧”“采用两侧”，箭头均指向中栏；中栏可直接编辑，支持撤销本文件未保存的选择。非冲突块自动进入中栏，不要求重复处理。
4. 每个文件需要明确标记“已解决”。仅当全部冲突文件已解决，才允许“完成合并”。关闭有未保存编辑的窗口使用现有确认组件。取消时丢弃预览和草稿，目标工作目录保持原状。
5. 行号、语法高亮、同步滚动、冲突块导航和可拖动栏宽复用现有代码编辑器与弹窗样式；三栏的状态、请求和关闭保护放在独立的 `GitMergeResolveDialog`，不继续增加 `GitWorktreePanel` 的业务状态。

## 后端流程与接口

- `POST /api/git/worktrees/{id}/merge/preview`：请求包含方向、来源或目标分支、当前审阅快照。后端验证分支、项目范围、活动任务和未完成的 Git 操作，在同仓库临时 Worktree 中预演。返回目标/来源的固定提交哈希、文件清单、每个冲突文件的共同基准（Git index stage 1）、目标版本（stage 2）、来源版本（stage 3）、冲突类型及结果草稿。预演结束始终删除临时 Worktree，不保留 `MERGE_HEAD`。
- `POST /api/git/worktrees/{id}/merge/resolve`：请求携带预览时的分支提交哈希、审阅快照和所有冲突文件的最终内容。后端重新检查实际分支、工作目录及目标上游；在新的临时 Worktree 重演合并，只接受这次 Git 报出的冲突路径，写入解决内容并暂存，确认 index 无未合并条目后生成合并提交。随后按目标是否被检出，分别使用受保护的快进合并或带旧值校验的引用更新。响应返回目标分支与新提交，供现有推送入口使用。
- 预览和完成各自短暂持有仓库锁；用户编辑期间不持锁，也不保存服务端会话。若来源、目标、上游或审阅快照变化，完成接口返回 409，保留浏览器草稿并提示重新预览，不自动覆盖新状态。
- 对“合并去”沿用先获取目标上游、仅允许快进的规则。预览只计算更新后的目标基准；确认时再核对远程和本地头，避免冲突前就移动目标分支。已检出的目标若有未提交内容，最终快进由 Git 判断是否安全；若会覆盖内容，则拒绝并保留原样。
- 文本文件设单文件与整次请求大小上限，按 UTF-8 可安全解码内容进入编辑器。二进制、子模块、复杂重命名/删除冲突先显示类型和两侧信息；首阶段不提供不可靠的文本合并，需在 Git 客户端处理。路径必须来自 Git 本次未合并的 index，不能由请求指定任意路径。
- 所有文件和 Git 子进程 I/O 继续走异步子进程或执行器；临时 Worktree 在成功、失败、超时和取消时清理。普通合并失败继续自动中止，不留下半完成状态。
- 交互式共享任务接口只放行属于该任务 Worktree 的预览与完成请求；只读分享继续拒绝写入，来源和目标须属于该 Worktree 的同一仓库。

## 实施顺序与验收

1. **后端预演与数据模型**：在临时真实仓库覆盖无冲突、同一行冲突、添加/添加、修改/删除、目标上游快进；证明预览后目标 HEAD、工作目录与 index 不变。慢 Git 命令期间健康检查仍及时响应。
2. **三栏窗口**：复用现有编辑器，完成左/右/两侧选择、手动编辑、未解决计数、关闭保护、窄屏滚动和可拖动布局；组件测试验证所选内容准确进入中栏。
3. **完成合并**：真实仓库验证合并提交的两个父提交、解决内容、未提交文件保留、已检出与未检出目标、过期快照、目标并发变化、Git hook 失败和失败后的清理。
4. **接入两个合并入口及分享模式**：分支行预选方向与分支，成功后刷新状态并显示手动推送；共享任务只允许自己的 Worktree，只读分享返回 403。

## 决策边界

首阶段聚焦文本冲突。复杂重命名、二进制和子模块冲突不进行自动写入；窗口明确指出原因并保留在外部 Git 工具处理的路径。原有“一旦发生冲突自动中止实际合并”的约定保持有效，三栏编辑发生在隔离预演结果上。
