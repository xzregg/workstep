# WorkStep Android

Android 应用通过 HTTP 或 HTTPS 加载现有 WorkStep 移动端网页。第一次打开时输入服务根地址，例如 `http://192.168.1.10:8765` 或 `https://workstep.example.com`。连接成功后地址保存在本机。地址页面可输入地址并点“新增地址”保存，不会立即切换；选择已保存地址后点“切换到所选地址”才连接，也可直接输入地址点“连接”。“删除所选地址”会移除列表项；删除当前地址后应用进入未连接状态。连接或切换前会检查目标服务是否可用。短按悬浮球切换网页的项目、会话和流程导航菜单的开关；长按打开修改地址、重新加载、清除网页缓存、查看日志和发送测试通知。悬浮球可拖动，位置会保存在本机。应用离开至少 5 分钟后返回才自动重新加载当前页面；重新启动时加载上次访问的同一服务页面。文件选择和保存完成后不会重新加载。清除缓存会保留登录 Cookie、本地设置和服务器地址。

屏幕常亮默认开启：应用在前台时保持屏幕点亮，切到其他应用或锁屏后不继续亮屏。长按悬浮球可取消勾选“屏幕常亮（仅应用打开时）”，选择会保存在本机；不需要额外申请系统权限。常亮会增加耗电。

## P2P 设备

连接页顶部切换「网关地址 / P2P 设备」。P2P 页可扫码或在输入框粘贴完整的 `/p2p/<设备>/#pair_key=...` 链接；扫码页固定竖屏，顶部有取消按钮。扫码后保存并连接，手动输入先保存，再从设备列表切换。已保存设备可以再次切换或删除，重新扫描同一设备会更新配对密钥。列表只显示设备入口，不显示密钥；密钥使用 Android Keystore 加密后保存在本机。轮换桌面端配对密钥后需重新扫码或粘贴。P2P 入口不使用网关根地址的 `/api/health` 检查，实际连接错误由网页显示。

使用 P2P 时，从配对面板点「取消」返回连接页。进入工作台后，从侧栏点击直连状态可切换设备。在网页历史的第一页按系统返回键也可进入连接页。
安卓会按 P2P 设备保留上次打开的会话或任务详情，再次进入时自动恢复。没有记录时打开工作台首页。

## 服务要求

- 手机浏览器能访问该地址；同一域名和端口提供网页、`/api` 与 `/ws`。
- 使用 HTTPS 时证书须被 Android 系统信任；应用拒绝证书错误及 HTTPS 页面中的混合内容。HTTP 可用于用户自己配置的服务，但内容和登录 Cookie 不受传输加密保护。
- 语音输入需要 HTTPS（本机回环地址除外）。长按消息输入框开始录音，松手结束采集并恢复键盘输入框。首次录音时，应用申请 Android 麦克风权限，并只向当前配置服务同源页面授予音频采集；外部登录页和其他资源不会获得该授权。拒绝后可在系统「应用 → WorkStep → 权限 → 麦克风」中允许。APK 必须同时声明 `RECORD_AUDIO` 与 `MODIFY_AUDIO_SETTINGS`，后者是 Chromium 选择音频设备所需的普通安装权限，不额外弹窗。1.0.50 补齐后者，修复仅有录音授权却报 `Could not start audio source` 的配置缺失；须安装新 APK，仅更新网页不能修复旧 APK。
- 数字人视觉使用当前设备摄像头，发送消息时截取一帧作为图片附件。需要 HTTPS（本机回环地址除外）和声明 `CAMERA` 权限的新版 APK；首次使用申请系统摄像头权限，仅当前配置服务的同源页面可采集。旧 APK 需更新安装后使用。网页文档还须允许 `Permissions-Policy: camera=(self)`；旧后台返回 `camera=()` 会在 Android 权限弹窗前阻断采集，须更新并重启服务后重新加载网页，经网关或反向代理时也须检查最终文档响应。局域网 HTTP 地址不能通过 APK 授权绕过浏览器安全上下文要求。
- 系统语音输出通过原生 Android TextToSpeech 播放，须安装包含 `WorkStepSpeech` 桥接的新版 APK；仅当前配置服务的同源主页面可调用。手机需已安装中文音色；未就绪会显示具体原因。旧 APK 可使用主机本地模型或云端语音输出。
- 数字中枢的缓存唤醒欢迎语可经 `WorkStepWakeGreeting` 交给安卓系统媒体播放器。桥接只向当前配置服务的同源主页面开放，播放完整一条 PCM 音频并回报完成后才恢复对话收音。旧版 APK 沿用网页播放。原生欢迎语的完成、取消或错误会写入「查看日志」，记录输出设备类型和播放进度。
- 电脑端默认后台只监听 `127.0.0.1`，不能直接作为手机连接地址；需另行部署可从手机访问的 HTTP 或 HTTPS 入口。

## 构建

原生导航悬浮球在网关、P2P、思考记录弹窗和网页错误页保持可见，保留拖动位置和长按菜单。

需要 JDK 17 或更高版本及 Android SDK 35。设置 `ANDROID_HOME` 后，在此目录运行：

```bash
./gradlew testDebugUnitTest assembleDebug
```

生成的调试包在 `app/build/outputs/apk/debug/app-debug.apk`。发布包需要另行配置签名；不要分发调试包作为正式版本。

长按悬浮球打开「运行诊断」，可筛选安卓主进程、WebView、通知进程和崩溃日志。连接失败页也可打开。性能页可录制 15 秒，开始录制后返回原页面复现，随后从同一入口查看或提前停止。点选慢帧、长任务、消息渲染或慢请求，可联查附近的日志。消息阶段数据由新版 WorkStep 网页提供，旧服务仍可记录通用页面性能。可复制或导出完整的脱敏 JSON 报告，报告由用户主动分享。调试 APK 可通过 USB 从 Chrome 的 `chrome://inspect` 检查 WebView，正式 APK 关闭此能力。

### 网关页面加载失败的恢复

网关设备工作台的首页、会话和任务页也会检查页面是否正常渲染。页面加载失败或根节点缺失、为空时，原生错误页提供重试、清除缓存并重新加载、返回设备列表和查看日志。正常页面也可长按悬浮球选择“返回设备列表”；该入口直接打开网关 `/devices`，无需当前设备网页的脚本运行，且不会自动再次进入故障设备。清除缓存保留登录 Cookie 和本地设置。

脚本诊断记录来源路径、行号及可识别的错误类型（例如动态模块加载失败、SyntaxError、TypeError）。来源不包含查询参数和锚点；控制台原始正文可能含聊天或凭据，因此只提取已知错误签名。HTTP 资源加载失败仍记录状态码及资源路径。这些信息用于区分加载故障与运行异常，不能单凭错误类型判定为设备版本冲突。

CSP 诊断从 WebView 控制台消息中提取规则名称（如 `script-src`、`connect-src`）、可识别的操作类型和资源来源。资源来源只保留协议、主机及端口，不记录账号、路径、查询参数、锚点或 `data:` / `blob:` 内容；不记录完整策略、nonce、脚本正文。无法识别规则时显示“规则=未知”，已标记 `[Report Only]` 的消息显示为报告而非强制拦截。控制台中的规则可能是回退规则，不等同于事件的 `effectiveDirective`。这项诊断增强需要重新构建并安装 APK，旧包不会因网页更新而自动获得。

## 应用行为

从本地 WorkStep 的「网关平台设置」连接网关时，应用在当前网页中打开网关登录页、HTTPS 身份源及返回本地服务的回调。完成或取消后回到原应用；从认证页返回本地页面也会结束这次应用内跳转。网关登录链接必须将当前配置服务的 `/api/gateway-platform/callback` 作为回调地址。认证结束后的普通外部链接仍由系统浏览器打开。此行为从 APK 1.0.36 开始。

外网 HTTPS 地址经过 TLS 终结反代时，daemon 现在以网页验证过的公网 HTTPS Origin 生成网关回调，并按本次登录保存的地址处理返回和 Secure Cookie。APK 1.0.39 也兼容旧 daemon 生成的同主机 HTTP 回调登录链接，使钉钉登录过程继续留在应用内；完整认证返回仍需部署新版 daemon。回调地址指向不同域名的链接仍交给系统浏览器。

APK 1.0.40 在上述登录过程中遇到同主机 HTTP 的“返回本地工作台”或认证回调时，改用已配置的 HTTPS WorkStep 地址在当前 WebView 加载。日志只记录改写的路径，不记录回调中的授权参数。

APK 1.0.41 的“查看日志”和“复制排查信息”按手机当前时区显示生成时间、诊断事件和错误详情，并附时区偏移；内部日志仍保存世界标准时间，便于跨进程排序和筛选。
APK 1.0.42 修正网关通知缺少步骤键时显示“步骤 null”的问题；此类回复按回复通知展示，安卓通知桥接和后台监听也会过滤无效步骤键。
APK 1.0.43 保留上次打开的具体会话或任务页面，不让网关首页及认证跳转覆盖记录；网关重新取得设备访问权限后继续打开上次的设备和页面。
APK 1.0.44 点击指向当前已打开会话或任务的通知时复用现有页面，并正确识别网关设备范围的目标地址。
APK 1.0.45 优先在当前网页内跳转到通知对应的会话或任务，处理网关工作区地址；网页加载超时判定延长至 3 分钟。

直接以网关地址连接 APK 时，从网关登录页进入钉钉或企业微信扫码认证，后续 HTTPS 认证页面也留在同一 WebView；返回网关回调后恢复普通外链规则。APK 1.0.38 起支持这条路径。长按悬浮球打开日志，可查看被转交系统浏览器的域名，日志不记录认证地址中的查询参数。

首次填写地址会请求 `/api/health`，确认是 WorkStep 服务后才保存。应用沿用网页的登录、接口和实时连接。有运行中的回复或任务步骤且应用切到后台时，才启动安卓前台服务单独订阅结果事件；完成或失败时显示系统通知，执行结束后停止监听。Android 13 及以上在进入网页时申请通知权限。前台服务在等待期间显示常驻通知，应用被强制停止后不保证即时提醒。返回前台时通知网页恢复 WebSocket，重新订阅并补回当前对话漏掉的消息，后台超过 5 分钟仍按原规则整页刷新。网页也在页面可见、网络恢复或浏览器历史恢复时重新连接，并用心跳识别失效连接。WebView 渲染进程异常退出时会尝试恢复页面；前台服务无法启动时会记录错误，网页继续运行。同一服务的页面留在应用内；钉钉和企业微信的 HTTPS 网页授权地址也在同一 WebView 中打开，回调返回配置的平台地址并沿用其登录 Cookie，不接入原生登录 SDK。普通外部 HTTP 或 HTTPS 链接交给系统浏览器。授权页面不保存为应用启动地址，也无法使用 WorkStep 原生通知桥接。“添加图片”优先使用系统图片选择器，普通附件使用文件选择器；网页下载会打开系统“另存为”界面，可选择位置和文件名。这些操作不需要存储权限。断网时可重试或修改地址。

后台通知服务运行在独立进程，切回应用时停止。WebSocket 首次中断只记录状态并在 5 秒后重连；重连仍失败才记录错误堆栈，同一次中断只记录一次，继续重试直至恢复或服务停止。恢复后记录重连成功。应用前台显示其他会话或任务时，完成事件也会弹系统通知；正在查看对应详情时不重复提醒。发送接口确认后，监听绑定本轮消息 ID；确认前的临时监听补查只接受监听开始后的结果，防止上一轮结果误报当前轮完成。网页与后台进程通过带文件锁的持久化通知记录共同去重（保留最近 1000 条），应用重启后仍生效。点击通知时只加载通知目标，返回前台的自动刷新不会打断正在加载的页面。主文档或脚本加载失败、加载超过 3 分钟、会话/任务页面加载后根节点仍为空时显示重试提示；脚本错误位置和加载错误记入日志。APK 1.0.33 起，配合新版网页，回复通知标题使用“会话名／任务名 · 回复完成（失败）”，正文带对应名称；步骤通知带任务名、步骤标识及通过／失败结果。APK 1.0.34 起，通知中的名称最多 20 个 Unicode 字符，超长显示前 19 个加“…”；标题和正文均截断名称，保留完成／失败状态，原始会话及任务名称不受影响。后台使用网页登记监听时的名称，未取得名称则使用会话／任务编号。完成通知点击后按事件频道打开对应会话或任务，任务地址尽量携带所属流程，任务详情会独立读取目标任务，避免当前流程的列表筛选把它误判为不存在；等待中的常驻通知点击后打开切到后台前的页面。悬浮球长按菜单的“查看日志”可查看精简排查报告，点“复制日志”可选精简排查信息或当前保留的完整日志，也可清除日志。报告包含 APK 与 WebView 版本、设备、通知设置、当前页面及加载状态，自动合并最近 30 分钟的主进程和通知进程记录，只保留最近 30 条诊断事件和 3 条错误详情，精简报告最多 14000 字符；完整日志按当前时区导出已有记录，不做摘要截断；窗口自动定位到底部，无需滚动查找；清除时也会移除上次崩溃记录。“发送测试通知”可单独检查系统通知权限；异常退出后再次打开应用还会显示上次异常。日志记录连接状态、事件类型、通知未显示的具体原因、目标地址和异常堆栈，不记录消息正文。

APK 内预览文件的下载按钮遇到同源 WorkStep APK 时，会下载并校验包名，将文件保存在系统下载目录，然后询问是否进入系统安装流程。首次安装需在系统设置中允许 WorkStep 安装未知应用；安装仍由系统确认。其他文件维持原有“另存为”流程，网页文件预览不作更改。


### 使用网关地址与旧 APK 通知兼容

新版网关和网页可兼容已发布 APK 的通知接口，无须为这一改动重新安装安卓包。地址填写网关根地址，进入设备工作台后，当前工作台的完成事件通过原 `notify` 桥接显示系统通知；已登记的回复/步骤进入后台时，原服务继续连接网关根 `/ws`，并通过 `/api/completion-notifications/recent` 补查完成结果。网页登记设备范围的项目标识，网关只发送当前授权内的原完成事件；点击根任务/会话通知链接会重新核权并进入来源设备。

通知跳转不要求网关已采集到该完成记录：携带设备范围的链接会按当前设备／项目授权签发访问票据，再打开来源任务或会话；设备离线、项目删除或授权撤销仍会拒绝访问。设备工作台的延迟加载资源（例如 Mermaid）按脚本所在地址解析，避免访问网关根 `/assets/` 导致 404 和整页错误。修复需要更新来源设备的 Web 构建与网关后台；旧网页仍被缓存时，可通过悬浮球菜单“清除网页缓存”重新加载，登录 Cookie 保留。

后台仍保持原规则：没有活跃回复/步骤监听时不启动服务，完成后停止；不能保证无任务监听、强制停止或系统限制后台运行时接收所有设备的提醒。该兼容已通过接口与桥接回归，安卓真机前后台弹窗尚待验收。

消息输入框的“增加图片”先选择“本地图片”或“拍照”。本地图片沿用系统相册和多选；拍照只在主动选择时申请相机权限，确认后以原图附件返回输入框，取消不添加附件。此入口需要安装包含该实现的新 APK。

### 系统采集权限

拍照／无声视频采集申请相机权限，录音申请麦克风权限，同时采集画面和声音时按实际缺少的权限申请相机与麦克风；全部允许后才授权网页。拒绝任一权限、取消、切换页面／服务或进入后台不会留下网页授权。系统没有独立的“录像权限”，带声音录像需要相机与麦克风两项。仅配置服务的 HTTPS 或本机回环同源页面可请求；不在启动时预申请。需更新 APK；网页策略提前禁止时，不会触发系统申请，仍须修复对应后台响应头。该授权支持媒体采集请求，不代表新增独立录像界面。

### 系统日历

APK 1.0.62 配合最新网页，在数字中枢设置 → 操作授权系统日历；首次授权默认选择本机可写日历，新增会通过原生 Calendar Provider 写入并回读确认。手机系统原有日程在当前月历范围内只读显示，读取在后台执行、最多 200 项，不上传为 WorkStep 记录。明确选择 WorkStep 时仍只保存在内部日历；已有内部日程不自动迁移。权限弹窗、系统实际写入和通知仍需真机验收。

### 启动器图标

品牌源文件沿用 `apps/web/public/favicon.svg`（与官网 `apps/landing/public/favicon.svg` 相同）。复用桌面端的 Electron/Chromium 渲染方式，保留 SVG 箭头与渐变；安装桌面端开发依赖后，在仓库根目录执行：

```bash
rtk proxy node apps/android/scripts/generate-icons.cjs
rtk proxy node apps/android/scripts/generate-icons.cjs --check
```

生成资源随源码提交，Gradle 直接打包，不在 Android 构建时依赖 Electron。Manifest 的普通及圆形入口共用 `@drawable/app_icon`：`drawable-nodpi/app_icon.png` 是普通回退图标，API 26+ 使用 `drawable-anydpi-v26/app_icon.xml` 的白底自适应图标和 `app_icon_foreground.png`。前景为 108dp 图层（432px），完整 SVG 缩放至中央 60dp，箭头尖端均处于 66dp 安全圆内，避免启动器遮罩裁掉箭头。当前没有额外的产品风味或活动别名图标，也未配置单色主题图标。

回归：`LauncherIconTest` 核对打包入口与自适应层引用；生成器 `--check` 核对已提交 PNG 与网站源图的实际渲染一致。安装后仍须检查设备启动器遮罩与图标显示。

### 通知图标

测试通知、网页与后台服务的回复／步骤完成或失败通知均由 `CompletionNotifications.show` 发送；前台服务先用 `starting`，再用 `ongoing`。三条构建路径共用通知图标设置：`notification_icon` 为从网站 SVG 生成的透明背景白色单色轮廓（24dp，mdpi–xxxhdpi），用于状态栏和通知小图标；彩色大图显式引用现有 `app_icon` 自适应资源。厂商通知卡片也可能读取 Manifest 的应用／圆形图标，这两个入口仍指向同一新版 `app_icon`，没有另外保留旧蓝底通知图。

单色资源与启动器资源由同一 `scripts/generate-icons.cjs` 生成，`--check` 一并验证。修改后须重新安装 APK；网页更新不会替换已安装应用的资源。厂商界面可自行决定大小图标的显示位置与缓存，不能用 AOSP 模拟器验证代替对应手机验收。

设备回归位于 `app/src/androidTest/java/com/workstep/android/NotificationIconsTest.java`，运行器由 `app/src/androidTest/AndroidManifest.xml` 注册，只进入测试 APK，不增加生产调试入口或导出组件，也不修改应用版本配置。构建 `assembleDebug assembleDebugAndroidTest` 并安装两个 APK，授予应用通知权限后运行：

```bash
adb shell am instrument -w -e phase test com.workstep.android.test/com.workstep.android.NotificationIconsTest
```

`phase` 支持 `test`、`success`、`failure`、`starting`、`waiting`。截图时可加 `-e holdSeconds 20`，在测试结束清理服务前保留通知。每轮检查生产构建器、实际发布通知的大小图标、Manifest 应用图标，以及单色轮廓的透明度和颜色；`waiting` 实际启动既有前台服务，测试数据只连接设备本机丢弃端口，不接触用户服务；`starting` 单独发布通常瞬时被替换的启动通知以便截图。测试／消息阶段直接调用生产发送方法，保留原有权限、去重和点击行为，不代表真实后台业务或网络结果链路已验收。
