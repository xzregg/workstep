# WorkStep Android

Android 应用通过 HTTP 或 HTTPS 加载现有 WorkStep 移动端网页。第一次打开时输入服务根地址，例如 `http://192.168.1.10:8765` 或 `https://workstep.example.com`。连接成功后地址保存在本机。短按悬浮球切换网页的项目、会话和流程导航菜单的开关；长按打开修改地址、重新加载、清除网页缓存、查看日志和发送测试通知。悬浮球可拖动，位置会保存在本机。应用离开至少 5 分钟后返回才自动重新加载当前页面；重新启动时加载上次访问的同一服务页面。文件选择和保存完成后不会重新加载。清除缓存会保留登录 Cookie、本地设置和服务器地址。

## 服务要求

- 手机浏览器能访问该地址；同一域名和端口提供网页、`/api` 与 `/ws`。
- 使用 HTTPS 时证书须被 Android 系统信任；应用拒绝证书错误及 HTTPS 页面中的混合内容。HTTP 可用于用户自己配置的服务，但内容和登录 Cookie 不受传输加密保护。
- 电脑端默认后台只监听 `127.0.0.1`，不能直接作为手机连接地址；需另行部署可从手机访问的 HTTP 或 HTTPS 入口。

## 构建

需要 JDK 17 或更高版本及 Android SDK 35。设置 `ANDROID_HOME` 后，在此目录运行：

```bash
./gradlew testDebugUnitTest assembleDebug
```

生成的调试包在 `app/build/outputs/apk/debug/app-debug.apk`。发布包需要另行配置签名；不要分发调试包作为正式版本。

## 应用行为

首次填写地址会请求 `/api/health`，确认是 WorkStep 服务后才保存。应用沿用网页的登录、接口和实时连接。有运行中的回复或任务步骤且应用切到后台时，才启动安卓前台服务单独订阅结果事件；完成或失败时显示系统通知，执行结束后停止监听。Android 13 及以上在进入网页时申请通知权限。前台服务在等待期间显示常驻通知，应用被强制停止后不保证即时提醒。返回前台时通知网页恢复 WebSocket，重新订阅并补回当前对话漏掉的消息，后台超过 5 分钟仍按原规则整页刷新。网页也在页面可见、网络恢复或浏览器历史恢复时重新连接，并用心跳识别失效连接。WebView 渲染进程异常退出时会尝试恢复页面；前台服务无法启动时会记录错误，网页继续运行。同一服务的页面留在应用内；钉钉和企业微信的 HTTPS 网页授权地址也在同一 WebView 中打开，回调返回配置的平台地址并沿用其登录 Cookie，不接入原生登录 SDK。普通外部 HTTP 或 HTTPS 链接交给系统浏览器。授权页面不保存为应用启动地址，也无法使用 WorkStep 原生通知桥接。“添加图片”优先使用系统图片选择器，普通附件使用文件选择器；网页下载会打开系统“另存为”界面，可选择位置和文件名。这些操作不需要存储权限。断网时可重试或修改地址。

后台通知服务运行在独立进程，切回应用时停止。WebSocket 首次中断只记录状态并在 5 秒后重连；重连仍失败才记录错误堆栈，同一次中断只记录一次，继续重试直至恢复或服务停止。恢复后记录重连成功。应用前台显示其他会话或任务时，完成事件也会弹系统通知；正在查看对应详情时不重复提醒。发送接口确认后，监听绑定本轮消息 ID；确认前的临时监听补查只接受监听开始后的结果，防止上一轮结果误报当前轮完成。网页与后台进程通过带文件锁的持久化通知记录共同去重（保留最近 1000 条），应用重启后仍生效。点击通知时只加载通知目标，返回前台的自动刷新不会打断正在加载的页面。主文档或脚本加载失败、加载超过 20 秒、会话/任务页面加载后根节点仍为空时显示重试提示；脚本错误位置和加载错误记入日志。APK 1.0.33 起，配合新版网页，回复通知标题使用“会话名／任务名 · 回复完成（失败）”，正文带对应名称；步骤通知带任务名、步骤标识及通过／失败结果。APK 1.0.34 起，通知中的名称最多 20 个 Unicode 字符，超长显示前 19 个加“…”；标题和正文均截断名称，保留完成／失败状态，原始会话及任务名称不受影响。后台使用网页登记监听时的名称，未取得名称则使用会话／任务编号。完成通知点击后按事件频道打开对应会话或任务，任务地址尽量携带所属流程，任务详情会独立读取目标任务，避免当前流程的列表筛选把它误判为不存在；等待中的常驻通知点击后打开切到后台前的页面。悬浮球长按菜单的“查看日志”可查看精简排查报告，一键“复制排查信息”或清除日志。报告包含 APK 与 WebView 版本、设备、通知设置、当前页面及加载状态，自动合并最近 30 分钟的主进程和通知进程记录，只保留最近 30 条诊断事件和 3 条错误详情，日志正文最多 14000 字符；窗口自动定位到底部，无需滚动查找；清除时也会移除上次崩溃记录。“发送测试通知”可单独检查系统通知权限；异常退出后再次打开应用还会显示上次异常。日志记录连接状态、事件类型、通知未显示的具体原因、目标地址和异常堆栈，不记录消息正文。

APK 内预览文件的下载按钮遇到同源 WorkStep APK 时，会下载并校验包名，将文件保存在系统下载目录，然后询问是否进入系统安装流程。首次安装需在系统设置中允许 WorkStep 安装未知应用；安装仍由系统确认。其他文件维持原有“另存为”流程，网页文件预览不作更改。


### 使用网关地址与旧 APK 通知兼容

新版网关和网页可兼容已发布 APK 的通知接口，无须为这一改动重新安装安卓包。地址填写网关根地址，登录后前台跨设备通知通过原 `notify` 桥接显示系统通知；已登记的回复/步骤进入后台时，原服务继续连接网关根 `/ws`，并通过 `/api/completion-notifications/recent` 补查完成结果。网页登记设备范围的项目标识，网关只发送当前授权内的原完成事件；点击根任务/会话通知链接会重新核权并进入来源设备。

后台仍保持原规则：没有活跃回复/步骤监听时不启动服务，完成后停止；不能保证无任务监听、强制停止或系统限制后台运行时接收所有设备的提醒。该兼容已通过接口与桥接回归，安卓真机前后台弹窗尚待验收。
