# 渠道机器人

WorkStep 通过官方长连接或长轮询接收机器人消息。daemon 主动连出，不需要给本机开放公网回调地址。企业微信、钉钉、飞书与 Lark 支持文本、图片与文件；Telegram、Discord、Slack 与 QQ 当前支持文字收发。任务群消息进入对应任务的协调助手，未绑定群和单聊使用机器人的默认项目。添加机器人必须选择默认本地项目，未选择时保存按钮禁用；没有本地项目时，先创建或打开项目。创建 API 同步要求非空默认项目，更新 API 不允许显式清空默认项目；历史无默认项目配置不自动选择项目，在界面编辑保存时需补选。任务绑定可在任务详情「绑定 BOT」设置，也可在未绑定群中 @机器人要求绑定已有任务。

设置页左侧选择渠道，右侧显示该渠道已配置的机器人和配置表单；窄屏渠道列表横向滚动。同平台可添加不同应用标识的多个机器人。编辑现有机器人时，Token／Secret 留空保留原值；切换渠道或编辑其他机器人前，对未保存修改进行确认。

## Telegram

1. 通过 [@BotFather](https://t.me/BotFather) 创建机器人，在 WorkStep 选择 Telegram，填写名称、Bot Token 和默认项目。Bot ID 从 Token 自动读取，无需另填。
2. 勾选「启用机器人」并保存。接入采用 [Bot API 的 getUpdates 长轮询](https://core.telegram.org/bots/api#getupdates)；同一机器人不能同时被其他程序轮询，已配置 Webhook 时需先由管理员移除，WorkStep 不自动删除。
3. 私聊直接发送文字；群内 @机器人或回复机器人消息。群标识采用 `chat.id`，论坛主题中的即时回复保留 `message_thread_id`；同群不同主题仍共享群绑定和会话。

## Discord

1. 在 [Developer Portal](https://discord.com/developers/applications) 创建应用和 Bot，复制 Application ID、Bot Token。
2. 开启 **Message Content Intent**，用 `bot` 权限将机器人邀请到服务器，授予 `View Channels`、`Send Messages`；线程还需 `Send Messages in Threads`。在 WorkStep 选择 Discord，填入凭据、默认项目，启用并保存。
3. 私聊直接发送文字；服务器频道必须 @机器人。通过 [Gateway](https://docs.discord.com/developers/events/gateway) 接收消息，保留序列号及会话恢复信息，并处理心跳和重连。任务绑定使用频道／线程的 `channel_id`，不使用服务器 ID。自动发送的正文禁用批量提及，避免助手正文意外触发通知。

## Slack

1. 在 [Slack 应用后台](https://api.slack.com/apps) 创建应用，开启 [Socket Mode](https://docs.slack.dev/apis/events-api/using-socket-mode/)，创建具有 `connections:write` 的 App-Level Token（`xapp-`）。
2. Bot OAuth 权限配置 `chat:write`、`app_mentions:read`、`im:history`，订阅 `app_mention` 和 `message.im`，安装／重新安装应用到工作区，复制 App ID 和 Bot Token（`xoxb-`）。
3. WorkStep 选择 Slack，填写 App ID、两份 Token 和默认项目，启用保存。私聊直接发送文字；频道需要先邀请机器人，再 @它。即时回复使用原消息的 `thread_ts`，群绑定采用频道 ID；同频道的多个线程共享会话。平台回执先确认，助手执行独立运行，不阻塞 Socket Mode 消息回执。

Telegram、Discord、Slack 与 QQ 均复用既有私聊／群聊白名单、会话、去重和任务绑定，最终正文按平台容量分段发送。目前不声明图片、文件、流式正文、等待气泡或交互卡片能力；停止、权限回答、提案确认和审核操作需回 WorkStep 完成。自动化通过模拟官方帧与异步网络覆盖，尚未使用真实凭证完成这四个平台的联调，连接权限、安装和实际客户端收发仍需验收。

## QQ 官方机器人

1. 在 [QQ 开放平台](https://q.qq.com/)创建机器人，取得 App ID 和 App Secret。在「事件与回调」中选择 **WebSocket**，按平台要求开通 QQ 单聊及群聊事件权限、发布／测试范围和网络访问配置。
2. WorkStep「设置 → 渠道机器人」选择 QQ，填写名称、App ID、App Secret 和默认本地项目，勾选「启用机器人」并保存。无需填写已弃用的机器人 Token；后台按[官方凭证接口](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/access-token.html)取得并缓存 access_token，临近过期刷新，HTTP 401 时仅刷新重试一次。凭据不通过机器人列表返回前端。
3. 私聊直接发送文字；群内必须 @机器人。通过[官方 Gateway](https://bot.q.qq.com/wiki/develop/api-v2/dev-prepare/interface-framework/event-emit.html)接收 `C2C_MESSAGE_CREATE` 和 `GROUP_AT_MESSAGE_CREATE`，仅订阅 `GROUP_AND_C2C_EVENT`。机器人自己的消息、群内非 @事件和纯附件不会触发助手。
4. 群内发送一条 @消息后，在任务详情「绑定 BOT」的最近群中选择并绑定。群标识为 `group_openid`，私聊与群成员白名单使用平台返回的 OpenID，不能用 QQ 号码、群号或昵称替代。平台未返回昵称／群名时沿用标识显示。

即时回复使用入站消息的原始 `msg_id`，分段递增 `msg_seq`；同一消息多次发送不会重用序号。QQ 当前限制单聊被动回复最多 4 条、群聊最多 5 条，超出可用次数的长结果会在末条明确提示「完整结果请在 WorkStep 查看」，完整正文仍保留在 WorkStep。被动回复的时间窗口和权限由 QQ 平台校验，超时会报告发送失败，不自动改成主动消息。依据：[单聊发送](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_users_user_openid_messages.post.html)、[群聊发送](https://bot.q.qq.com/wiki/develop/api-v2/autogen/api/v2_groups_group_openid_messages.post.html)。

WorkStep 内续聊、自动任务阶段推送与 CLI 通知没有入站回复上下文时使用主动发送，受[平台主动消息权限、拒收及频控](https://bot.q.qq.com/wiki/develop/api-v2/server-inter/message/overview.html)约束，不伪造或缓存过期 `msg_id`。当前不接入 QQ 频道、频道私信、Webhook、NapCat／个人 QQ 登录，也不支持图片、文件或交互卡片。`tests/test_qq_channel.py` 覆盖鉴权缓存、刷新、Gateway 登录／恢复／心跳、消息归一化、序号与配额、真实管理 API、共享业务路由和慢网络健康检查；真实机器人收发仍需联调。

## 飞书与国际版 Lark

1. 在[飞书开发者后台](https://open.feishu.cn/app)或 [Lark 开发者后台](https://open.larksuite.com/app)创建**企业自建应用**，启用机器人能力，获取 `App ID` 和 `App Secret`。这是应用机器人，不是仅用于通知的群 Webhook；当前不接入商店应用。
2. 打开 WorkStep「设置 → 渠道机器人」，选择「飞书」或「Lark」，填写对应平台凭证，选择默认本地项目，勾选启用并保存。平台标识分别为 `feishu`、`lark`，不能混用凭证。
3. WorkStep 建立连接后，在应用「事件与回调」中选择**使用长连接接收事件／回调**，订阅消息事件 `im.message.receive_v1` 和新版卡片回调 `card.action.trigger`。无需填写本机公网地址、Verification Token 或 Encrypt Key。
4. 按开放平台当前的权限名称开通接收机器人私聊、接收群内 @机器人、以机器人身份发送消息、更新卡片和获取／上传图片文件资源的权限，并发布应用。读取用户基础信息和群信息用于显示昵称与群名，未授权时回退显示标识。应用可用范围和通讯录数据范围由企业管理员授权。
5. 私聊可直接发消息；群聊必须在消息中 **@机器人**。其他群消息及机器人自己的消息不会触发助手。将机器人加入群后发一条 @消息，即可在任务详情「绑定 BOT」中从最近群选择并绑定。

接收文本、图片、文件及富文本中的文字／图片，发送文本和原生图片／文件。群内纯附件消息若没有 @信息不会触发：可在带 @的富文本中放图片，或回复原附件并 @机器人；引用读取仍受平台权限限制，权限不足时可改用私聊发送附件。引用仅读取同一会话的原消息。沿用 WorkStep 图片 2 MiB、文件 20 MiB、每次最多 10 个附件的限制，临时下载地址和资源密钥不写入可见正文。

处理时创建一张卡片，正文以累计快照更新；停止按钮并入这张卡片，完成后移除按钮并固定状态。长结果保留首段卡片并分段发送剩余正文，卡片发送或更新失败时回退完整文本。主动通知、WorkStep 内续聊回复和绑定群的任务阶段推送复用既有发送入口；私聊用户标识使用当前应用的 `open_id`，群使用 `chat_id`。模板直接生成，无需填写钉钉模板 ID。

支持中止、提案确认／取消、权限选择和任务审核，操作权限、重复点击、旧轮次及跨群校验沿用统一渠道控制层。审核意见使用「填写意见 → 同一会话发送下一条文字」，群内填写意见须再次 @机器人；保存后再点击审核按钮。未接入卡片内的自由文本输入框。卡片回调先回执，助手处理和数据库操作不阻塞长连接。

技术依据：[官方长连接说明](https://open.feishu.cn/document/ukTMukTMukTM/uYDNxYjL2QTM24iN0EjN/event-subscription-configure-)与[消息 API](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1)。网络使用异步 HTTP／WebSocket，官方 `lark-oapi` 负责帧协议、分片、心跳格式及回执；不在 daemon 事件循环中调用 SDK 的同步启动入口。国内和国际域名分别固定为 `open.feishu.cn`、`open.larksuite.com`。网关登录／组织同步须在网关独立配置，机器人凭据不自动传给网关。

自动化覆盖见 `test_feishu_channel.py`；真实企业租户的应用发布、权限审批、入群、双平台收发、断线重连及客户端卡片渲染仍需联调，模拟帧通过不等同于真实平台验收。

## 企业微信智能机器人

1. 在企业微信管理端创建**智能机器人**，选择长连接方式，并取得 `Bot ID` 和 `Secret`。这里不是仅用于通知的群 Webhook 机器人。
2. 打开 WorkStep「设置 → 渠道机器人」，选择「企业微信」，填写 Bot ID、Secret，选择默认项目，启用连接并保存。
3. 将机器人加入企业微信群。群里发送一条文本消息后，在任务详情的「绑定BOT」里选机器人，并从「最近收到的群」中选择该群，保存绑定。

接入使用[企业微信官方 Python SDK](https://github.com/WecomTeam/wecom-aibot-python-sdk)。群标识采用平台消息中的 `chatid`，不能用群名称代替。

企业微信收到有效消息后使用官方 `reply_stream` 创建未完成的回复气泡（空内容、`finish=false`），排队期间也先回执；回答、空结果或失败时使用同一 `stream.id` 结束并替换气泡。三点等待动画由企业微信客户端呈现，需实际租户验证。若最终流式回复失效，回退为主动发送最终回答。

## 钉钉 Stream 机器人

1. 在钉钉开发者后台创建应用，启用机器人能力并选择 **Stream 模式**，取得应用的 `Client ID` 和 `Client Secret`。发布和安装应用所需的组织配置按钉钉后台提示完成。
2. 在 WorkStep「设置 → 渠道机器人」选择「钉钉」，填写 Client ID、Client Secret，选择默认项目，启用连接并保存。
3. 将应用机器人加入群并发送一条文本消息，然后在任务详情的「绑定BOT」中从「最近收到的群」选择群标识，再点击「绑定群」保存。

接入使用[钉钉官方 Stream SDK](https://github.com/open-dingtalk/dingtalk-stream-sdk-python) 的消息解析和回执协议；建连 HTTP 请求和 WebSocket 循环采用异步网络客户端，避免阻塞 daemon 事件循环。群标识采用 `conversationId`。

## 在群里绑定任务

机器人先设置默认项目。将它加入群后，在群里 @机器人说“把当前群绑定到任务 <任务 ID>”。渠道助手核对默认项目内的任务，再调用 `workstep channel bind --session <当前渠道会话 ID> --project <项目 ID> --task <任务 ID> --json`（支持引擎也可调用同名 WorkStep 工具）。命令根据当前项目渠道会话解析机器人和群 ID，不接受消息文本里冒充的群 ID。绑定成功后，该群下一条消息开始进入目标任务的协调助手；当前这条绑定指令仍由项目渠道助手回复。

仅有效群聊会话可绑定，私聊、已重置会话、其他项目任务及已绑别的任务的群会被拒绝。查看会话、项目和任务 ID 可用 `channel sessions`、`project list` 和 `task list`；助手有结构化工具时直接调用相应工具。

## 路由与限制

- 一个机器人可以绑定多个讨论群，每个群可以对应不同项目的任务；同一机器人下的同一个群最多绑定一个任务。群绑定优先于机器人的默认目标。
- 设置页只配置默认项目，不提供默认任务选项。每个平台会话使用独立的项目渠道聊天会话；已绑定任务的群进入该任务的协调助手。旧版默认任务配置仍兼容，编辑并保存后改为该任务所在的默认项目，已有群绑定保留。无默认目标且群未绑定时，消息不会提交给助手。
- 项目渠道会话标题为「渠道对话」，按机器人、单聊/群聊和平台会话标识复用；它与当前打开的 WorkStep 对话独立。引擎和模型读取渠道助手的默认配置。任务目标使用该任务协调助手的会话和配置。项目渠道回答以共享助手的消息完成事件为准，完成后回发平台。
- 渠道助手与任务协调助手均使用项目所在设备的供应商和模型目录，消息仍记录真实渠道发送者。连接网关不会隐藏设备自行配置的本地供应商；网关已下发供应商仍须满足该设备的有效授权，未下发到该设备的供应商不可选择。
- 对话列表根据消息中保存的渠道操作者标识显示机器人名称；机器人已移除或没有名称时显示企业微信/钉钉来源，不依赖标题，改名和归档后仍可区分。左侧每个项目的「对话」标题右侧同一行提供「普通」和「渠道」两个 Tab，渠道 Tab 隐藏新建加号，显示各自数量，打开会话时自动切换到对应分类；各组内部保留原有排序。
- 重置项目渠道对话：在 WorkStep 中归档或删除对应的「渠道对话」，下一条平台消息会创建新会话并更新对应关系，不继承旧上下文；之后继续复用新会话。归档保留历史，删除按普通会话删除规则清理。当前未提供平台聊天中的重置命令；此规则不适用于任务协调助手。
- 删除机器人会移除它的群绑定。删除任务会清除相应群绑定和机器人默认任务目标。密钥保存在本机全局配置文件，机器人列表 API 不返回密钥。
- 当前自动化测试使用模拟平台帧；实际租户仍需验证组织权限、机器人入群、单聊和群聊的收发。长时间任务可能超过钉钉 `sessionWebhook` 的有效期，此时任务消息会留在 WorkStep 历史中，但平台回复可能失败。
- 企业微信使用系统代理连接时，若状态持续为「重连中」，设置页会显示最近一次连接错误。使用 SOCKS 代理需要安装项目依赖中的 `python-socks`；更新依赖后须重启 daemon，连接库才能重新加载代理支持。

渠道会话列表标签显示平台及私聊对象（例如「钉钉 · 私聊 小王」），群聊显示群标识；平台未提供姓名时显示用户 ID。完整标签包含机器人名称，长标签截断显示。会话来源独立保存，归档或重置后仍保留原会话的来源。既有会话从当前渠道映射补全；无法确定私聊或群聊的历史记录只显示平台与机器人。

### 在 WorkStep 内续聊并推送回复

绑定任务的群会收到步骤结束消息。供应商连接超时、引擎报错或引擎不可用时，消息以「@阶段名」开头，保留已生成的正文，并附上「执行失败：具体原因」；尚未生成正文也会发送失败提醒。手动停止不追加失败提示。机器人须保持启用、连接正常且拥有发送权限。

在左侧「渠道」Tab 打开会话并发送消息后，LLM 已完成的正文回复会主动推送到该会话当前映射的机器人私聊或群聊。普通会话、已归档或已被重置替换的会话不推送；渠道入站消息已有回复回调，不会重复发送。思考、工具调用与流式碎片不逐条推送。失败会记录日志并发布 `channel_bots.reply_error` 事件。

企业微信使用长连接 SDK 的主动发送接口；钉钉使用 [机器人群聊发送](https://open.dingtalk.com/document/orgapp/the-robot-sends-a-group-message) 或 [机器人单聊发送](https://open.dingtalk.com/document/orgapp/chatbots-send-one-on-one-chat-messages-in-batches)，通过应用凭证获取并缓存 accessToken。钉钉应用需要具备相应主动发送权限。


### CLI 主动通知

使用 `workstep channel list --json` 查看机器人，用 `workstep channel sessions --project <项目ID> --json` 查看当前项目的渠道会话及收件人。

```bash
workstep channel send --project <项目ID> --session <渠道会话ID> --text "任务已完成" --json
workstep channel send --project <项目ID> --bot <机器人ID> --user <平台用户ID> --text "任务已完成" --json
workstep channel send --project <项目ID> --bot <机器人ID> --group <平台群ID> --text "任务已完成" --json
```

源码环境将 `workstep` 替换为 `uv run --no-sync --directory apps/daemon python -m cli`。按会话发送会自动识别机器人、私聊用户或群；直接指定目标时，机器人默认项目或群绑定的项目必须匹配。归档、重置后的旧会话和未启用机器人拒绝发送，项目范围凭据不能跨项目发送。消息直接发给渠道，不启动 LLM，也不写入聊天历史；返回 `sent: true` 表示平台发送接口成功，失败返回非零退出码，不能等同于用户已读。助手和定时任务须有明确的发送授权。


### 图片和文件

企业微信、钉钉适配器使用统一渠道消息协议接收和发送图片、文件。收到的附件保存到绑定项目 `.workstep/uploads/`，继续复用现有项目会话或任务助手；LLM 完成回复中的项目上传/产物附件会原生推送到渠道。

```bash
workstep channel send --project <项目ID> --session <会话ID> --image ./截图.png --json
workstep channel send --project <项目ID> --bot <机器人ID> --user <用户ID> --file ./报告.pdf --text "报告已完成" --json
```

`--image/--file` 可重复，附件消息可省略 `--text`。当前图片限 2 MiB、文件限 20 MiB，单次最多 10 个附件。钉钉原生文件格式限 `xlsx/pdf/zip/rar/doc/docx`。发送仍受平台权限与配额约束；`sent: true` 表示接口成功，不表示用户已读。详见 [渠道消息协议与接入开发](channel-message-protocol.md)。


### 群名称与消息来源

任务「绑定 BOT」按「群名称 · 群 ID」显示最近收到的群。钉钉读取平台 `conversationTitle`；企业微信当前智能机器人消息未提供群名时，使用当前渠道对话名称，可在对话中重命名。群聊的新对话默认以平台群名命名，私聊默认以平台发送者用户名命名，没有昵称时用用户 ID；用户修改后的标题不会被后续消息覆盖。绑定按机器人 ID 与群 ID 定位。旧绑定无需迁移，下一条消息会补充近期来源。

渠道对话顶部可展开查看平台、机器人、群名称、群／会话 ID、对话首次发起者和最近发送者。首次发起者指当前 WorkStep 渠道会话的第一位发送者，不代表群主或创建群的人；归档／删除后新会话重新记录。发送者由平台用户 ID 和平台提供的昵称识别，企业微信未提供姓名时显示用户 ID。

默认项目的渠道助手每轮通过统一引擎入口独立提供角色、项目指令、平台、机器人、群／会话 ID、群名称、首次发起者及本轮发送者。用户聊天气泡及持久化正文只保留入站内容（附件仍按既有机制转换为引用）；本轮来源信息不拼进气泡。支持的引擎使用原生系统指令追加（Codex 使用开发者指令），保留引擎内置指令；其他引擎每轮在模型输入正文中降级附加背景，避免恢复会话遗漏新的发送者。WorkStep 内直接发起消息时使用该消息作者，不沿用上一位渠道发送者。名称仅作为 JSON 来源数据，未知字段留空，机器人凭证不传给模型。

绑定任务的协调助手将固定协调规则与每轮来源背景分开：固定规则使用系统／开发者指令，本轮来源背景放在任务上下文中，用户消息正文仍只保存原文。恢复同一 Codex SDK 会话且原生记录确认规则未变时，不重复注入固定规则；来源、群或发送者变化只更新本轮背景。从渠道切回 WorkStep 时明确使用当前消息作者，避免沿用上个群的发送者。原生规则无法确认、规则更新或新会话时仍重新注入。

「查看提示词」展示本轮调用准备后实际提供的输入：原生独立指令与正文分开，正文降级显示实际拼接正文；本轮没有独立指令或使用空的原生恢复标记时不显示该区块。按最新确认，完整输入复用 `chat_messages.prompt` 保存，用户原文仍在 `chat_messages.content`，不重复写入过程日志。历史查询读取已保存记录，运行时记录只用于及时更新，不根据当前配置重组过去请求。重启后已保存的输入仍可查看；未捕获过的旧消息不补造。协调、流程和经验归档也复用各自原有提示词字段持久化。

设置页每个机器人卡片下显示「已绑定任务」，包含任务名称、所属项目和群名称（缺少群名时显示群 ID）。点击右侧叉号立即解除该群与任务的绑定；失败时保留该项并显示错误，可再次重试。也可在未绑定群中通过渠道助手创建绑定。


## 渠道内停止与选择

普通渠道会话、绑定任务的协调回复和推送到已绑定群的自动阶段消息运行时会附带「终止」按钮卡片，点击复用 WorkStep 的停止逻辑，并按消息 ID 只停止对应的这次回复，不停止后续排队消息。钉钉的按钮和正文共用同一张流式卡片，正文更新时保留按钮，结束后移除按钮并保留完整正文；企业微信使用流式正文与按钮卡片组合回复。协调助手需要确认阶段操作时发送「确认／取消」提案卡片；普通选择题显示对应选项，选择作为用户消息回到原任务的协调助手。引擎权限和布尔／枚举问题则直接继续原等待请求。用户发起的回复和确认选择仅该用户可操作；自动阶段的终止卡片允许同一绑定群的成员点击，停止卡片所关联的当前阶段，完成后旧卡片失效。

企业微信使用现成按钮模板，无额外模板 ID。未点击的旧停止按钮在结束后可能仍显示，但已失效；用户点击后会收到提示。钉钉默认使用官方 SDK 的 Markdown 按钮模板 `1366a1eb-bc54-4859-ac88-517c56a9acb1.schema`；应用须开通互动卡片创建、投放、更新权限。若公共模板不可用，可在「设置 → 渠道助手 → 钉钉」填自己的兼容模板 ID，变量为 `title`、`markdown`、`tips`、`sys_full_json_obj`，后者包含 `msgButtons: [{text,id,request:true,color}]`。卡片或权限发送失败会提示转到 WorkStep 操作，普通回复仍正常运行。

官方协议参考：[企业微信 SDK 卡片与回调](https://github.com/WecomTeam/aibot-node-sdk/blob/main/README.md)、[钉钉官方通用按钮模板](https://github.com/open-dingtalk/dingtalk-stream-sdk-python/blob/main/dingtalk_stream/card_instance.py)、[钉钉卡片创建／投放和更新](https://github.com/open-dingtalk/dingtalk-stream-sdk-python/blob/main/dingtalk_stream/card_replier.py)。


任务归档／删除后的渠道解绑由 `api/task_context.py::_release_task_channel_bindings` 统一调用 `services/channels/bots.py::remove_task_bindings`。`api/task_archive.py` 的直接归档、经验确认归档（有／无经验）及 `api/task.py` 的删除仅在任务操作成功后调用；解除该项目、该任务的全部群绑定，历史默认任务目标回到原默认项目，不删除渠道会话、来源或近期群。恢复归档不会恢复旧绑定。真实 HTTP、跨项目／跨任务隔离、失败保留及慢配置写入健康检查见 `tests/test_task_channel_unbinding.py`。


## 验收边界

企业微信、钉钉适配器及群绑定已有自动化回归；真实平台租户的权限配置、收发、重连与跨群路由仍需联调，模拟客户端不代表真实平台验收通过。机器人默认配置使用项目；已有默认任务配置只作为历史兼容，编辑保存时转换到默认项目。一个机器人可通过不同群绑定服务多个项目及任务，不能根据当前前端所选项目猜测路由。

### 任务审核卡片与意见

等待人工审核的任务卡片提供「通过」「不通过」「终止任务」「完成步骤」「填写意见」。点击「完成步骤」后，由点击者选择「继续下游」或「仅完成步骤」；选择前不会更改任务。按钮复用任务详情的审核服务，记录实际点击者身份。任一群完成审核后，同一审核的其它卡片都失效，旧轮次和已改变绑定的卡片不能继续操作。

企业微信及未配置输入模板的钉钉机器人：点击「填写意见」，在同一会话中发送下一条文字（10 分钟内、不超过 10000 字），收到保存提示后再点击原卡片的审核按钮。意见按点击者隔离，其他成员的聊天仍正常进入助手；发送「取消审核意见」取消本次填写。保存意见不会自动提交审核，可再次点击填写覆盖意见；意见与审核卡片可跨 daemon 重启恢复。

钉钉卡片内输入需配置独立的审核模板：

1. 在钉钉卡片平台新建模板并导入 [WorkStep 审核卡片编辑器配置](assets/dingtalk-review-card.json)。打开编辑器检查预览后保存、发布，让平台生成渲染产物；该文件不包含预编译的 `widgetInfo`。
2. 在 WorkStep「设置 → 渠道助手 → 钉钉」填入「审核卡片模板 ID」。它只用于待审核卡片，不影响原回复卡片。
3. 填写可选审核意见，再点击按钮；模板的文本输入保存到用户本地变量 `comment`，各按钮以 `cardPrivateData.params.comment` 回传意见。按钮 action ID 为 `0`～`5`，由服务器保存的选项决定审核动作，不接受回调自定义决定。

模板参数：`title`、`markdown`、`tips`、`inputPrompt`，以及 `button0Label`～`button5Label`、`button0Visible`～`button5Visible`；可见性为布尔值（API 参数用字符串形式传递）。完成步骤选择使用普通按钮卡片，继承已填写意见。未配置模板时使用现有官方按钮模板及消息填写意见；模板发送失败会提示到 WorkStep 操作。

接入依据：[钉钉官方文本输入及卡片回调示例](https://github.com/open-dingtalk/dingtalk-card-examples/tree/main/examples/helloworld)。当前已验证配置保存、模板选择、输入回调、意见落库及审核状态的自动化行为；模板导入、发布和真实钉钉客户端渲染仍需租户联调，企业微信无法在此按钮模板内嵌自由文本输入框。
