# 本地 MCP 测试服务

`scripts/mcp_demo_server.py` 提供三个可重复调用的工具：`echo(message)` 返回文本，`add(a, b)` 返回和，`get_demo_info()` 返回服务名称、工具数量及专用测试标签。它不读写项目文件、不需要平台账号，也不监听网络端口。

## 在连接器中添加

打开「设置 → 连接器 → 添加连接器」，填写：

| 字段 | 值 |
| --- | --- |
| 名称 | MCP 本地测试 |
| 连接方式 | 本地 MCP |
| 可执行命令 | `<仓库绝对路径>/apps/daemon/.venv/bin/python3`（Windows 使用 `.venv/Scripts/python.exe`） |
| 启动参数 | 添加一项：`<仓库绝对路径>/scripts/mcp_demo_server.py` |
| 高级设置 → 环境变量（可选） | `WORKSTEP_MCP_DEMO_LABEL`，值为自定义测试标签 |
| 可用项目 | 选择用于测试的项目 |

先按 daemon 的开发流程安装依赖；服务复用 daemon 虚拟环境中的 MCP SDK。不要用没有安装该依赖的系统 Python。命令和参数分别填写，路径包含空格时也无需加引号。

填写后切到弹窗「测试」页，点击「检测连接」，应发现三个工具；此时不会保存配置。选择 `add`，参数填写 `{"a": 12, "b": 30}`，点击「执行工具」，在返回结果中核对 `42`。工具调用会真实执行，测试其他服务时须核对所选工具和参数。

保存后卡片上的「检测连接」也会打开测试页。对话中通过「＋ → 连接器」打开该连接，再发一条新消息，例如：

> 使用 MCP 本地测试的 echo 返回“你好，MCP”，再调用 add 计算 12 + 30，最后读取 get_demo_info。请使用连接器工具，不要自行计算或运行 shell。

预期回声为“你好，MCP”，加法结果为 `42`。修改测试标签后，在下一轮执行中读取新标签。是否实际由 LLM 调用，以会话工具记录为准；「检测连接」只验证 MCP 服务，不调用 LLM。

远程服务返回 401 时，测试页显示认证需求并提供「配置认证」入口；填写服务支持的 Bearer Token 或认证请求头后返回测试。403 表示访问被拒绝，还需核对账号权限和服务策略。网页 OAuth 跳转及回调当前尚未接入，不能将任意网页登录页当作已支持的授权入口。CLI 测试只检查可执行文件，登录在宿主终端通过该 CLI 官方登录命令完成。

## 验证

```bash
uv run --no-sync --directory apps/daemon pytest tests/test_mcp_demo_server.py -q
```

测试以真实子进程完成 MCP 初始化、工具发现、三个工具的调用，并验证项目会话桥接链路。stdio 服务由检测或引擎按需启动，连接关闭后退出，无需手动保持后台进程。
