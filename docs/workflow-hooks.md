# 流程钩子

任务列表工具栏（移动端菜单）的“流程钩子”打开当前流程的配置窗口，选择“触发钩子”。一个流程可以保存多个触发钩子；配置与模拟调用分为两个标签页。管理配置需要项目编辑权限。“通知钩子”用于向外部平台发送任务事件，见 [通知钩子技术说明](notification-hooks.md)。

## 调用协议

```text
POST {base_url}/api/hook/{device_id}/{hook_id}?token={token}&step_key={step_key}
```

网关、内网、外网使用相同路径。基础地址从已保存的总配置读取，未填写的不生成地址。`device_id` 是本地安装配置中的稳定标识，`hook_id` 由设备生成；两者都不由调用方配置。

可选参数：`title` 覆盖默认标题；`creator` 覆盖默认创建者（仅显示名称，不赋予账号身份）；`step_key` 指定起始步骤，未传或为空从流程第一步开始。无效步骤拒绝创建。界面所选阶段保存为地址生成配置，生成 URL 时写入 `step_key`。

POST 正文全部作为任务内容，支持 UTF-8 的 JSON、纯文本和 Markdown，最多 1 MiB。JSON 使用代码块展示且保留原文。模拟调用只更新浏览器预览，不发送网络请求。

成功返回 `201 {"task_id": "…", "run_error": null}`。自动运行失败仍返回已创建的任务 ID，并填写 `run_error`，可在任务详情重试。每次有效投递创建一个任务；本版不去重、不解析 GitHub/GitLab 事件、不保存离线队列。

错误包括 Token 无效 401、停用或权限拒绝 403、设备／钩子／流程不存在 404、正文超限 413、媒体类型不支持 415、参数／UTF-8／步骤错误 422、设备离线或服务未就绪 503。GET 不创建任务。

## 存储与转发

钩子完整配置仅存在设备的项目数据库 `workflow_hooks` 表。保存、删除、停用和 Token 重置均由设备处理，不向网关同步钩子副本。服务按项目执行器读取数据库并缓存钩子到项目的索引；配置修改或项目目录变化时重建。

网关已有 `devices` 记录增加唯一 `hook_device_id`，由已认证的控制连接携带安装 ID 与签名登记。它只是设备身份映射，不保存钩子或 Token。登记后不可通过握手改绑；重复标识、无效签名和已停用设备被拒绝。用户切换、改名及重连不改变安装 ID，清除本地安装身份会改变它。

公网调用按安装 ID 查找网关设备连接，经专用 `hook_request` HTTP 帧转发原路径、参数和正文。该帧不携带登录用户身份，只能访问固定 POST 钩子路径。设备校验 Token 并调用共享任务创建服务；普通工作台、分享与项目授权链路保持独立。

受平台管控时，钩子保存时记录配置者的真实账号 ID，触发时仍受该账号的有效任务创建策略限制，URL 的 `creator` 不参与授权。切换到其他平台账号后，如原账号策略不再可用，需要由有权限的新账号重新保存配置。

网关数据库升级为 `0043_hook_device_identity`；设备与网关都需要更新并重连一次以登记路由。只填写网关地址不等于设备已连接，界面分别展示地址和连接状态。访问日志过滤钩子的整个 query，避免输出 Token 和请求来源名称；自建反向代理也应对该入口隐藏 query。

## 行为验证入口

- 设备：`apps/daemon/tests/test_workflow_hooks.py`，覆盖真实任务创建、流式正文、匿名桥接、Token 生命周期、默认值与慢数据库健康检查。
- 网关：`apps/gateway/tests/test_workflow_hooks.py`，覆盖公开 API、数据帧转发、离线、签名登记和身份冲突；迁移一致性由 `test_database.py` 验证。
- 前端：`apps/web/tests/workflowHooks.test.tsx`，覆盖多个钩子、两个标签页、默认值、URL 参数及未保存关闭保护。
- 协议：`packages/gateway-protocol/tests/test_hooks.py`，覆盖项目编辑范围与日志脱敏。
