# 项目数据存储位置

添加项目及“项目配置 → 常规”提供“数据目录跟随项目目录”，默认开启。已有项目重新添加时沿用身份文件中的模式；修改已有项目的选项会先确认，再迁移全部数据。

- 跟随：`<项目目录>/.workstep/`。
- 统一：`~/.workstep/projects/<项目ID>/`；设置了 `WORKSTEP_CONFIG_DIR` 时沿用该配置根目录。
- 两种模式始终在项目代码目录保留 `.workstep/project.json`，保存稳定 ID 和 `follow_project`。旧文件缺少该字段时按跟随模式处理，新项目使用完整 UUID。

数据目录包括数据库、附件、事件日志、产物、记忆、技能和引擎运行数据。代码工作目录仍为项目根目录，文件接口的 `.workstep/...` 是项目内的逻辑引用，不暴露外置 Home 路径。通过项目 ID 授权文件访问，不能读取其他项目的数据。存储管理仅允许本机入口，远程项目不提供此控件。

移动或重命名项目时保留身份文件，重新添加即可关联原数据。复制出的目录保留相同 ID 时不能与原项目同时登记，系统明确报告冲突。删除身份文件会失去自动关联，但不会删除 Home 数据。跨电脑或切换到另一个独立 Home／沙箱环境时，还需迁移对应的数据目录；此功能不自动同步不同 Home 的数据。

迁移先检查运行状态、目标冲突和 Git 工作区，通过专用数据库线程检查点、复制、校验，再原子更新身份文件，最后清理旧数据。运行中的任务、会话和动作阻止切换；已有 Git 工作区需先移除。迁移期间新的项目数据库操作拒绝执行。复制或校验失败保持原项目；提交后的旧目录清理失败明确返回提示。中断后留下 `.migrating` 临时目录时不自动覆盖，应检查并清理临时副本后重试；原身份文件指定的数据目录仍是权威来源。

行为回归见 daemon `tests/test_project_storage.py`、`tests/test_project.py` 及 Web `tests/projectStorage.test.tsx`。慢盘模拟通过健康检查证明事件循环保持响应。
