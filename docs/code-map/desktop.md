本机 CLI 入口为 `apps/daemon/cli.py` 与 `services/tool_registry.py::WorkstepClient`。`main.py::lifespan` 启停 `services/local_cli.py::LocalCliRuntime`，将实例记录放在用户配置目录 `cli-runtime/`（不放进项目）；客户端在线程中按本机 URL 发现，无需平台登录或手动 Token。`api/desktop_security.py` 只承认同用户私有凭据、回环来源且无浏览器／代理标记的 HTTP 请求，不放开网页和远程访问。`api/remote_project_proxy.py` 转发时只保留协议允许的非认证头。行为入口为 `tests/test_local_cli.py`、`test_cli.py`、`test_tool_registry.py`、`test_desktop_security.py` 和 `test_remote_project.py::test_proxy_middleware_forwards_existing_api_when_project_is_remote`；慢凭据读取 canary 验证事件循环不被磁盘 I/O 阻塞。
沙箱磁盘容量与空间错误由 `apps/desktop/src/sandbox-storage.cjs` 持有：新虚拟机使用 64 GiB，`sandbox.cjs::setup` 在启动前无损扩容较小的 macOS 专属虚拟磁盘，启动后通过 `ensureMachineFilesystem` 检查 `/var` 的实际文件系统容量；磁盘文件已变大而根分区/XFS 仍小的机器，使用来宾 `growpart` / `xfs_growfs` 扩容后复查，未达到预期时阻止镜像导入并保留数据，WSL 不走此迁移。Podman 命令的 ENOSPC 被翻译为独立存储空间不足提示。`sandbox-docker.cjs::importDockerImage` 按配置摘要跳过已存在镜像的重复加载，`sandbox.cjs::prepare` 同样复用已存在的缓存镜像。磁盘 64 GiB / 文件系统 20 GiB 回归、无删除扩容、失败保留、无重复导入及缺失缓存恢复测试见 `apps/desktop/tests/sandbox-storage.test.cjs`、`sandbox-docker.test.cjs`、`sandbox-wizard.test.cjs`。
桌面非沙箱安装环境由 `apps/desktop/backend/server.py::prepare_runtime_environment` 持有，在加载 daemon 前将 npm 全局安装、uv 安装及解释器下载统一到配置目录的 `runtime/`，并注入 CLI PATH 和 Python 子进程 PYTHONPATH；Windows npm 命令位于 prefix，macOS/Linux 位于 prefix/bin。Volta 管理的宿主 npm 会先解析实际工具路径，以保证引擎安装仍写入 WorkStep 目录。后台自带 Python 随安装包分发，宿主机原有引擎继续作为回退。测试为 `apps/desktop/tests/test_backend_entry.py`，覆盖配置目录、子进程导入、离线 npm 安装/更新、重复初始化与加载 daemon 前初始化。
桌面启动时的待切换镜像由 `apps/desktop/src/sandbox-startup-window.cjs::applyPendingImageSwitch` 应用：准备前暂时关闭沙箱模式，按已保存标签重新扫描 Docker 的当前镜像 ID，避免旧缓存掩盖 `workstep:latest` 更新；本地镜像直接交给 `SandboxManager.prepare` 单次导入并保持 Podman machine 运行，跳过中间 OCI 缓存的保存、整包哈希与再次加载。`sandbox.cjs::prepare` 对相同 Docker ID 优先 inspect 已导入的 Podman 镜像，缺失或损坏时回退重新导入；失败时停止机器并保留可重试状态。回归入口为 `apps/desktop/tests/sandbox-startup-window.test.cjs`、`sandbox.test.cjs` 与 `sandbox-docker.test.cjs`。
桌面首选端口由 `apps/desktop/src/sidecar.cjs::resolveBackendPort` 解析，沙箱和非沙箱都默认使用宿主机 8766，支持命令行与环境变量覆盖（0 表示随机）。原生后台 `backend/server.py::bind_server_socket` 监听宿主机网络接口，仅遇到 EADDRINUSE 时改绑空闲端口；沙箱 `src/sandbox.cjs::start` 将宿主机端口发布到容器 8765，仅发布端口冲突时清理自己创建的容器并重试随机映射。`src/main.cjs` 使用 `security.cjs::primaryNetworkIPv4` 将宿主机局域网 IP 与实际端口提交给 `api/remote_project.py::set_desktop_runtime`，避免远程访问页显示容器地址；`api/desktop_security.py` 在远程访问关闭时继续要求临时桌面令牌，开启后由 `api/remote_access_guard.py` 执行访问密钥校验。测试：桌面 `tests/sidecar.test.cjs`、`tests/test_backend_entry.py`、`tests/sandbox.test.cjs`，daemon `tests/test_remote_project.py`、`tests/test_desktop_security.py`。
企业 OAuth 的 `_begin` 与回调换码统一通过 `platform_address.request_platform_origin` 选择已配置的当前入口（支持保留 Host 的 TLS 反向代理），否则回退默认平台地址构建回调 URI，网页登录与桌面授权共用同一第三方回调，通过 return_to 区分完成后的页面。保存域名后的实际回调由 `tests/test_external_identity.py::test_oauth_callback_uses_saved_platform_domain_for_web_and_desktop` 覆盖。
本地工作台 `App.tsx` 挂载 `components/DesktopProjectDrop.tsx`，模块在捕获阶段识别系统文件夹拖放，复用 `projectStore.initProject` 与项目路由选择；列表内项目直接切换，未登记的已有项目由 `/api/project/init` 恢复，新目录自动创建空项目。普通文件仍由附件控件处理，侧栏内部排序不受影响；画布未保存时复用 `ConfirmDialog` 提供放弃／取消，处理中显示旋转图标，失败允许重试。Electron `preload.cjs` 用 `webUtils.getPathForFile` 读取真实路径，`sandbox-ipc.cjs` 核验工作台来源后交给 `project-drop.cjs` 异步验证文件夹、规范化别名并映射当前沙箱挂载；未挂载目录提示先配置挂载。行为测试：Web `tests/desktopProjectDrop.test.tsx`、桌面 `tests/project-drop.test.cjs`。
桌面后台启动诊断：`apps/desktop/backend/server.py::startup_stage` 记录运行环境和模块加载；daemon `services/startup_progress.py::startup_stage` 由 `main.py::_application_lifespan` 标记初始化阶段及耗时，写 stderr 时通过线程隔离，也适用于容器日志。`apps/desktop/src/sidecar.cjs` 保存启动阶段 stdout/stderr 的有界脱敏尾部，在超时或提前退出时附带到错误；超时复用 `stopSidecar` 的预期停止和 10 秒强制退出兜底，不改变原有就绪条件、启动顺序或预算。行为测试为 desktop `sidecar.test.cjs`、`test_backend_entry.py`，daemon `test_startup_progress.py`（慢日志与健康检查 canary）、`test_main.py`（实际生命周期阶段覆盖）。
PC 图片放大由 `ImagePreview.tsx` 与 `.desktop-image-preview` 持有，初始按视口适配，双击以鼠标位置放大 200%／恢复，放大后的图片在独立区域原生滚动；工具栏与关闭入口不参与缩放。行为回归：`imagePreviewCopy.test.tsx`。
诊断路由发布回归：`apps/desktop/src/diagnostic-privacy.mjs` 与独立报告运行时 `runtime-diagnostics.js::safeLog` 同步保留日历、委派和声纹 API 的公开固定路径段；动态标识和查询参数仍脱敏。`apps/desktop/tests/diagnostic-privacy.test.cjs` 遍历真实 API 声明并验证报告导出，Web 沿用 `browserDiagnostics.test.ts`／`apiResponse.test.ts`。
桌面品牌图标由 `apps/desktop/scripts/generate-icons.cjs` 从 Web favicon 生成中央 80% 留白的 ICNS、ICO、各尺寸 PNG（32px 同时用于托盘／启动窗口），打包入口在桌面 manifest；`scripts/check-icons.cjs` 持有图标完整性校验，`validate-sandbox-release.cjs::beforePack` 在打包前核对源文件和全部变体哈希，避免沿用旧资源。回归：`tests/icon-resources.test.cjs`。iOS 的 `apps/ios/scripts/prepare-icon.swift` 默认将同一 1024px PNG 铺为不透明白底，归 `Assets.xcassets/AppIcon.appiconset` 持有，Xcode AppIcon 配置直接引用；回归为 iOS `tests/project.test.mjs`。无新增业务 API。
