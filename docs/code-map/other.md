重启日志的创建先在提交进程取得 `restart.lock`，再原子替换 `restart-action.log`；锁句柄通过 `pass_fds` 交给独立执行器持续持有，执行器退出后自动释放。重复点击在创建执行器或清空日志前拒绝；旧启动器持有的文件描述符只能继续写旧 inode，不污染本次日志。测试入口为 `scripts/tests/test_workstep_restart.py`：重复提交保留日志、旧写入者隔离，以及真实子进程持锁／退出释放的交接测试。

后台跨重启的子进程归属与回收由 `apps/daemon/services/process_recovery.py::ProcessOwnership` 持有，`main.py::lifespan` 在启动业务前恢复、在业务关闭及启动失败后兜底清理。每次启动生成独立环境标记；引擎、语音输入／输出、Jev 等后代继承它，按配置目录隔离，定期在线程中写入 PID＋创建时间检查点。只回收已退出后台对应的标记／已登记身份，跳过仍在运行的后台，不按进程名扫描终止。没有本版本归属记录／标记的历史进程不自动认领。 v2记录绑定boot身份与Linux PID/cgroup命名空间及PID 1创建时间，避免共享卷、namespace编号复用或容器重建后误用旧PID；不同环境及v1旧记录不用于回收。Docker隔离实测覆盖共享目录跨namespace、容器重建、同容器遗留回收和`--pid=host`。测试入口：`tests/test_process_recovery.py`（强杀后启动恢复、脱离原进程组、PID复用保护、并行后台、启动失败、慢扫描canary、检查点关闭竞争）。 回收准备／扫描／写盘失败不阻止业务启动，无法落盘时仅禁用本轮归属兜底；退出检查点失败仍尝试按标记回收，失败不覆盖业务原始错误，已有记录保留供下次重试。检查点异常后继续定时重试；`CancelledError` 不吞掉。故障回归包含真实 lifespan 下的健康接口、PermissionError／RuntimeError 注入、失败记录保留、监控恢复及启动取消。

### 人脸识别与人物录入










`runtime.ts` 的 `retryFaceMatch` 仅在预览低光且没有明确匹配时，在推理副本上提亮重试一次；普通漏识帧只推理一次。重试沿用目录阈值（默认 0.65）和候选差值 0.05，已有检测框时须与重试结果重合。录入与发送抽帧沿用单次推理。回归：`tests/faceRecognition.test.ts`。

FaceRes 的常规匹配仍优先使用 Human 距离分数。最佳候选低于设置阈值且距离分至少为 0.50 时，使用同一份特征做余弦相似度复核。最佳候选至少三组录入特征均须达到设置阈值且不低于 0.65，第三高分与其他人物最高分至少相差 0.05。复核共用现有 1024 维特征及模型版本，不增加推理次数。行为回归：`tests/faceRecognition.test.ts`。


采集等待由 `face-recognition/operation.ts` 限时，摄像头关闭、切换或进入后台会取消本次采集等待并恢复操作；运行时不执行 SDK 的额外预热，模型加载与推理超时后提示刷新，未结束的 GPU 工作仍保持串行，迟到结果不能录入样本。
