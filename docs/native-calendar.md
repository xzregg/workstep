# 系统日历

系统接入代码已覆盖安卓 Calendar Provider 和 macOS EventKit；安卓 Java、macOS Swift 编译及模拟设备链路／浏览器检查已通过。真实手机、真实签名／安装包的权限弹窗、系统日历和提醒仍待验收，不能把编译通过视为原生交付验收通过。Windows、iOS 和系统重复系列尚未接入。

## 使用入口

数字中枢设置 → 操作提供“连接系统日历”授权入口，形象页不再展示独立授权入口。移动端形象页点击“日程”，在原生包中仅未授权时显示授权引导；授权完成或从系统设置返回确认权限后，直接展示紧凑月历。普通浏览器可直接使用内部日历。有日程的日期点击打开独立日程弹窗，显示当天全部 Markdown 日程，并通过添加按钮新增（月历下方不再内嵌日程列表）；空日期点击直接新增，已有条目可编辑／删除；与桌面月历共用 DigitalPersonCalendar、编辑器和 API，关闭时不再请求月历数据。前台点击“立即授权”直接请求系统权限，授权后选择可写日历；已拒绝时按钮直接打开系统权限设置，首次请求被拒绝后也自动跳转，无需再次点击。macOS 定位日历隐私设置，安卓定位本应用设置（系统未提供稳定的日历权限子页直达接口）。返回应用会重新检查权限。无可写日历时提示先配置系统日历或账号。普通浏览器可以查看已登记目标、发起操作，但原生执行需目标设备中的 WorkStep 包在线。

数字中枢设置 → 操作提供“同步到系统日历”开关，开启后可选择目标系统日历。新日程默认由该设置决定：开启时通过原生执行并核验，系统记录和 WorkStep 关联记录同时保留；关闭时只创建 WorkStep 日程且不读取系统原有日程。日程编辑器不再提供“保存到”选择。开关和目标按当前工作区与身份保存在本机；已有关联日程仍按原目标修改／删除，关闭开关不批量删除、迁移或解除既有关联。正文为通用 Markdown，无必填名称；系统标题从正文生成。默认系统事件持续 30 分钟，CLI／聊天可指定时长。

安卓 APK 1.0.62 增加受信原生 events 只读入口：仅查询当前月历窗口（最大 62 天），读取系统可见日历的实例，因此重复日程也可展示。每次最多 200 项，每项正文展示前 2000 字，超限明确提示。读取在原生后台队列执行，仅在打开、切月、回前台或变更时触发（短时间合并），30 秒内部日历恢复轮询不重新扫描系统日历。系统原有条目只读展示且不上传 daemon、不注入 LLM、不导入 WorkStep；WorkStep 创建的系统条目继续使用原有核验／增删链路，避免重复展示。

移动端月历收紧标题和月份工具栏，新增日程位于底部整行主按钮，日期点击区及主要提交按钮使用 44px 触控档；今天、翻月和右上关闭采用轻量样式。详情中的编辑保留文字，删除保持次要操作。

界面不弹出正常执行／成功结果窗口；仅授权、选日历、设备待处理或失败／未知时显示必要操作。系统已有日程只显示简短只读标识，不展示功能介绍和实现说明；删除直接执行，不提供撤销入口。

## 调用与存储

CLI → `tool_registry.py` → 宿主 API → `CalendarApplication` 规范化操作。设备通过 `/ws?calendar_device=1` 专用模式接收定向操作标识，前端通过 HTTP 领取操作、调用原生桥接，并通过 HTTP 上报带执行凭据的逐项回执。该模式复用既有 Gateway 的 `/ws` 路由和查询串转发，不订阅全局 EventBus，也不解析聊天正文或回放消息执行操作。

daemon 在实例 `Memory/memory.db` 保存 `calendar_devices`（安装凭据哈希及可写日历）、`calendar_operations`（状态及稳定请求键）、`calendar_operation_items`（逐项执行检查点）和 `calendar_links`（设备／系统日历标识、计划和日期关联）；确认写入的展示镜像仍保存在 `digital_calendar`。设备秘密不出现在目标列表或操作结果。日历专用 I/O 最多两项并发，排队和等待授权不占数据库线程。回执仅返回变化子项的短进度，避免每次传输整个批次；daemon 检查点也只写变化子项，不反复重写全部正文。原生端另行保存安装身份、逐项幂等记录和创建归属：安卓使用应用私有 SQLite，macOS 使用 userData/calendar 下按条目拆分的私有文件，避免每次重写整个历史。

设备凭据由原生包创建，通过已有宿主认证登记，并与调用者绑定。本机 CLI 和未托管的完整宿主入口共用实例归属，浏览器展示身份头不作为账户认证；托管／远程认证用户按账户隔离。它防止其他安装冒充已登记设备，不是硬件远程证明，不能据此声称能够证明任意客户端未被篡改。项目范围／公开分享无权访问宿主日历控制接口。

## 状态与删除一致性

系统日历是原生日程实际状态来源，WorkStep 维护核对镜像和操作日志。新增、修改和删除只有在原生回读验证后才能提交成功；系统日程不能通过内部日历的删除／恢复接口绕过原生执行。

删除中保留条目；失败、权限撤销或未知时保留条目并提示仍可能提醒。只有在权限有效、目标日历可访问、查询正常完成并确认不存在时，才移除镜像。批次逐项提交，成功部分不自动回滚；重试仅补失败项。取消只停止未执行项，不删除已经写入的日程。

系统已创建但回执丢失时，原生记录保留不确定状态。重试先按稳定条目标记核对已有系统事件，确认唯一匹配才恢复成功回执；核对不充分时保持 unknown，不盲目再建。系统侧移动、同步更换标识等可能使核对无法完成，此时需人工查看系统日历。

设备离线时新请求显示 needs_device，恢复前台后要求用户点击继续；不会在任意后续时间突然新增。已领取批次断线后按原生检查点恢复，系统调用结果不明时标记 unknown。目标设备不在线时不能承诺立即停止系统提醒。

原生镜像标记 reminder_owner=system，WorkStep 独立分钟调度排除这些事件。主动思考提前关照需要先通过在线设备查询核对，五分钟内的核对记录及在线状态有效才允许通知。内部日历继续沿用现有分钟调度。

## CLI

完整命令及运行入口见 [Calendar 技能参考](../apps/daemon/data/skills/workstep-cli/references/calendar.md)。单条 create/get/update/delete/list 增加 `--target`；批量使用 create-batch、delete-occurrences，operation get/cancel/resume 查询、停止及继续操作。稳定 request_id 用于重试，不能用新随机请求键重发不确定创建。

指定未来 30 天会生成同一计划下的 30 条独立事件。删除其中几天按 plan_id 和明确日期匹配；不同计划存在歧义时询问用户，不按同名标题猜测。首期不创建无限重复系列。

数字中枢聊天中传入当前 `--project`、`--session`，后端校验来源会话后将最终完成数量以稳定消息标识回写，不为进度再次调用模型。未传来源时通过操作状态和设备弹窗查看结果；排队／待授权不是成功。

## 验证入口与缺口

- daemon：`tests/test_native_calendar.py` 覆盖 30 条批次、按日期部分删除失败、凭据／身份隔离、拒绝无核验回执、CLI/API/定向 WebSocket/真实存储、来源消息和慢 I/O canary。
- 桌面：`tests/calendar-host.test.cjs` 覆盖不确定创建恢复、重复请求不再创建、拒绝不可信前端；`scripts/build-calendar-helper.cjs` 编译 Swift，打包钩子自动构建并纳入 macOS 资源。
- Web：`scripts/check-native-calendar.mjs` 使用真实生产组件和模拟原生／API，检查 320/390/1024/1440px 授权、30 条创建、部分失败和仅重试失败项；产物在 `tmp/native-calendar/`。
- 真机／真包权限、实际系统日历读写及通知、两端真实网关联调仍待验收。原生窗口冻结或应用关闭会中断新的操作分发；已写入事件的提醒由系统负责。
